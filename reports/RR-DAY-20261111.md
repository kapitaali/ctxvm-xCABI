**Cause, reproduced in a clean checkout of the pushed SHA:** two failures, **one file** — the committed
`packages/hermes/test/generate_traces.py` still asserts the pre-0.12.0 behaviour (the live-shape trace
must carry an `identifier_scan` fault), and with the observer aligned that fault is gone, so the

**Why nothing local saw it:** `tools/run-ci.sh` runs the **working tree**, and `tools/ci-rehearsal.py` —
whose docstring says it "clones the committed tree … exactly what actions/checkout gives you" —
actually **overlays the dirty tree** and commits that overlay ("rehearse what would be *pushed*"). The
implementation comment was right; the docstring was wrong. The repo therefore had **no gate that could
see the hosted failure** — the very class the rehearsal exists for.

**Fix in this lane's tooling:** `tools/ci-rehearsal.py --committed` now rehearses the **committed tree
alone** — exactly what `actions/checkout` gives the runner — and reproduces the hosted failure in one
command (`--committed --job ts` → step 15 exit 1 with the same two failures). The same command goes
**green** the moment the missing file is committed.

**The standing rule, now in the tools:** *a green local gate is evidence about the working tree; the gate
that decides the pushed commit is `ci-rehearsal.py --committed`.*
