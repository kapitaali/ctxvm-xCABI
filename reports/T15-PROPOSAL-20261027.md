## 1. Why this is an implementation card, not a design card

T7's `design/adapters.md` already fixes Adapter B end to end: hook points at the
pinned commit (middleware `transformParams` = render anchor, `fullStream` tap =
page/observe/scan), the timing facts (one `transformParams` fire = one xCABI
turn; `tool-call` precedes its `tool-result` in stream order so the T6 recording
matrix applies without buffering), a ~40 LoC glue sketch, the test strategy, and
five pre-registered risks. What is missing is exactly one thing: the code.

Everything below implements that design — it does not re-litigate it.

## 2. Proposed package shape (mirrors T12's opencode package)

`packages/ai-sdk/` — npm `@ctxvm/ai-sdk` (matches the design's agent name
`"ai-sdk"`; the harness story here is a library + app author, not a plugin host):

| File | Purpose |
|------|---------|
| `package.json` | `@ctxvm/ai-sdk@0.0.1`, peer dep on `ai` (version frozen by B0) |
| `src/contract.ts` | typed part→method mapping (`TextStreamPart` → vm calls) + the two-layer count-agreement invariant (types are the fixture schema, T12 pattern) |
| `src/middleware.ts` | `wrapLanguageModel` target: `transformParams` → `vm.render` (params passed through **unchanged**, mirror law) |
| `src/tap.ts` | `ctxvmTap` async generator: `tool-call` → `vm.observe_recall`, `tool-result` → `vm.page_raw`, `text-delta` accumulate → scan at `finish-step`, `tool-error`/`tool-output-denied` → no pages, everything yields untouched |
| `src/flush.ts` | env-gated finish write: `<name>.jsonl` (`@ctxvm/node` `finish()` output) + `<name>.meta.json` (model/provider, hook counts, trace stats) + `hooks-witness.log` appended from day one (T12's TUI-loss erratum carried forward) |
| `test/` | glue units + SDK mock-model fixture streams + schema/replay conformance |
| `fixtures/` | recorded deterministic `fullStream` orderings (mock streams with `tool-call` + result + `finish-step` parts — the SDK's own test pattern) |

Env gating identical to T12: without `CTXVM_TRACE_DIR` the middleware and tap are
pure pass-through no-ops. Flush fires on app finish (`tap` end / `onFinish`);
hard-kill losses stay silent-but-witnessed (same documented posture, hooks-witness
log names the gap next run — the T12 lesson, not a new invention).

Wiring per card convention: run-ci FIXTURES += m8 traces, per-drop checksum

   if the release tag already carries them, pin the tag for supply-chain
   stability.

   separate follow-up cards (recommended — T12's chain executed it that way),
   or ride-along here (grows the card to L).

## 8. Pre-registered risks (carried from design §B, unchanged)

1. Two-layer correlation — asserted per beat B1's witness; warn + skip, never
   mis-score.
2. Stream nesting — matcher keyed per `{ session, step }`.
3. Approval/permission (`tool-output-denied`) turns render associations remain
   approximate in v0 (disclosed in the drop's provenance if hit live).
4. Provider-executed tools — the tap still sees the `tool-result` part;
   verified per-provider at B3, otherwise disclosed.
5. No `params` mutation — mirror contract enforced by the glue test.
