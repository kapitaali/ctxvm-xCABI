## 1. What Gate 2 asks and how it was run

The gate: a 1.5–1.7B model may not reliably emit the 2-hop identifier tokens (`doc<j>_value = V` and
`<topic>-doc-<j>`), producing constant `T(p)` → the bank's own §4 degeneracy guard would make the full run
`INVALID — constant T`. Pilot 3–5 items first; only escalate ($5–10 GPU + 7–8B) if ungradable.

- **Server:** `scripts/start-llama-server.sh` → hashes verified (`0f60e048…` binary, `66a17017…` weights), pid
  60762, `/health` 200.
- **Prompts:** for items `fb01`–`fb05`, τ built by the bank's `buildContext(item)` (`prompt` + `[logicalRef]\n body`
  blocks, all 11 pages).
- **Model call:** `/completion`, `temperature 0`, `seed 7`, `n_predict 160`, `n_probs 0`, `cache_prompt false`,
  `timeout 180`.
- **T(p):** the bank verifier's exact rule — for each of the 10 `file` pages, count occurrences (case-insensitive,
  whole-token) of the page's two identifiers (`doc<j>_value`, `<topic>-doc-<j>`); `Var(T)` = population variance
  across the 10 pages.

## 3. What this establishes and what it does not

- **Establishes:** the pinned CPU model is gradable on the controlled bank; the $0 local route is viable for E0;
  no escalation to the $5–10 GPU route is triggered by the pilot.
- **Does not establish:** that all 20 items will be gradable (only 5 piloted; 15 untested); answer correctness,
  retrieval quality, causal influence, or any cost-saving/model-quality claim. The matched control remains
  degenerate (all file pages same kind/tokens), logged in the parked prereg §1.
- **Timing:** baseline generation is 66–143 s per ~1k-token prompt at `n_predict=160` on this CPU (not the
  ~1.5–1.8 s of Gate 1's `n_predict=1` scoring). A full run's 20 baselines plus ~400 teacher-forced ablation
  scorings is a multi-hour job; "hour-order" from the ruling is optimistic for generation but the design's
  scoring arm is fast. No full run authorized by this card.
