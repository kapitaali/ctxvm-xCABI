# RR-20261031 — R5/R4 card: `page.declare` gains `turn` + `latencyMs`

**Card:** the LAST optional fields on `page.declare` — RFC-0.1 **§R5** (`turn`) and the
emit half of **§R4** (`latencyMs`) — on BOTH emitters (node tracer, which opencode and
ai-sdk inherit; the hermes python port), plus parity tables, doc anchors, books, and
derived-fixture regen. **Date:** 2026-10-31.

Adoption only: `spec/rfc-0.1/**`, `spec/rfc-0/**`, `02-xcabi-events-v0.md` and `rust/**`
were NOT modified (`git diff --stat` on them is empty — §4).

## 1. What was done

- **`@ctxvm/node`** (`packages/node/src/tracer.ts`): NEW `declarePage()` choke point —
  both `page.declare` push sites now go through it, so the wire shape has one owner.
  - `turn` = the tracer's counter AT DECLARATION TIME; the pre-first-render counter
    (−1) stamps as **0**, the standing RFC-0 §5 convention `emitFault` already uses
    (`const t = turn < 0 ? 0 : turn`). The reveal law is untouched: a page still gets
    its `page.render` at the boundary AFTER its declaration.
  - `latencyMs` = NEW optional `PageInput` field, strict intake `declareLatencyOf()`
    (mirror of `providerUsageOf`): a finite safe integer ≥ 0 is emitted, anything else
    is an ABSENCE and the key is omitted — never null, never a float, never coerced.
    `0` is a fact and is emitted.
  - Wire order: `type, page, turn, latencyMs?, ts` (`ts` still lands LAST via `push`,
    unchanged from the R4-ts card).
- **`packages/hermes/src/plugin.py`**: the same two things, mirrored — NEW
  `_declare_page()` method (both call sites) and NEW module-level `declare_latency_ms()`
  intake. Python-specific law: `bool` is excluded explicitly because `bool` IS an `int`
  there (`True` must never become 1 ms).
- **Parity tables (both sides):** `CANONICAL_EVENT_KEYS["page.declare"]` gains `turn`
  in `packages/opencode/test/meta-parity.test.ts` and
  `packages/hermes/test/test_plugin.py`, each with a comment recording that `latencyMs`
  is accepted-but-unemitted (the `providerUsage` precedent: a table lists what a fixture
  actually exercises, so the pin stays true to the wire rather than aspirational).
- **Field-order pins extended (both sides):** the node
  `"event types + field order match the RFC-0 §6 payload shapes"` pin and the hermes
  `test_event_types_and_field_order_match_rfc0` pin now assert
  `type,page,turn,ts` for a declaration that supplies no latency, keeping the
  `page`-object key tuple `id,kind,tokens` unchanged.
- **NEW pins (both ports):** declaration-turn (pre-first-render and mid-stream) and the
  `latencyMs` intake law (absent / `0` / valid / float / negative / NaN-or-bool / string).
- **Derived fixtures regenerated** (§3 of the report): ai-sdk canon trace and the hermes
  live-echo synthetic. Frozen drops untouched.
- **Docs:** `03-tracer-api-ts.md` impl note, `09-plugin-parity.md` §2 dated note;
  `tools/run-ci.sh` counts truth-up.

## 3. Semantics recorded (W3/W8-facing)

- `turn` on `page.declare` is the DECLARATION turn, not the render turn. A page declared
  before any render is stamped turn 0; its `page.render` still arrives at the first
  boundary. A page declared while turn t is current stamps t even if it renders at t+2
  (a real case: declare at turn 1, two renders later reveals it).
- The turn field is provenance for the declaration — it does NOT change reveal
  bookkeeping, residency accounting, or the fault-resident rule.
- `latencyMs` on `page.declare` is the page's own acquisition latency, not model latency.
  `call.meta.latencyMs` remains the measured model-call latency (unchanged).
- **No lane emits `latencyMs` today.** opencode's hook terrain is
  `session.context`/`tool.execute.before`/`tool.execute.after`; hermes's is tool pairs +
  `pre_llm_call` history (the RR-W2B1 §1 audit). Neither carries a timing fact, so every
  real capture and every regenerated fixture carries `turn` only. The slot exists so a
  harness that measures its own tool call can hand the fact in without a schema change.

## 6. Deviations

1. **The first draft of the node turn pin encoded a wrong expectation, and the
   implementation run caught it.** I wrote the mid-stream case as "declare immediately
   after the first `render()` → turn 1". The counter law is the opposite: `render()`
   advances the counter to 0 on the FIRST boundary, so a declaration right after it is
   turn 0 and needs a second render to be turn 1. Observed `[0,0,0]` against my expected
   `[0,1,1]`. The pin was corrected to hold the real law (pre-first-render → 0;
   declare at turn 1 after two renders; render of those pages at turn 2), and the
   assertion now pins the reveal turn as well, so the declaration-turn-vs-render-turn
   distinction is test-enforced on both ports. The red-before for that pin stayed
   genuine (the key was absent), but the drafting error is recorded rather than hidden.
2. **Parity tables carry `turn` but not `latencyMs`.** The card's fallback instruction
   applied: the pin compares the exact observed key set, and no fixture exercises
   `latencyMs`, so listing it would break the pin and lie about the wire. The comment in
   both tables records the slot and the rule (the `providerUsage` precedent).
3. **Two extra hermes intake cases beyond the node matrix** (`bool`, string) — Python's
   `bool ⊂ int` makes `True` a live hazard that TypeScript simply does not have.

Nothing is blocked; the card is complete and reproducible as committed.
