# RR-W13 — bill the static prefix

**Card:** W13 of `08.1-UPDATE-PROMPT.md` (added 2026-11-01 after reading arXiv:2610.22732v1).
**Status:** implemented in both adapters, schema, codec and validator. `ALL GATES GREEN`.

## Why

TokenEconomizer (arXiv:2610.22732v1 §2.2, §4.2) cuts mean cost 18.4–30.9% at comparable Pass@1.
The largest single mechanism is tool pruning — −13.2% on Sonnet 5, −17.7% on Opus 4.8 — because 23
tool schemas load on every turn, no repository calls more than 7, and 16 are never called.

ctxvm modelled only pages that get *touched*. The cost the paper removes is billed whether or not
anything touches it. Our one real capture reported waste 1.000 on 6 events and 268 tokens: degenerate
exactly because the expensive object was invisible to the ledger.

## What landed

| Surface | Change |
|---|---|
| `model.rs` | `PrefixCost` struct; optional `prefix` on `turn.render`; version gate: `prefix` requires `schemaVersion "0.1"`; allowlisted in the codec's strict field check |
| schema `x-cabi-0.1.json` | `$defs/prefixCost` (all counters nullable, `source` required, `enum measured/estimated/unknown`), wired into the `turn.render` branch |
| RFC-0.1 text | new §R6 describing the field, its motivation and the "unknown is a first-class answer" rule |
| hermes adapter | subscribes `pre_api_request`; the host's own counters land on the turn's render row |
| node/opencode | `PrefixCost` type + `onApiRequest()`; the OpenCode adapter cannot see the request, so it emits `{"source":"unknown"}` |
| validator | three new negatives (no `source`, invented source, negative count) + one v0-boundary case |
| conformance vector | `events-v0-1.jsonl` render row now carries a measured prefix |

**Where the numbers come from.** `agent/turn_api_request.py:60-79` in the Hermes install passes
`tool_count`, `message_count`, `request_char_count`, `system_prompt` and `approx_input_tokens` to
`pre_api_request`. The adapter maps the counters verbatim. `approxInputTokens` is the host's own
estimate and is labelled as an estimate by its field name — it is never called billed tokens.

**Key order.** `ts` must ride last on every event (R4). A new field therefore goes *before* it in
all three emitters; that broke the TS and Python "ts rides last" pins until reordered, and the Rust
struct's declaration order had to match or the canonical writer produced a different byte string
than the committed vector.

The ai-sdk canon (`fixtures/echo-thrash.trace.jsonl`) was regenerated because the emitter's output
shape legitimately changed. The generator deleted every `CTXVM_*` var before running, including the
`CTXVM_TRACE_TS=0` needed to match the replay pin's byte comparison, so `test/gen-fixture.ts` now
sets it back after the wipe. Without that, `npm run gen` produced a ts-stamped canon that its own
replay test could never reproduce.

## Limitations and non-claims

- **No live confirmation yet.** The gateway must restart to load the new wrapper. Until then the
  evidence is the payload contract in the installed Hermes source plus the unit tests, not a trace
  from a real session. The first post-restart capture should show `prefix.toolSchemas > 0`.
- The OpenCode adapter reports `unknown` and that is not a placeholder to be filled by guessing: the
  plugin has no request visibility today.
- `systemPromptBytes` counts what the host passes to the hook. A provider that moves the system
  prompt out of `messages` (Anthropic does) still gets a byte count, but the *billed* prefix may
  differ; the field measures the string, not the invoice.
- Nothing here reduces cost. It makes the cost measurable — which is what W13 asked for.
