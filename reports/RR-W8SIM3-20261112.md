# RR-W8SIM3-20261112 — the call-granularity scorer PASSES, and that closes the simulator question

Zero spend. Run `w8b-20261112-201127`, paged arm only, 20 prompts, budget 60,000, longcat free tier,
plugin 0.13.13. Verdict **CELL**: 41 selections, **227,963 evicted tokens**, parsed-equal artefact,
41 calls, 498.3 s, $0.00.

## The rule, committed before this data existed (`2b6c950`)

```
after_k = min(before_k, budget)          the only input is the measured `before`
drop_k  = max(0, before_k - budget)
tolerance  median relative error of after_k ≤ 5 % on selections with a predicted drop,
           and every prediction's sign must match
```

## What this closes

`RR-W8SIM2` measured the same model at **turn granularity** and failed it: onset one turn early, median
error 33.3 %, total under-predicted by 31 %, residual growing ~3,200 tokens per turn. This run confirms
the diagnosis that card offered rather than assumed: the residual was the **second call of each turn**,
which the trace now records per selection.

```
turn granularity   FAIL   (33.3 % median; an artefact of one turn = two requests)
call granularity   PASS   (1.2 % median; sign exact)
```

## What it does not establish

- **The model is a clamp, so passing it is a statement about the policy, not about prediction.** It says
  the keep law really does fit every request under the budget and nothing else: no hidden second pass, no
  reordering beyond the eligible middle. It does not say a simulator could predict a *different* policy.
- n = 1 arm, one model, one budget, one session shape. The 16 drops are consecutive turns of a single
  session.
- Free tier, so nothing about cost; the paid cost direction was measured in cell-03 (2.11×).

## Erratum (2026-11-12, after `RR-SIM3CRITIQUE-20261112`)

The review lane is right on all three counts, and one of them changes the verdict's basis.

**1. The residual is whole-page quantization, not "the protected-set/scaffold gap".** Both `before` and
`after` are full-request token sums, so the protected set and scaffold are on both sides and cancel. The
engine drops whole pages (~4,424 tokens here ≈ 7.4 % of the budget), so `after` lands somewhere in
`(budget − page, budget]`. Across the 16 dropping calls the errors are bimodal: nine at 0.28-1.21 % and
seven at 6.01-8.21 %, because a page boundary is crossed between them. A 5 % point tolerance is
**tighter than the instrument's resolution**, and the earlier PASS depended on the 9/7 split: two more
prompts would have flipped it to FAIL. That is not a property of the policy.

**2. The model is now a bound, and the point tolerance is retired (`tools/w8-sim-score.py`, S3).**

```
predicted   budget - 2*page  <  after_k  <=  budget
page        the smallest drop in the run = the one-page case (4,424 tokens)
PASS        every dropped request inside the interval
diagnostic  median |after - budget| / budget = 1.15 %, reported but not the verdict
```

Result on the same capture: **PASS**, all 16 inside `(51,152, 60,000]`. The verdict now says what the
instrument can actually resolve: the policy fits every request under the budget within page quantization,
and nothing finer than one page can be claimed.

**3. `CALL_LOG` censored non-dropping calls, so the sign test was one-sided.** Fixed in 0.13.14: every
selection is logged (`{before, after, dropped, budget}`), so a call that should have dropped and did not
now enters the scorer. The earlier "every prediction's sign matches: True" was true by construction and
is worth nothing; the S3 verdict does not rely on it.

**4. Two sidecar fields were still reading old paths** (the review lane's §1.3): `plugin.engine` used the
instance meter — now the module total; `evictedPagesCount` was 0 because `_value_tokens` and
`identity_tokens` disagree on extensions — the join now compares stems. Both are fixed in 0.13.14 and
**must be confirmed on the next capture**; this card does not claim them.
