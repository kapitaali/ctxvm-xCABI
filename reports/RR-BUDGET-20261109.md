# RR-BUDGET-20261109 — the pair ran at 200,000, not 24,000

Card: one defect, one fix. The pair that produced `NTR −2.14` never had the treatment condition
applied. The treatment was "ctxvm engine at a 24,000-token budget"; what ran was the engine at its
**200,000 default**, where it has nothing to select.

## 1. The evidence, from the captures themselves

Both cells' `turn.render` for turn 0:

```
naive  resident 62,707  evicted 0  headroom 137,293   -> declared budget 200,000
paged  resident 63,293  evicted 0  headroom 136,707   -> declared budget 200,000
```

`budget = resident + headroom` is the only way the number appears, and both arms agree on 200,000.
`evictedTokens: 0` in both: the engine ran out of headroom to use, not pages to evict. The
`engineSelections: 14` is therefore truthful and useless — the hook was called fourteen times with
84% of its budget free.

## 2. Why

`packages/hermes/live/__init__.py:356` read the budget from one place:

```python
raw = os.environ.get("CTXVM_BUDGET_TOKENS", "200000")
```

Nothing set that variable — deliberately, because the run rules forbid env rituals — and no profile
declared a budget either. The harness rules said "do NOT export CTXVM_*", the plugin had no other
source, so 200,000 won by default. **A default is not a treatment.** The plan's one-factor design was
satisfied on paper (`context.engine` differs) and defeated in practice (the budget, the other half of
the treatment, was identical in both arms).

## 3. The fix (plugin 0.10.11)

Budget precedence, and the source recorded with the value:

```
plugins.entries.ctxvm-tracer.settings.budgetTokens   (the serving profile's config)
  > CTXVM_BUDGET_TOKENS                               (compatibility)
  > 200000                                            (default)
```

- `_budget_from_settings(ctx)` returns `(tokens, source)`; the engine is built with that value.
- The coverage sidecar's `plugin` block carries `budgetTokens` and `budgetSource`, so a cell can
  never again be read without knowing which budget produced it. The trace meta is unchanged — this
  is an observation, not a wire field.
- `~/.hermes/profiles/w8-paged/config.yaml` declares `budgetTokens: 24000`; `w8-naive` declares nothing.

Verified:

```
hermes config get plugins.entries.ctxvm-tracer.settings.budgetTokens -p w8-paged   -> 24000
hermes config get plugins.entries.ctxvm-tracer.settings.budgetTokens -p w8-naive   -> not set
python (installed copy): settings -> (24000, 'settings');  no setting -> (200000, 'default')
```

## 4. Status of the pair

**Reclassified: a no-op measurement, not a paging result.** The two cells remain bought and reported
(`reports/W8-SPEND.md`), and the artefacts are correct, but the treatment arm was never run. The
cache arithmetic in `design/w8-cache-stable-selection.md` stands as arithmetic; it has not been
tested. Cells that count: 0.

## 5. What the next cell must prove before it is allowed to count

```
1  sidecar plugin.budgetTokens == 24000 on the paged arm, budgetSource == "settings"
2  turn.render evictedTokens > 0 on at least one turn
3  per-call prefix peaks below 200,000 by a margin consistent with the budget
4  cache-write total below the naive arm's, with cache-read above it
```

If (1) is not 24000, the cell is void at turn 0 and should be stopped before it finishes.
