## 1. Method (exactly what was run)

Each check = one unauthenticated HTTP GET against the registry's public
package endpoint, with the response code recorded as observed today. **Where a
status means a name is free, that meaning is registry-specific and is stated
per row; where the status cannot prove availability at all, the row says so.**

- PyPI: `https://pypi.org/pypi/<name>/json` — 404 = no project with that name
  exists (caveat: PyPI reserves some project names per PEP 541 for the admins'
  own reasons; a 404 does not deposit a guarantee).
- crates.io: `https://crates.io/api/v1/crates/<name>` with the required
  User-Agent header (their API returns 403 without it — observed in this same
  session, then retried) — 404 "crate does not exist" = the name is unclaimed.
- npm: `https://registry.npmjs.org/<name>` — unscoped 404 = no published
  package with that exact slug (namespaces: npm lowercases; "xCABI" maps to
  `xcabi`); **scoped names (`@ctxvm/*`) are different**: the 404 observed today
  while no `@ctxvm` package exists ANYWHERE means nothing about future scope
  availability — npm has no public pre-reservation check, and a scope becomes
  whoever's on the first publish under it. Registered as that limitation, not
  as availability.
