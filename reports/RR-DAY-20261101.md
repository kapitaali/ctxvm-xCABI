## 6. Afternoon — capture that works without a manual (14:00 → 14:41)

Two commits, both mine, both prompted by a real failure: a session was traced and then could not
be found.

| Time | Commit | What it was |
|---|---|---|
| 14:22 | `040ac74` | Four adoption defects fixed across the hermes and opencode adapters, with the contract written into `09-plugin-parity.md` §5.1 |
| 14:41 | `59200b6` | The first default-ON capture, analysed; model now comes from the payload, provider still does not |

**The diagnosis, including my own error.** The capture had landed in
`/home/theb/.hermes/~/.local/state/ctxvm/traces/` — a literal `~` directory — because the slash
command never expanded it. I first read the empty log in the *real* directory as "the hooks never
fire"; that was wrong, and the witness log in the literal-`~` directory disproved it. What the
failure actually exposed:

1. `~` not expanded (both adapters) → `expanduser`/`expandvars`/`resolve`, with a test asserting
   no `/~` can appear.
2. Capture OFF unless `CTXVM_TRACE_DIR` was set → unset now resolves to
   `${XDG_STATE_HOME:-~/.local/state}/ctxvm/traces`, created `0700`; opt-out is documented
   (`CTXVM_TRACE=0`/`off`/`false`/`no`, or an empty dir).
3. `stop` reported "traces flushed" while writing nothing → `_flush_traces()` returns a count and
   the command says `N trace(s) flushed` or `0 traces written — no events were captured between
   start and stop`.
4. Identity was env-only → `identity_from_payload()` reads model/provider from the hook payload,
   flat keys and the nested `model: {id, providerID}` shape, env as fallback.

`/ctxvm-trace status` now prints the resolved absolute dir **and its source**; `PLUGIN_VERSION`
and `plugin.yaml` are 0.3.0 so a stale running copy is identifiable from its own output.

**Verification.** Hermes suite 91 → **95** (2 old tests rewritten because they encoded the retired
default-off contract), opencode 58 → **59**; counts trued up in `run-ci.sh`; `ALL GATES GREEN`.
Then a live capture with **zero** `CTXVM_*` variables in the gateway: `ctxvm-dev.jsonl`, 1,530
bytes, 6 events, `model: deepseek/deepseek-v4.1-flash-1017` read from the payload, `provider:
unknown`, `replay` exit 0, dir `0700`.

**Two facts from that capture that stay open.** `provider` is not in the payload under any
spelling the adapter knows (upstream fix preferred; the alternative is reinstating the env ritual
this card deleted). And `session_start` never fires in this build — capture works because
`pre_llm_call` creates the tracer lazily, but identity sent only at session start would be lost.
