# RR-W14 — environment identity, so sessions can form a stream

**Card:** W14 of `08.1-UPDATE-PROMPT.md`. **Status:** landed in both lanes; `ALL GATES GREEN`.
Plugin 0.6.0.

## 1. Why

TokenEconomizer (arXiv:2610.22732v1 §3, §4.2) optimises a **task stream in an environment**, and its
savings only appear by roughly the sixth task. Our ledger had per-session identity only: two sessions
in one repository were unrelated rows. Ordering was already available (`ts`, R4), so the missing
piece was a grouping key.

## 2. What the key is

```
environmentId = "env-" + sha256(basis)[:12]
basis = "remote:" + credential-stripped, normalized remote.origin.url
      | "path:"   + absolute worktree path (no origin)
```

Only the digest reaches the trace. The raw basis is never emitted, so a trace cannot carry a home
directory, a client's remote name, or a branch. Branch is deliberately excluded: it changes per task
and can identify a client. One repository therefore has one id across clones and machines, and a
non-git directory still gets a stable one.

The schema pins the shape: `^env-[0-9a-f]{12}$`. Two validator negatives enforce it (a path, and a
short id), and the v0 boundary rejects the field on a v0 trace.

## 3. Per lane, and why hermes differs

| Lane | Source | Absent when |
|---|---|---|
| opencode | `deriveEnvironmentId(process.cwd())` | never — the plugin runs in the project |
| ai-sdk | same, unless the caller passes one | never — the library runs in the caller's process |
| hermes | explicit `CTXVM_ENVIRONMENT_ID` only | the operator registered none |

Hermes is the exception and the reason is structural, not laziness: the plugin executes inside the
gateway process, so `cwd` is the gateway's directory, not the session's project. Hashing it would
give every session the same fake environment — a number that looks like data and means nothing. The
host exposes no workspace fact in any payload audited (`on_session_start`, `pre_tool_call`,
`post_tool_call`, `pre_llm_call`, `pre_api_request`, `on_session_end`), so the honest answer is
absence. The key is validated at the boundary: a path or a short id is dropped, never coerced, and a
test asserts no absolute path can appear in a trace.

This is the same law as the side-effect table: registration-owned, or absent.

Byte-stability: fixtures that pin bytes pin a fixed id (`env-000000000000`) rather than a derived one,
because a hash of the CI runner's checkout path would differ on every machine and break the
byte-identical test for a reason that has nothing to do with the code.

## 5. What this enables and what it does not

- Enables: grouping sessions by repository, ordering by `ts`, and therefore the stream-level
  questions the paper asks — repeated setup across tasks, files re-read in session after session,
  whether a policy's savings appear by the sixth task.
- Does **not** enable: anything on the hermes lane until an operator registers an id, and nothing at
  all until there are two sessions in one environment. No policy, no controller, no claim of savings.

## 6. Open

- The hermes lane has no automatic source. If the host ever exposes a workspace fact, the adapter
  should derive the id from it and drop the env requirement; that is the preferred fix.
- `taskId` was considered and left out: the harness exposes `task_id` on some hooks, but its scope
  (per turn vs per task) is not documented, and a wrong task boundary is worse than none. W14's
  acceptance is the environment stream; a task key can be a later additive field.
