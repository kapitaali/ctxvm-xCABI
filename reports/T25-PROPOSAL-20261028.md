## §1 Objective

Unpark the **opencode half** of the design's per-harness `handoff-inject` beat
(`design/uc1-plugin.md` §1.3(3): "materialize resident pages / identity stubs
into the new session's assembled context at boot, per the `handoff-inject`
feature (off by default)"). T24 landed the LIBRARY lane as injection-as-DATA —
the app owns message assembly, so the middleware stayed a byte-mirror. The
opencode plugin sits at a different point in the stack: **it holds the
assembled request draft** at the `session.context` hook, so there is no app
above it to hand data to — the plugin IS the integration layer. The design's
own pinned mapping already resolved the feasibility question the design letter
called UNVERIFIED. Hermes stays where it lawfully is: 5 observed hooks, no
context-mutation surface → verify-only + operator guidance (their
`/ctxvm-resume` UX, landed 2026-10-28, is exactly that fallback).

## §2 Survey facts this proposal is built on (probed 2026-10-28, read-only)

- **The mutation reach is pinned, not open.** `design/adapters.md` (pinned
  upstream `anomalyco/opencode` `e965774fa`, v2.1.3): `prepare("primary", …) →
  hooks.trigger("session","context",{ ...draft, agent, tools })`; payload type
  `SessionContext extends SessionRequest` (system, **"mutable `messages`"**,
  options, tools, agent). The spread is shallow — the payload's `messages`
  array reference is the live draft's — so a prepend reaches the real request.
- **One `session.context` fire = one model request = one xCABI turn.** Boot
  injection therefore = the FIRST fire of the resumed session, exactly once.
- **The m6 knowledge-stateful tail law cuts both ways:** render residency is
  derived from the real context (`diff full-vs-slice … diverges at turn.render
  residency 253-vs-93`). An honest trace of an INJECTED session must show the
  injected bytes — capture-order is a real §7 question (Q4).
- **The plugin shim models the payload readonly**
  (`packages/opencode/src/opencode-contract.ts`: `readonly messages: readonly
  LooseMessage[]`, `readonly system: readonly unknown[]`) — mirror discipline
  for the capture path; the gated mutation is a controlled escape from the
  readonly view, never a type-system accident.
- **No `CTXVM_FEATURES` vocabulary exists in opencode live today** (gates are
  dedicated envs: `CTXVM_RESUME_FROM`, `CTXVM_HANDOFF_TURN`,
  `CTXVM_HANDOFF_STOP`); hermes gates `/ctxvm-handoff` and `/ctxvm-resume` via
  `CTXVM_FEATURES=handoff`.
- **The boot law is already in place:** `CTXVM_RESUME_FROM` → `resumeVerify`
  at boot BEFORE hook work (B3 + m7 law) — injection arms only off that
  verified boot, never rescuing an unverified one.
- **T24's assembly exists and is a pure function of the package**:
  `packages/ai-sdk/src/resume-brief.ts`. The opencode module law (imports
  `../../node/src/index.ts` only) makes ai-sdk unreachable — so opencode gets
  its own mirrored `src/resume-brief.ts` (line-for-lines from the ai-sdk
  module, importing opencode's own `uc1-handoff.ts` `snapshotDigest`; the
  mirror direction ai-sdk → opencode is new but the same discipline: T22 went
  the other way).
- **The plugin must never break capture** (witness law). Structural package
  problems at arm time degrade to loud witness + injection disarmed — NOT the
  library's init-throw law (there is no init to throw out of safely; the
  plugin is long-lived).
- **The disarm red-pin shape already exists**: `plugin.test.ts` pins a
  frozen-payload byte-compare through `replayHooks` — the disarmed capture
  path is already test-pinned byte-exact.
- **The m6/m7 README law stays true**: "Resume is observation, not injection
  (v0 §3)" — T25 v0 ships NO corpus drop; all shipped packages remain
  observation-shaped.

## §3 Proposed law (v0)

**Boot (unchanged):** `CTXVM_RESUME_FROM` → `resumeVerify` at boot; unverified
→ loud reason, verify-only continues (never blocks — existing law).

**Arming:** verified boot + explicit gate (Q3) + brief assembly succeeds →
armed. Assembly failure (structural package problem) → loud witness line,
injection disarmed, capture continues (plugin law, NOT the library throw law).

**Assembly (mirror module):** `packages/opencode/src/resume-brief.ts` — the
T24 brief, resolver-less in v0 (Q5): stub slots carry `stubText` verbatim
(package-complete), full slots degrade loudly to
`[unresolved: <ref> — content not provided]` (the plugin has no app-supplied
content source; the operator fetches content exactly as the m7 recipe did).
Witness at boot: `resumeBrief assembled: slots=N full=M stub=K digest=… turn=…`.

**Delivery (Q1):** at the FIRST `session.context` fire of the resumed session,
prepend the brief into the payload (Q2 decides `system` vs `messages`), then
let the capture proceed (Q4 decides the order). Witness:
`resumeBrief injected turn=N session=… surface=…`. Later fires: no-op (once
per session — boot semantics).

**Red-pins:** gate off → payload byte-untouched (the existing frozen test
extended); armed → exactly one prepend on the first fire, none later; the
tracer core stays read-only in every path (the plugin mutates the draft, the
tracer only meters it — design risk 5's "mutability temptation" stays fenced
at the module boundary); sidecar canon untouched (witness lines only, the
T24 derived-data law — no new keys).

## §7 Open questions (recommendations — I proceed on acceptance)

1. **Delivery shape:** gated mutation at the `context` hook (RECOMMENDED — the
   pinned contract documents mutable messages; data-only degenerates to the
   verify-only + operator guidance that already exists) vs keep the per-harness
   beat parked (v-next stays parked; board closes).
2. **Injection surface:** prepend into `system` (context fragment, no fake
   turns, conversation history stays native — RECOMMENDED) vs `messages`
   unshift (synthetic user turn; mirrors the m7 paste but risks the agent
   reading it as a human utterance).
3. **Gate vocabulary:** `CTXVM_FEATURES` containing `handoff-inject` (one
   cross-harness gate law, shared with hermes — RECOMMENDED) vs a dedicated
   `CTXVM_INJECT=1` env (opencode's current dedicated-env style).
4. **Capture order:** inject-then-capture (the turn.render row meters the
   mutated draft — the trace shows what the model actually saw; the
   diff-vs-source relation diverges lawfully per the m6 tail law —
   RECOMMENDED) vs capture-then-inject (native-draft trace; injected bytes
   invisible to the trace — an honesty gap).
5. **Resolver:** resolver-less v0 (RECOMMENDED — no app content source exists
   in the plugin lane; full slots degrade loudly; stubs still package-complete)
   vs an escape-hatch resolver env (content-via-env is code-not-data —
   rejected shape, listed for completeness).
6. **Cross-lane clearance:** §7 acceptance doubles as the operator's
   pre-clearance for touching `packages/opencode/**` (this session's
   do-not-touch list) — the T22-era precedent (UC1-PAUSE-WIRE backfill,
   cross-lane approved).
7. **One commit** for code + tests + books (RECOMMENDED).
