and any header/implementation are gated on W8 or **D7**. Nothing was designed or

**Attribution:** commits sign `kapitaali <teppo@kapitaali.com>`. No push.

## 1. What was done

`design/runtime-abi/00-reconciliation-and-justification.md` (new):

- **Step 0 — reconciliation.** There is **no `00-SPEC.md`** (the prompt assumes one);
  the spec surface is `02-xcabi-events-v0.md` + sealed `spec/rfc-0/`. "xCABI" today
  denotes an *exchange* format (pages/faults/renders/evictions/turn facts), not a C
  calling convention — so W12's usage of the same name is a **collision**. Drafts use
  the provisional name **`ctxvm-rt`** and must stay consistent with the sealed trace
  vocabulary. Flagged under D7.
- **Step 1 — justify before designing.** The prescribed measurement ("allocation/copy
  share of real session latency from W1/W4 traces") **cannot be performed**: no real
  capture records latency. A microbenchmark of the path ctxvm actually owns (canonical
  JSON + SHA-256, and log parsing) gives the upper bound on anything a zero-copy ABI
  could save in the tracer — and it is negligible.

## 3. The conclusion, stated the way the prompt demands

> "If the benefit is not measurable, say so and shrink the ABI to the minimum needed
> for safe handles."

Done, in the note: **0.26 ms to canonicalise and hash a 50 KB tool result is ≤ 0.1 %
of any model round trip** (even m1's *synthetic* 860–2 440 ms), so zero-copy at an ABI
boundary buys nothing this repo can measure. The justified minimum is: opaque,
generation-tagged handles; explicit ownership ("nothing allocated on one side is freed
by the other"); error codes, no unwinding. Arena/frame allocation, CoW branching and
schema-by-handle dispatch stay unbuilt until W8 has a paging result or D7 authorises
the design.

Where the benefit *would* have to appear — prefix/KV-cache reuse priced in net tokens,
large payloads crossing a boundary in a sub-10 ms local loop, multi-branch sharing in
a pager — none of it is observable in 17 traces that never page and never record
latency. The one measured effect in that family is request-level (Pichay's 84.4×
median re-mention amplification, arXiv 2603.09023 §5.1, verified in
`RR-ADOPTIONINTAKE` §1), and it argues for paging, not for a C ABI.

## 4. Deviations

- The card asks for "a half-page analysis"; this is a one-page note plus a Step 0
  reconciliation section, because the naming collision had to be resolved before the
  analysis could be written without ambiguity.
- No microbenchmark tool was committed: the numbers are reproducible from the commands
  quoted here (stdlib python, 20-run median) and shipping a benchmark harness for a
  gated card would be scaffolding without a consumer.

## 5. Discoveries

1. **The corpus cannot answer latency questions at all.** Five `latencyMs` values, all
   synthetic. Any future claim about overhead, cache benefit or paging cost needs a
   clock and a duration in the capture — the **same clock** W6 needs for OTel and W7
   needs for RFC-0.1. Three cards, one field: this is now the strongest argument for
   the RFC-0.1 clock proposal.
2. **The Hermes contract already carries `api_duration`** (`post_api_request`), so the
   cheapest way to get real latency is the Hermes adapter lane, not a new instrument.
3. **`00-SPEC.md` does not exist** and is referenced by the owner's prompt: worth
   knowing before anyone else goes looking.
