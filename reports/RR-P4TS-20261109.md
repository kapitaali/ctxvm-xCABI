## The verdicts as recorded

**Verdict 1 — (a) + (c).** `ts` stays optional in umpire ledgers (no emitter, validator, or schema
change); the ordering rule is recorded as the one honest thing: within a ledger, LINE ORDER
GOVERNS (one decision = one turn, `session.open` first), an absent `ts` means **unknown, never
zero**, and no order across ledgers/sessions is implied. (b) is refused as a default — the
D9 default-ON + `CTXVM_TRACE_TS=0` reproducibility posture and the 0.1/v0 asymmetry make the
mandate both against law 6 and structurally impossible for v0-only emitters.

**Verdict 2 — what breaks** — verified consistent (the reviewer's table): (a) breaks nothing
(replay exit 0 across the fleet, sealed v0 untouched, validator untouched); (b) xCABI-wide breaks
the four 0.1 fixtures and needs a version gate above 0.1 — plus (my addition) it strands any
future v0-only emitter by construction; (c) documentation only.

**Verdict 3 — no 5-touchpoint card.** `ts` already exists in RFC-0.1 (:34); (a) and (c) add no
field. The (c) clause is an umpire spec edit = owner approval + D-number. The future
per-session sequence number remains the named field to evaluate IF the falsifier fires — with the
full five touchpoints (Rust model before `ts`, `FIELD_ALLOWLIST`, v0.1 schema branch, `check_version`
gate, validator negative).
