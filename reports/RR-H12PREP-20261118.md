# RR-H12PREP-20261118 — H12 armed: the mode is a profile setting, the cell's profiles are set, and a restart is owed

Owner confirmed H12 inside the $1 cap. This card is everything that must exist before the cell runs; **the cell
itself has not run**, because the build that carries the per-profile mode is on disk and not yet in the gateway.

## 1. Why the mode had to become a profile setting, not an env var

The engine reads `CTXVM_SELECTION_MODE` at construction, and construction happens **once per process**. One
gateway serves every profile, so an env var would have set one mode for the operator and both arms — the exact
snapshot bug that made the arms indistinguishable in 0.10.x. So the mode now resolves per turn, like the budget:

| order | source | where it comes from |
|---|---|---|
| 1 | **profile setting** | `plugins.entries.ctxvm-tracer.settings.selectionMode` in the serving profile's `config.yaml` |
| 2 | `CTXVM_SELECTION_MODE` | the process environment, as a fallback |
| 3 | `fresh` | the shipped default |

An **explicit** mode (constructor or env) is never overridden; a profile's mode is adopted **at call time**, and a
mode change clears the held selection and the call counter so a session cannot inherit a hold from another mode.

`profile_policy.read_yaml_subset` gained the third key, with the same narrow scanner the budget uses. No new YAML
parser, no host import.

## 3. The laws that pin it (4 new, suite 216 passed)

1. the mode is read from the profile's `settings.selectionMode` (`selectionModeSource: settings`);
2. a profile without the key resolves to `fresh` / `default`;
3. a profile's mode is **adopted at call time** (the law H12 depends on: one engine, many arms);
4. an explicit constructor mode is never overridden.

The adoption law caught a real trap while being written: a bare `import profile_policy` in the test resolved to
the **installed** copy under `~/.hermes/plugins/ctxvm-tracer/`, so the test read the old module and failed with a
`KeyError: 'selectionMode'` that looked exactly like a code defect. The test now loads the repo file by path.
