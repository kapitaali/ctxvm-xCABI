## W15 gets a plan, and the open decisions get closed

The first W15 draft (written by the other lane, in chat) left four decisions to be made during
implementation. Each one fails late if guessed at, so the plan of record decides them:

1. **Strict tool names, no alias table.** The Hermes fixtures say `"read"`, which is not a registered
   name, so those pages classify `MUTATING` — the fail-safe outcome, not a bug to patch with an alias
   map. A value assertion with a real host name replaces the temptation.
2. **The table is the host's verified bucket** — `_READ_SEARCH_TOOLS = {"read_file", "search_files"}`
   at `model_tools.py:615` — and nothing else. Consequence accepted and measured: against a ~20-tool
   catalog the class is nearly constant, the same information-free reading as `waste 1.000`.
3. **The env var extends, never decides.** Default-on with zero `CTXVM_*` is the property the
   plugin-defaults card established; `CTXVM_PROVIDER` was removed for exactly this reason.
4. **Canonical signatures go per-kind**, because `toolEffect` rides only on `kind == "tool_result"`.

The plan also answered a question the draft left open: `uc1-resume-golden.json` and
`uc2-diagnose-golden.json` contain zero `page.declare` rows, so W15 cannot destabilise them.
