## W8 implementation: the paged arm, the receipt intake, the DQ gate

`48e9ed7`, `RR-W8IMPL-20261106`. A lane had left the code complete and green (171 tests) with nothing
written about it: no parity note, no hook note, no observability resolution, no card record. This card
finished that and verified it.

What the code does, in three parts:

- **Provider receipts.** A strict intake takes the host's `post_api_request.usage` and emits the v0.1
  shape: whole-number buckets only, `inputTokens` as the uncached input (prompt minus both cache
  buckets, clamped), absence never coerced to zero. Last write wins per pending meta; a receipt seen
  before any meta exists attaches to the next one; the slot is `latencyMs`, `providerUsage`, `ts`.
- **The engine.** `live/context_engine.py` implements the preregistered `FaultPinPolicy`: selection
  under `vBudget`, never compaction, the compression seam a no-op so the two cannot double-apply, seven
  laws, `vBudget` 24000 with confirm-or-raise only, registration fail-open and inert unless a profile
  carries `context.engine: "ctxvm"`.
- **The DQ gate.** `tools/dq-secret-scan.py` blocks a drop on any credential, `.env`, e-mail or
  absolute-path hit, and prints positions and pattern names, never matched bytes.

**The deviation that had to be written down.** The frozen design (§6) and the preregistration both say
the plugin "turns `providerReported` TRUE for the W8 captures". The owner ruled option A on 2026-11-06:
the estimate keeps page-table semantics and the receipt is a separate fact, so the flag stays FALSE.
The frozen files were not edited; the erratum lives in the card report. It is analysis-neutral, because
the gate formula reads `cacheEstimate`, but a W8 trace will show "estimated" beside a real receipt.

Documentation landed with the code: the parity §2 W8 note (which also states the per-port rule that
leaves the opencode table untouched), seven hooks in `HOOKS.md`, and the `Provider usage` row plus the

## The provider remedy had been dead since 0.4.1

`RR-IDENTITY-20261106`, plugin 0.10.1. The log line `Rejected config path 'model' from plugin
ctxvm-tracer` appeared on every load and was read as noise. It was the failure: the host refuses a
plugin settings key rooted at `model`, the identity reader asked for `model` and `provider` inside one
`try`, and the raise aborted the loop before `provider` was ever read. So the `settings.provider` line
the reports have told the owner to write never executed, and fail-open hid it.

Fixed: the non-reserved `identity` mapping is read first, each bare key now has its own `try`, and a
refused root costs one field. The test suite gained a stub that mirrors the host rule — its old fake
was permissive enough to hide the defect. Also fixed: `provides_hooks` declared six hooks while the
plugin registers seven; `post_api_request` was missing.
