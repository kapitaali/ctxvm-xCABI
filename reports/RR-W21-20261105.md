# RR-W21-20261105 — a reused trace name can no longer replace another session's bytes

Card: #6 in `research/synthesis-20261105.md` ("collide-proof trace filenames"), recorded as a lesson in
`RR-LIVE-20261104`: a post-restart capture reused the default trace name, and the write-through
replaced the 13:0x evidence under identical filenames. The bytes were lost; only the witness log
remained.

## The rule

Before a flush writes anything, it reads `<file>.meta.json`:

- sidecar absent, unreadable, or naming the same session → keep `<file>`;
- sidecar naming a **different** session → write `<file>-<sha256(sessionID)[:8]>`,
  with the same suffix on the meta and coverage sidecars.

The same session therefore keeps its own name across repeated flushes, so a mid-session flush still
supersedes its own bytes and D9 byte-idempotency is untouched. A different session cannot collide,
even when an operator has pinned `CTXVM_TRACE_NAME`.

The rule is resolved per flush from the sidecar, not cached per process: the meta file is the
authority for who owns a name, and a cache could outlive a directory cleanup.

## The three lanes

| lane | site | note |
|---|---|---|
| hermes | `_collision_safe_file` in `packages/hermes/live/__init__.py`, used by `_write_trace` and `_flush_traces` | the write-through partial uses the resolved name too |
| opencode | `collisionSafeFile` in `packages/opencode/live/ctxvm.ts`, used by `flushTraces` | the mid-session trigger and cleanup share one flush path |
| ai-sdk | `collisionSafeName` in `packages/ai-sdk/src/flush.ts`, used by `writeCapture` | the coverage manifest is built with the resolved name |

The retention guard moved with it. Both prune functions take a `keep` argument, and passing the base
name while writing a suffixed file would leave the file just written unprotected — so the keep name is
now the resolved flush name. The coverage manifest's `traceFile` is likewise the resolved name, and
the W17 checker already enforces that `traceFile` equals the basename of the trace it covers.

## What the tests pin

One test per lane, each pre-writing a `meta.json` that names `another-session`:

- the flush lands at `<name>-<8 hex>.jsonl` (and the suffixed meta/coverage pair);
- the other session's bytes are byte-identical afterwards (a sentinel line);
- the manifest's `traceFile` matches the resolved name, and the hermes test runs the W17 checker to
  prove the suffixed pair is consistent.

A second hermes test flushes the same session id twice and asserts that no suffixed file ever
appears — the owner keeps its name.

assertion, and it had drifted.

## What this does not do

- **A session still overwrites itself.** Re-flushing one session replaces its earlier bytes on
  purpose; that is the idempotency law, and an operator who wants history keeps era copies
  (`tools/snapshot-capture.sh`, the m5 lesson).
- **It does not stop a collision inside 8 hex characters.** Two session ids sharing the first eight
  hex digits of their SHA-256 would collide; the probability is negligible and the failure is loud in
  the witness log.
- **It does not redact or sign anything.** A suffixed file is still only as trustworthy as its
  directory (`design/W20-trace-surface-extensions.md` §4).
- **It does not change the wire.** No event, no field, no schema: naming is a harness concern.
