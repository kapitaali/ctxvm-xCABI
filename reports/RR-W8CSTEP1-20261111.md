## 1. The hazard that would have worried the owner: CLEARED

The observer change (prose mentions become telemetry; `identifier_scan` stops emitting faults) touches
the **tracer**, and the tracer's output is committed as fixtures. If the committed fixtures' *structure*
changed, the frozen m3 drop sources could have been orphaned (law 5) or the committed live fixture would
have gone stale without the gate noticing (law 6).

**Measured, not assumed.** The committed live fixture
(`packages/hermes/fixtures/hermes-live-echo-synthetic.jsonl`, 18 events) was reproduced in-process from
the current in-flight code — `make_live_shape_trace()` — and compared **ts-stripped** (the generator
emits wall-clock `ts`, so raw bytes can never match):

```
ts-stripped identical:            True
event types committed == fresh:   session.open, page.declare, page.render, page.fault,
                                   page.declare, page.render, page.declare, page.render,
                                   turn.render ×5, call.meta ×5
fault sources committed == fresh:  ['tool_recall'] == ['tool_recall']
```

So the observer change does **not** alter the committed fixture's structure: the live shape's history
triggers a *re-read* (`tool_recall`), and the prose mention it also contains now lands as telemetry
that never enters the trace. The two **frozen** m3 sources (`hermes-echo-synthetic.jsonl`,
`hermes-thrash-synthetic.jsonl`) are protected by the generator's own refusal
(`_write_fixture` raises without `--force`) and are **not** regenerated by the test suite (the suite
calls only `make_live_shape_trace()`). **No corpus-checksum orphaning, no law-5 exposure, no stale
committed fixture.**

## 5. ERRATUM on this card's §1 (2026-11-11, after their `7e0f2df` landed): the "byte-identical"
## comparison was made against the WORKING-TREE copy, not against `HEAD`

**The claim in §1 was wrong in its method, and the claim in §1's heading was wrong in its conclusion.**
This card said: "the committed live fixture is reproduced ts-stripped byte-identical by the in-flight
code … ts-stripped identical: True". The comparison ran `make_live_shape_trace()` in-process and
compared it against the **working-tree** file — which their in-flight run had **already regenerated** —
and the line was labelled "committed" because the label was assumed rather than checked.

Against `HEAD`'s true bytes the picture is the opposite:

```
HEAD's committed package fixture : 20 content lines, faults [identifier_scan, tool_recall, identifier_scan]
the new observer produces          : 18 content lines, faults [tool_recall]
```

So the committed fixture was **not** reproducible by the new observer, and it **needed** regeneration —
which their commit `7e0f2df` did (regenerated **without `--force`**, carried in the same commit as the
observer change: law 6 satisfied — emitter-produced fixtures are regenerated, never hand-edited).

**The conclusion (no law-5 exposure) survives, for a different reason:** the *package* fixture is **not
checksum-pinned anywhere** — the `live-echo.jsonl` entries in `corpus/m2/checksums.sha256` and
`corpus/m8/checksums.sha256` are the frozen **corpus drops**, a different artefact (22 content lines,
carrying the two `identifier_scan` faults, untouched) — and the two frozen *package* fixtures
(`hermes-echo-synthetic.jsonl`, `hermes-thrash-synthetic.jsonl`) are protected by the generator's own
refusal and are never regenerated by the test suite. The full verification, with the corrected
comparison and the one gap it produced, is in `reports/RR-W8CVERIFY-20261111.md`.
