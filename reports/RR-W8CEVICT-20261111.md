# RR-W8CEVICT-20261111 — the other lane's "no `page.evict`" decision is SOUND, and the review side
## adds what the sidecar's eviction detail must satisfy to be checkable against the trace

Card: the other lane's agent commented on this lane's card: *"the card asks for `page.evict` and I did
not emit it: this policy removes the dropped messages rather than substituting stubs, and RFC-0's
`page.evict` requires a stub. Emitting one would describe a wire we did not send. So the count belongs
to `turn.render.evictedTokens` and the detail to the sidecar; `page.evict` stays for policies that
actually stub. That is an instrument-honesty decision, not an omission — and it means the verifier's
`evictions > 0` gate is now satisfiable by the trace without a fabricated event."*

**This lane's verdict: the decision is correct, and it is verified in the code and in the schema.**

## 1. Verified: this policy drops, it does not stub

The hermes engine's selection path (`packages/hermes/live/context_engine.py:366-444`) is
`_classify` → `_update_page_state` → `_credit_demand` → `_hard_keep` → `_plan` → **`_assemble(…,
dropped, repositioned)`** — and the returned list is built from what survives. There is **no stub
substitution anywhere in this engine**: no stub text is produced for a dropped page, because the
*rust* engine's stub mechanism (`ctxvm_core::render`'s `Slot { mode, stub_text, … }`) belongs to the
ctxvm core, not to this host-side engine. So the hermes policy's wire shape is "the message is gone",
not "the message was replaced by a stub" ✓.

## 2. Verified: RFC-0's `page.evict` *is* the stub event

`spec/rfc-0/x-cabi.schema-v0.json:73-84`:

```json
"page.evict": { "type": "object", "additionalProperties": false,
                "required": ["type", "turn", "page", "stubText"], … }
```

`stubText` is **required**, and it is *the replacement the model saw*. A drop-policy has no such
replacement, so a `page.evict` row here would assert a substitution that never happened — the row's own
shape would be the falsehood. Their phrasing is exactly right: *"emitting one would describe a wire we
did not send."*

**And the shape that fits is already in RFC-0**: `turn.render.evictedTokens` is a **required** field
("the render set for that call: resident/evicted token totals + headroom", `ctxvm-codec/src/model.rs:231-235`)
and it does not presuppose substitution ✓. So the count belongs there, the per-page detail belongs in
the **sidecar** (which is not a trace and is governed by `tools/coverage_check.py`), and `page.evict`
stays for the policies that really stub ✓ — the ctxvm core's own page-table policies, for instance.

**This lane's own earlier note is hereby corrected in that respect**: the card's §6 asked for
"`page.evict` per dropped page", and that ask was wrong for *this* engine. The correction is recorded
here as an erratum on the request, not on the decision — the decision is better than the request was.

## 3. The rule this decision establishes (worth writing down, because it will recur)

**A missing event is a gap; a wrong event is a falsehood.** An instrument that emits an event whose
shape asserts something the policy did not do has made the trace lie in a way no checker can catch —
the shape is valid, the claim is false. Where the wire shape does not match the event's semantics, the
honest move is to report the *count* in the field that can carry it and the *detail* outside the trace.
That is the same discipline as the rest of the books: the trace is evidence, and evidence must not be
manufactured.

## 4. What the sidecar's eviction detail must satisfy to be checkable (the review side's addition)

The detail is only useful if it can be **checked against the trace**. The standard the `proseMentions`
number set (`reports/RR-W8CVERIFY-20261111.md` §2) is the precedent, so the new sidecar fields should
carry the same kind of rule in `tools/coverage_check.py`:

1. **Every dropped page must name a page the trace declared** — keyed by the **logicalRef**, the same
   string the trace's `page.declare` carries and the same key form `proseMentions` uses ✓ (the key
   invariant was verified in `src/plugin.py:308` and confirmed on a real capture).
2. **The per-page token totals must sum to the trace's `turn.render.evictedTokens`** for that turn —
   the sidecar's detail and the trace's count are two independent statements about the same event, and
   the checker is where they must agree ✓ (this is the cross-check a drop-policy *can* have, and it is
   the only witness it will ever get).
3. **A control arm must report no evictions at all** (no selections ⇒ nothing dropped) — the
   arm-aware counterpart of the verifier fix.
4. **`repositioned` is a second kind of change** and must not be folded into the eviction count: the
   engine's payload carries both ✓, and only the dropped units' tokens belong in `evictedTokens`
   ✓ (`evicted = sum(units[i].tokens for i in dropped …)`).

**One implementation note, from reading the in-flight payload:** the engine reports
`"dropped": [sorted(units[i].id_toks) for i in sorted(dropped)]` — the page's **identifier tokens**, not
its logicalRef. The observer can map tokens → ref (it holds `_declared` keyed by ref with the pages'
identities ✓), but a token list is ambiguous where two pages share argument tokens, and the checker's
rule needs the precise key. **Carrying the logicalRef in the engine → observer payload** (or having the
observer resolve it unambiguously) makes rule 1 checkable as stated.
