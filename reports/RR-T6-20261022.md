# RR-T6 — MCP tool-shim design note

**Card executed:** T6 (S) · **Date:** 2026-10-22

## What was done

- `design/mcp-shim.md` (145 lines — card cap 180) — loader-side decorator over
  MCP client `callTool`; pure markdown, no code:
  - **interception point:** client-SDK `callTool`, one-line swap per `03`; NOT
    transport (caching spans) / NOT server (provenance + remoteness)
  - **page identity:** `tool:<server>.<name>(<canonicalArgs>)` logicalRef
    (truncation + sha256.8 suffix), sha256 contentHash, kind mapping (text →
    tool_result, image blocks → image_ref, `isError` ⇒ NOT a page)
  - **handle shape (the JSON the model sees):** v0 = the tool result VERBATIM
    (mirror; no model-visible handle object); v1 = RFC-0 §7 prose stubText
    derived mechanically (identify/recover/cost) — never rendered-rewritten
  - **tool_recall matching (Pichay):** equality on canonical (name, sorted-key
    JSON args); nondeterministic args ⇒ distinct logicalRef ⇒ honest
  - **recording matrix incl. the resident re-call case:** evicted ⇒
    `page.fault(tool_recall)` (fault-in, full@t+1); resident ⇒ same event
    shape but ledger-logged as `FaultOfResidentPage` violation, state
    untouched, divergence-free — the violation ledger IS the double-fetch
    metric (no new event kinds; standard stays pure)
  - **fresh-fetch honesty:** same tool+args + new contentHash ⇒ new page —
    never mis-measured as waste (hash-before-count)
  - **zero-config surface:** exactly 3 flags (mode, tokenizer; v1-inert
    budget/policy), no protocol extension
  - **risks:** gathering cost bounded (~µs/kTok, CPU); elimination is offline-
    evaluable policy, not format; PII stays hashing-local; non-MCP costs live
    in `call.meta`
  - **pseudocode:** 24-line `vmCall` wrapper (≤40 required) over
    trace/declare/render/fault; internal call-through names only
- Verified consistency checklist in the note (§8) against `02` fault taxonomy
  and RFC-0 §5/§7/§8 — every claim checks against lock-quality M0 semantics.

## Deviations from card

- The card's "handle shape (the JSON seen by model)" is answered in both
  modes: v0 verbatim (mirror — the third card 03 wording) and v1 stub-slot.
  The literal reading ("shim feeds the model a JSON handle") would violate
  `03`'s telemetry-first "no behavior change" and was documented as an explicit
  deviation, not silently adopted.

## Discoveries

1. **Resident re-calls are FREE metrics via the existing violation ledger**
   (T1c `FaultOfResidentPage`): no new vocabulary needed; the ledger row
   measures double-fetch waste with zero format changes. This is the third
   independent confirmation of the telemetry-first decision paying off.
2. **`isError` results must not mint pages** — error payloads aren't content
   economics; discovered while mapping MCP result shape.
3. **Same-tension parking again:** `page.touch` (RR-T3 note 3) would remove
   ledger noise for mirror-mode touches — now recorded in BOTH T3 and T6.
   Two independent cards want it; RFC-1 case is strong.
