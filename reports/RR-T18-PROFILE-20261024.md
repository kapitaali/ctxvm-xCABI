## 1. What this card added

### ctxvm-core (1 new module, 5 new unit tests; 15 → 20)

- **`profile::profile(trace)`** — pure forensic view of the decision ledger:
  - `pages` — per-page decision history **in first-declaration order** (reference,
    0-based `declaredAtEvent` stream index, eviction count, faults by taxonomy
    source, `modeAfterStream` (end state at `u64::MAX`), last stub text verbatim, pinned).
  - `faults` / `evictions` — row lists in stream order (`FaultRow`: turn, page,
    source, latency; `EvictRow`: turn, page, stub text).
  - `turnTallies` — derived `TurnTally` at each recorded `turn.render` fact turn.
  - `summary` — whole-trace aggregates: pages, resident/stubbed at end, declared
    tokens (the naive-stuffing window cost), evictions, faults, **faultless
    pages + their tokens** (the waste-candidate roster), distinct turns with rows.
  - `violations` — decision-ledger anomalies (telemetry-first, passthrough).
  Not here on purpose: fact checking (that is `replay`) and waste/touch metric
  semantics (that is `benchmarks/metrics/metrics.py`). The memo's
  "never-touched %" proxy stays in the simulator; the profile supplies the raw
  faultless/de-clared roster profiles it can be computed from.
- **`profile::turn_windows(spec)`** — `--turns` grammar: comma-separated single
  turns and inclusive ranges (`2-4,9` → 2,3,4,9); start>end / non-numeric rejected.
- **codec:** `FaultSource` gains `PartialOrd/Ord` (unit-variant order) — keyed maps
  over the taxonomy need an axis; no semantic change.

### `profile` CLI (`rust/crates/ctxvm-conformance/src/bin/profile.rs`)

```
profile <session.jsonl>                             # summary + pages + turnTallies + violations
profile <f> --event page.fault                      # + typed fault rows
profile <f> --event page.fault --source tool_recall # narrowed fault rows
profile <f> --event page.evict --turns 4-5          # + windowed eviction rows
profile <f> --event turn.render --turns 2-4,9       # + raw tagged events, windowed
profile <f> ... --output FILE                       # report JSON → FILE
profile --help                                      # exits 0
```

- `--event <type>` repeatable; roster = the RFC-0 vocabulary (9 types).
- `--source` requires `--event page.fault` and fails on mixed selections; accepts
  the snake_case taxonomy spellings (`tool_recall`, `identifier_scan`,
  `explicit_api`, `semantic`) and tolerates underscore-less inputs.
- summary/pages/violations stay **whole-trace** regardless of `--turns` (documented);
  `--turns` windows the row families (and raw events via their turn field;
  turn-less events pass unchanged).
- **Exit contract intentionally narrower than replay** (0 success / 2 usage-IO-parse;
  **no divergence exit**) — profile is an aggregation, not a fact gate; the help text
  routes fact questions to `replay`. Fixtures that replay-exit-1 (`session-divergent`,
  `events-v0`) profile **exit 0** — the two tools compose, they don't overlap.

## 3. Honest deviations / limitations

- **`turns_with_rows` counts decision/fact turns only** (evict/fault/turn.render);
  `page.render`-only turns are not keyed a tally — the map is literally "tallies at
  turn.render facts". The name is honest about that.
- **The summary is whole-trace even under `--turns`** — windowing is for row
  families. A windowed-summary mode can be added by the consumer's next pass; the
  help states the behavior.
- **The faultless roster ≠ "never read".** The waste proxy (identifiers in model
  output/tool calls) lives in `metrics.py`; profile exposes declared-token rosters
  that feed such computations. No cross-module coupling was added in this card.
- **`mode_after_stream` uses `u64::MAX`** — the scheduled end state. If a trace's
  last turn never reaches a fault's `t+1` turn, a pending rematerialization still
  counts as resident-at-end; this is the timing table's own semantics
  (`page.fault@t → full from t+1`), now made explicit.
