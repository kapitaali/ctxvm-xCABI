# RR-W8PILOT-20261107 — the pilot on T1: solved twice, and the pressure never happened

Card: W8 run executor, stage P3 (pilot, template 1, both arms, one round). Spend $0.0188.
Outcome: **gate (b) fails in substance** — the frozen tool set let a single content search
collapse the fixture, so neither arm approached the 24,000-token budget and the engine had
nothing to select. The grid did not start.

## The four pilot gates, as measured

| gate | requirement | result |
|---|---|---|
| a | Luna solves the task in ≥1 arm | **PASS** — `PASS T1: flags.json equals the frozen vector` in **both** arms |
| b | paged request smaller than naive (`turn.render.prefix.requestChars`) | **76,864 → 75,584 chars** (−1.7%) — formally smaller, substantively noise: the request is ≈19.2k tokens, below vBudget 24,000, so `_plan` returns early and no selection is applied |
| c | the checker fires on the produced artefact | **PASS** both arms |
| d | the protected floor is below vBudget | **PASS** — `systemPromptBytes` 12,374 (≈3,093 tokens) + 7 tool schemas, far under 24,000 |

## Why (b) cannot be read as a paging result

The fixture's minimum-read bound is 64,676 tokens. The runs declared **11,469** — one sixth of
it. The naive run's page list shows the mechanism:

```
tool:search_files({"limit":10,"path":".","pattern":"MANIFEST.tsv","target":"files"})
tool:read_file({"path":"rust/crates/ctxvm-conformance/src/bin/replay.rs.part01"})   × 7 files
tool:search_files({"file_glob":"*.part*","limit":1000,"output_mode":"content",
                   "pattern":"^pub (fn|s…"})                                       ← 1,356 tokens
tool:write_file({"content":"{\"binaries\": …"})
```

Seven targeted reads for the flag matrix, then one content search over every part for the
public surface. The minimum-read bound is a property of a *correct reading path*; it is not a
property of the model's path, and a search tool turns the latter into one page.

## A second structural defect found by the pilot

Each run made **5 API calls** and its trace carries **1 `turn.render`** and **1 `call.meta`**.
The render row is written once per user turn, with the request as it stood at the *start* of
the turn (19 messages, 76,864 chars). The requests that grow during the turn — the ones a
paging policy would act on — are not recorded. So `requestChars` compares the opening request
of each arm, not the peak, and the design's "watch `requestChars` fall toward the budget" has
no observable in this capture shape.

## What this does and does not prove

* Proves: Luna can solve T1 exactly (both arms, same artefact), the checkers fire, the
  captures verify (`coverage ok; replay exit 0, byte-identical`), and the spend model holds
  ($0.0095 and $0.0093 per run against a $0.10/$0.50 row).
* Does **not** prove: anything about paging. At 11.5k declared tokens against a 24k budget
  there was nothing to page; the −1.7% difference is run-to-run text variation, not selection.
* Also unresolved: T2 asks for per-file digests, which a `file`-only tool set cannot compute
  at all (no hashing tool), while adding `terminal` would let `sha256sum` bypass the reading
  entirely. That template needs the same treatment before any grid run.

## Decision this forces

The grid cannot start on this fixture set. Three ways forward, none of them a tuning decision
the executor may take alone:

1. **Re-freeze the tool surface** so content search cannot answer a task (a harness- or
   plugin-level tool filter; the CLI exposes only toolset granularity, and the `file` toolset
   ships `read_file`, `write_file`, `patch` and `search_files` together). Then re-run the pilot
   (≈ $0.02) and, if the declared tokens clear the budget, the grid.
2. **Reclassify**: accept that in this build every template is a floor control and report the
   experiment as "no reachable pressure", which is a publishable negative but tests nothing
   about paging.
3. **Narrow the claim**: keep the run as an accuracy-and-replay experiment (non-inferiority,
   hard-fault recall, byte-identical capture) and drop NTR.

## Addendum — the T1 rebuild, and the quota wall that stopped the re-pilot

T1 was rebuilt (P1 of the owner's amendment): the artefact gains a `lineShape` section — per
file `lines`, `maxLineBytes`, `overlong100`. A content search returns matching lines; it
cannot say how many lines a file has or which is longest without the whole file being read.
The expected vector was regenerated, the checker extended, and the pair verified: 0 on the
frozen vector, 1 on a perturbation.

The re-pilot did not complete. The provider answered with its daily free-tier cap:

```
429 org_token_rate_limit_day: Free core models share 1000000 input + output tokens per UTC
day ... Retry after 00:00 UTC.
provider=custom base_url=https://api.experientiallabs.ai/v1 model=gpt-6-luna
```

The runner was stopped before its 600-second retry, so no ledger row was written and spend
stays at $0.0188. The instrument fix from `RR-W8INST-20261107` also lands only after the next
gateway restart, because the plugin is imported once per process.
