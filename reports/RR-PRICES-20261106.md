# RR-PRICES-20261106 — the price catalogue, parsed without inventing anything

Card: the owner supplied a provider price catalogue as CSV in the repository root. This card moves it
to a stable location, builds `prices.json` v2 from it, and checks the arithmetic that decides whether
the W8 run fits the $25 cap.

## The parse law

The export has no header and no unit column. Each row is `index, "Vendor: Model", modality, current
price, list price, discount`. The builder records what each cell says and refuses to guess:

| Cell shape | Recorded as |
|---|---|
| `FREE` | input 0.0, output 0.0, `priceBasis: "free"` (an observed price, not a missing one) |
| `in $X/1M / out $Y/1M` | both sides, `priceBasis: "in-out"` |
| `$X/1M input` (embeddings) | input X, output null, `priceBasis: "input-only"` |
| `$X/1M` with no direction | input X, output null, `priceBasis: "single"` — the export states no side |
| `—` | both null, `priceBasis: "unknown"` |
| a name with no `Vendor: ` prefix | `vendor: null`, model kept — absence recorded, row not dropped |
| a repeated `Vendor: Model` | every row kept; the later one carries `duplicateOf` |

**No cache-read price exists in this export**, so `usdPer1mCachedRead` is `null` on every catalogue
entry. A W8 ledger that needs cache pricing must name its assumption; pricing cached reads at the input
rate is an upper bound, and it must be labelled as one.

Counts: 298 `in-out`, 35 `input-only`, 5 `free`, 4 `single`, 0 `unknown`; 8 repeated names, all
preserved.

## The W8 row

```
DeepSeek: DeepSeek V4.1 Flash 1017   in $0.15/1M · out $0.60/1M   (row-002)
```

That is the model the live traces already carry (`deepseek/deepseek-v4.1-flash-1017`), so the price row
for the run exists without further negotiation.

## What the cap actually buys

Design volumes: 6 tasks × R rounds × 2 arms, paged at 24k input per call, naive growing to ~100k:

| Rounds | Runs | Input | Output | Cost at $0.15 / $0.60 |
|---|---|---|---|---|
| R = 3 | 36 | 22.3 M | 0.5 M | **$3.65** |
| R = 6 | 72 | 44.6 M | 1.0 M | **$7.30** |
| R = 12 | 144 | 89.2 M | 2.0 M | **$14.60** |

The cap is $25, so the preregistered R = 3 uses about 15% of it and **R = 12 would still fit**. That
matters: more rounds tighten the non-inferiority interval, and the design's own stopping rule wants
≥30 pooled hard faults, which is easier to reach with more rounds than with more tasks.

Two caveats on the arithmetic, both stated rather than buried: the naive arm's per-call size is an
assumption (100k), not a measurement, and cached reads are unpriced in the export. Both push the
estimate up, so the figures are ceilings, not quotes.

## Verification

```
python3 benchmarks/metrics/build_prices.py --check   # OK — prices.json matches the catalogue
venvs/odps/bin/python -m pytest benchmarks/metrics   # 63 passed (was 54)
```

The builder is idempotent: a second run reproduces the same bytes, and the test suite proves it. The
first version appended its v2 note to the existing note on every build, which made `--check` fail
immediately after a successful build — caught by the checker itself.

## What this does not do

- It does not verify the prices against any provider page. They are the owner's export, recorded as
  `verified: "owner-supplied; not web-verified by this repository"`.
- It does not pin a model for W8. It makes the row available; the pin is an owner decision.
- It does not price cache reads, prompt-cache writes, or batch discounts. Nulls stay null.
