## 3. The standing guards (the "never again" mechanism)

`packages/hermes/test/test_generate_traces.py` (NEW, 4 tests):

1. **`test_live_shape_session_exercises_the_scan`** — end-to-end: the generator
   feeds all-string history through the adapter and asserts `identifier_scan`
   fires, with the exact frozen-echo fault composition `[id@0, tool_recall@0,
   id@1]` and 5 turns / 3 pages. A future parser regression of the exact B1
   class (strings unread → scan silent) turns the suite RED — the m4/m7 escape
   (fixtures green, field faults 0) is structurally closed. Note the design
   property: `tool_recall` faults are ref-table driven and cannot die with the
   text parser — so the test pins `identifier_scan ≥ 1` SPECIFICALLY. (It also
   demonstrates D6 live: this is a MULTI-user-turn session, i.e. the shape B1
   actually activates in — RR-W5 D6.)
2. **`test_all_history_messages_are_plain_strings`** — audits the returned
   history: every message is a dict with `role ∈ {user, assistant}` and a plain
   (non-empty) `str` content. A block-only regression at the GENERATOR fails
   here even if the plugin parser is fine.
3. **`test_frozen_fixtures_stay_byte_identical_to_m3`** — sha-verified byte
   parity `packages/hermes/fixtures ↔ corpus/m3` for both frozen fixtures, plus
   the RR-T17 counts (echo 20/3/3/5, thrash 26/5/5/5). Accidental regeneration
   of a corpus-drop source goes red immediately.
4. **`test_frozen_write_guard_refuses_silent_overwrites`** — `_write_fixture`
   raises on a frozen target without `force`, overwrites with `force`, writes
   fresh paths freely.
