# RR-H11-20261118 — `selectionMode: stable` implemented: the hold, its three triggers, and what it cannot fix

H11 of `design/w8-cache-stable-selection.md`, implemented in the engine and pinned by five laws. No cell was
run; H12 (one stable-vs-naive pair) stays behind the owner's $1 gate. Gate green at plugin **0.13.25**.

## 1. What was built

`CtxvmFaultPinEngine` gains `selection_mode` — `fresh` (the shipped behaviour) or `stable` — set by
constructor argument or `CTXVM_SELECTION_MODE`, plus `CTXVM_SELECTION_EVERY` for the B-th-call trigger
(default 4). In `stable` mode a selection is **held** and re-applied byte-for-byte until one of three triggers
fires:

| trigger | meaning |
|---|---|
| `new-page` | the request carries a page the held selection never saw, or a held drop's message is gone |
| `overflow` | the **outgoing** request is over budget |
| `every-B` | B calls since the last plan |

The plan payload gains `selectionMode`, `selectionHash` and `trigger`; `tools/coverage_check.py` types them
presence-gated, so a capture from a build without the mode still passes and a bad value is a violation.

## 2. Three decisions the design text did not settle, and the measurements that decided them

1. **`overflow` must mean the outgoing request, not the incoming one.** On the paged arm the incoming request
   is always above the floor, so the obvious `resident > budget` test fired on every call and stable mode never
   held anything. The first test written for this mode caught it against the incoming size; it now subtracts
   the tokens of the held drops.
2. **`new-page` is checked before `overflow`.** A ninth page both breaks the held set *and* pushes the outgoing
   size over budget; reporting `overflow` there names the symptom instead of the reason.
3. **The selection hash is taken over page identity, not message bytes.** The design asks for volatile markers
   (timestamps, session ids, cwd, counters) to be canonicalised before hashing; hashing `(dropped keys,
   repositioned keys)` is stronger and cheaper — no volatile marker can enter the hash at all — and it answers
   the question the provider's cache actually asks: *would this call send the same pages in the same order.*

## 3. The laws, and the proof they bite

Five tests (`StableSelectionTests`, `packages/hermes/test/test_context_engine.py`):

1. the mode is `fresh` unless asked;
2. two identical pressured calls → the second **holds**: `trigger: held`, identical `selectionHash`;
3. a new page → `trigger: new-page`, and the hash changes;
4. `CTXVM_SELECTION_EVERY=1` → `trigger: every-B` even when nothing changed;
5. `should_compress()` stays `False` — the engine selects, it never compacts.

**Red-before:** forcing every call to re-plan (`if True:` in place of the B-th-call test) fails exactly law 2
and nothing else; the file was restored byte-identical (`sha256` compared).

Suite: `python -m pytest packages/hermes -q` → **212 passed** (was 207, +5). Gate:
`ts suites green (24 + 62 + 46 + 14 tests); python suites green (212 + 8 + 66 tests)`, `ALL GATES GREEN`.
Installed copy synced to 0.13.25 (3 files, load check 0.13.25); **the gateway still holds 0.13.24**, so the
mode is not live until the owner restarts.

## 4. What this does not fix, said plainly

The design's own arithmetic (`design/w8-cache-stable-selection.md` §2) already says cache stability is
**necessary and not sufficient**: at 14 calls the break-even prefix is 57,250 tokens against a measured paged
prefix of 65,488, so a perfectly cached paged arm of that shape still loses. This card delivers the stability
half. The other half is a smaller per-call prefix, and that is a budget-and-shape question:

- at 24,000 the same cell would cost 42 % of naive — but the W8 closure measured that the protected floor
  alone exceeds 24,000 on real traffic, so the arm is inert there;
- at 60,000 the arm acts, and the prefix has to fall below 57,250 to have a chance.

So **H12 is a measurement, not a formality.** Its four acceptance conditions are unchanged
(`design/w8-cache-stable-selection.md` §4): artefacts parsed-equal, per-call prefix ≤ 24,000 at some point,
`prefixHash` unchanged between triggers, and cache-write below the naive arm's with cache-read above it. If
condition 2 fails the cell is a **no-op measurement** and must be recorded as one — the same rule that retired
the pilot.
