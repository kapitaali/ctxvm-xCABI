## 1. What was done

- **`@ctxvm/node` reference tracer** (`packages/node/src/tracer.ts`): NEW
  `noteUsage({ inputTokens, outputTokens, cachedInputTokens? })` API + `ProviderUsageInput`
  interface. Strict intake, all-or-nothing: integers ≥ 0, both required fields
  present (float law — floats are a determinism hazard, RFC-0 preamble extends to
  the v0.1 shape); a reported 0 for `cachedInputTokens` is a FACT and is emitted;
  an absent detail is an ABSENCE and is omitted. Invalid intake is omitted at the
  wire (never null, never coerced), matching R3's "omitted (never null) when the
  provider did not report". Usage attaches to the newest buffered turn snapshot;
  a fact handed in before any render is claimed by the next one (orphan slot,
  exactly once). Flush order follows the canonical rust-writer wire:
  `cacheEstimate`, `latencyMs?`, `providerUsage`.
- **ai-sdk lane wired** (`packages/ai-sdk/src/tap.ts`): the tap already owned the
  step boundary — it now relays each `finish-step` part's provider receipt
  (`usage.inputTokenDetails.cacheReadTokens` → `cachedInputTokens`; present in the
  canon fixture, zero counts included) into the tracer's turn snapshot. Pass-through
  law untouched (the app's part yields byte-unchanged; the witness line records
  every relay or every omission — never silent).
- **opencode + hermes lanes: source-audited, no source — per-lane omission is
  the RFC law.** Deterministic evidence: opencode's recorded driver fixture is 13
  hook events over terrain `session.context`/`tool.execute.before`/
  `tool.execute.after` (payload key union carries no usage field — audited
  programmatically this session); hermes's hook terrain is tool pairs +
  `pre_llm_call` history only. Neither port can see provider receipts, so
  neither emits `providerUsage` (the v0.1 schema keeps it optional; their
  kit-parity key signatures stay valid). `09-plugin-parity.md` §2 carries the
  note; the ports gain the wiring when their harness surfaces usage hooks.
- **Docs anchors:** `03-tracer-api-ts.md` (integrator sketch + the impl note) and

## 4. What the numbers now mean (W1-facing)

- `providerUsage` = the provider's own receipt per model call (input/output tokens
  + optional cache-read). W1's waste runs and the W3 price model can consume the
  facts directly.
- `cacheEstimate` is UNCHANGED: `estHitTokens`/`estMissTokens` remain the
  page-table's own estimate of prompt-cache carriage and
  `providerReported` stays `false`. That estimate flag is the v0 semantic
  "the est figures ARE provider-derived" (W6's OTel mapping keys
  `gen_ai.usage.cache_read` on it) — replacing est* with provider truth is a
  DECISION with W3/W6 consequences, not a wiring nicety (§6).

should `cacheEstimate.estHitTokens`/`estMissTokens` be set from the provider's

tracer's page-model disagrees with the provider receipt (as it does in the canon

to decide when the W8 capture design is written (the receipt-bearing capture is
the one that matters); the FAILURE LAW stays unchanged either way — `ts` opt-out
and the separate `providerUsage` fact keep every capture honest regardless.
