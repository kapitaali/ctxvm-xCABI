## 5. Why the witness cannot witness — two defects at source

The manifest is built at `~/.hermes/plugins/ctxvm-tracer/__init__.py:489-490`:

```python
"engine":  _state().get("engine_registered"),
"profile": os.path.basename(os.environ.get("HERMES_HOME", "")) or None,
```

- **`engine` is registration, not activation.** `engine_registered` is set when `build_engine()`
  returns an engine at plugin load (`__init__.py:1653-1665`), and that call is unconditional. The
  state is therefore `"ctxvm"` in every process that loads the plugin — both arms, every cell. It
  can never be `null` for the naive arm, so the check "null for naive" is unimplementable as coded.
  This is the same distinction `RR-W8FREEZE` recorded ("`engine=ctxvm registered` is not arm
  evidence because `build_engine()` is unconditional; the host activates it").
- **`profile` is the flushing process's home, not the turn's profile.** A multiplexer gateway serves
  `default`, `w8-naive` and `w8-paged` from `/home/theb/.hermes`, so `os.environ["HERMES_HOME"]` is
  `.hermes` for every served cell, whichever `-p` the client passed. `hermes gateway list` shows one
  PID behind all three profiles, and no gateway log line names this session's profile.

So the field added in `c947530` reports the observer's identity, not the observed arm. The run's
behaviour is consistent with the naive instruction (peak request 268,635 tokens against a 24,000
vBudget — no selection anywhere), but 268k is also what a paged cell looks like when the engine is
inert, so behaviour cannot separate the two either. It is not possible, from this capture, to say
which engine served the turn.
