# RR-20261031 — R4-ts card 1: per-event `ts` on the node lane (RFC-0.1 §R4 + D9)

**Card:** the `ts` half of RFC-0.1 **§R4** ("Every event gains an optional `ts`,
RFC 3339 UTC, millisecond precision") — the node-lane adoption of D9's policy
(default ON, per-trace opt-out `CTXVM_TRACE_TS=0`). Scope NARROW per the D8
per-lane law: opencode + ai-sdk inherit through `@ctxvm/node` (opencode imports
node by relative path; ai-sdk likewise) — that is ALL lanes in the TS mono-tree =
one card; the hermes python port (its own emitter) stamps in its own per-lane
card. The `page.declare` `latencyMs` half of R4 and R5's `turn` are later cards.
**Date:** 2026-10-31.

## 1. What was done

- **`@ctxvm/node`** (`packages/node/src/tracer.ts`): `tsEnabled` read once per
  `createTrace` (per-trace, exactly the D9 env law: `CTXVM_TRACE_TS !== "0"`);
  `stamp()` = `new Date().toISOString()` = RFC 3339 UTC ms = the v0.1 schema's
  `$defs/ts` pattern by construction.
  - **Front-stream events** (session.open, page.declare, page.render,
    page.fault, page.pin/unpin): stamped inside the single `push` choke point —
    the assignment lands the key LAST (the canonical v0.1 wire order the rust
    writer minted: `…, providerUsage, ts` — events-v0-1.jsonl line 1 reference).
  - **Tail facts** (`turn.render`, `call.meta`): these are derived in `finish()`
    from live state and bypass `push` — so the stamp is minted at the turn's
    `render()` snapshot time and cached (`turnStamps[t]`, `PendingMeta.ts`).
    Repeated `finish()` flushes therefore re-derive the SAME stamps → the
    T17.7 idempotency law (repeated flushes produce the same JSONL) holds
    UNDER DEFAULT-ON, proven by the unwrapped idempotency pin.
- **Byte-stability mechanism exercised where the law names it:** the three
  byte-compare pins (node determinism, opencode determinism, ai-sdk canon-fixture
  replay) run under `CTXVM_TRACE_TS=0` — D9's named mechanism for exactly this.
  The ai-sdk canon fixture `echo-thrash.trace.jsonl` is **UNTOUCHED** (no regen
  needed — under the opt-out the wired lane reproduces the committed bytes
  exactly, already carrying the v0.1 version + providerUsage from the previous
  cards; the fixture is the ts-less v0.1 golden).
- **The canon fixture stays the proof AND the opencode drop sources stay
  frozen:** `corpus/m1`–`m8` and every fixtured drop are pre-§R4 goldens, never
  regenerated. Fresh captures post-card stamp ts unless opted out; the
  `driver.ts` freeze-guard on `opencode-echo.jsonl` (m1 drop source) makes any
  future re-mint a deliberate act (unchanged this card).
- **opencode kit:** `CANONICAL_EVENT_KEYS` gains `ts` on all six event types
  (meta-parity table; the table's own drift message demands same-card §2 + mirror
  updates — the mirror note covers it).
- **Docs anchors:** `03-tracer-api-ts.md` (§Type/impl notes: the ts semantics

## 3. Semantics recorded (W3/W8-facing)

- `ts` = the tracer's own mint instant — front-stream events stamp at emit;
  `turn.render`/`call.meta` stamp at the turn's render() close (snapshot time),
  cached so flushes are idempotent. Nothing provider-derived is asserted by ts:
  it is wall-clock provenance, not latency (`call.meta.latencyMs` remains the
  measured model latency; R4's `page.declare latencyMs` half lands later).
- The opt-out is per-trace (read at `createTrace`): a capture either stamps
  every line or none — no half-stamped traces (the omissions law, RFC-0
  preamble "optional fields are omitted, never `null`", extends to §R4).
- Monotonicity: RFC 3339 UTC strings sort lexicographically in time order;
  the node pin asserts the whole stream's mints are time-monotonic (live and
  cached tail stamps mint in temporal order by construction).
