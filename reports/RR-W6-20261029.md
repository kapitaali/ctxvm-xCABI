## 2. Verification (commands + real output)

### 2.1 The mapping runs on all four harnesses

```
$ node tools/otel-export.mjs corpus/m1/session-thrashing.jsonl --conversation m1-thrash
   spans=13 gen_ai.attrs=29 violations=none
$ node tools/otel-export.mjs corpus/m6/opencode-pause-session-a.jsonl
   spans=14 gen_ai.attrs=31 violations=none
$ node tools/otel-export.mjs corpus/m7/hermes-pause-session-a.jsonl
   spans=17 gen_ai.attrs=37 violations=none
$ node tools/otel-export.mjs corpus/m8/live-thrash.jsonl
   spans=10 gen_ai.attrs=23 violations=none
```

`violations=none` checks the three OTLP/JSON rules the prototype could break:
no `startTimeUnixNano`/`endTimeUnixNano` (the clock gap, §3), `kind` always an
integer (OTLP JSON forbids enum name strings), every `intValue` a decimal string
(protobuf 64-bit rule). m1's whole paging story lands on the wire:
1 agent span + 10 turn spans + 2 tool spans, carrying 20 `ctxvm.page.render`,
4 `ctxvm.page.evict` and 3 `ctxvm.page.fault` events.

### 2.2 The three gaps are structural, and two are RFC-0.1 candidates

1. **xCABI has no clock.** `grep -o '"[a-zA-Z]*[Tt]ime[a-zA-Z]*"'
   spec/rfc-0/x-cabi.schema-v0.json` → no matches (the only temporal field is the
   optional `latencyMs`). OTel spans are defined by their timestamps, so the
   prototype emits time-less spans: structurally valid, but degenerate in most
   backends. Honest fix = a capture-time clock in RFC-0.1 (→ W7).
2. **Residency ≠ usage.** `turn.render.residentTokens` is the declared page table.
   Filling `gen_ai.usage.input_tokens` from it would reintroduce exactly the
   dishonesty W3 removed. The prototype leaves `gen_ai.usage.*` empty unless
   `providerReported` (never, in v0) and ships `ctxvm.resident_tokens`.
3. **`page.declare` carries no `turn`.** Tool spans therefore cannot be parented
   to the turn they happened in; the prototype parents them to the agent span and
   records `ctxvm.page.first_rendered_turn`. Second RFC-0.1 candidate.

### 2.3 Coexistence facts (each with a locator in the doc)

- Langfuse exports a span if it "has at least one `gen_ai.*` attribute" → ctxvm
  spans would be ingested with no SDK and no custom filter.
- Arize's own table: OpenInference is "Stable"; the GenAI conventions are "still
  in development; not on a stable release" and "subject to change at any time".
  Phoenix accepts `gen_ai.*` "but won't get the same UI treatment".
- Hermes already ships a Langfuse catalog plugin and the NeMo Relay integration —
  so on our most-developed harness an OTel view of the session **already exists
  upstream of us**. The pitch cannot be "we add observability"; it must be "we add
  the page table".

## 3. Deviations

- The prompt offered "prototype **or** document why not"; this card did both. The
  prototype is the cheapest possible existence proof (no deps, no network) and it
  is what makes the gaps concrete rather than rhetorical.
- The prototype is **not** registered in `tools/run-ci.sh`. Wiring it would freeze
  a mapping onto a `Development` spec and pre-empt D3; the RR recommends wiring
  only after D3 is answered.
- No `design/` or `tools/` file belonging to another card was modified.

## 4. Discoveries

1. **The OTel story is a projection, not a container.** Three structural losses
   (clock, usage, declare-turn) plus replay itself. The defender of the JSONL is
   not taste, it is the page table.
2. **The `gen_ai.*` ↔ OpenInference split is not cosmetic**: the most established
   OSS OTel AI backend treats `gen_ai.*` as second class. If D3 goes to a
   semconv layer, "which convention" is a second, independent choice — and Arize
   recommends OpenInference for new instrumentation today.
3. **A clock is now wanted by two cards** (W6's OTel projection and W7's RFC-0.1);
   the same field would also make `latencyMs`-based analysis unnecessary. Worth
   batching into one RFC-0.1 proposal.
4. **`page.declare`'s missing `turn`** is a small RFC-0.1 win with a visible
   consumer (any span-based view of the trace).
