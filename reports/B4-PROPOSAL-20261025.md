# B4 PROPOSAL — UC1-PLUGIN corpus m6 pause/resume pair (orchestrator-gated)

**Card:** UC1-PLUGIN (M), beat B4 — corpus offer
**Status:** PROPOSED — awaiting orchestrator execution
**Depends:** UC1-PLUGIN B3 resume (DONE, commit `8871dda`), opencode B3 mirror (DONE, other agent's lane)

## 1. What B4 requires

Per `design/uc1-plugin.md` §6 (B4 beat): propose the m6 drop shape = a real
pause/resume pair. The operator runs the beat; packaging rules follow the
corpus drop convention established by m1–m5.

**The beat:** capture a live Hermes session → pause it at turn N via
`/ctxvm-handoff <dir> [turn]` → resume from that snapshot with
`CTXVM_RESUME_FROM=<snapshot dir>` → capture session-b → verify session-b's
trace shares the prefix with session-a's snapshot (`diff` relation
`a_extends_b`/`identical` on the shared prefix).

## 2. Expected m6 drop shape

Following the m1–m5 pattern, `corpus/m6/` should contain:

| File | Purpose |
|------|---------|
| `hermes-pause-session-a.jsonl` | live Hermes session-a trace up to pause turn |
| `hermes-pause-session-a.meta.json` | sidecar (no resumeFrom — not resuming) |
| `hermes-resume-session-b.jsonl` | live Hermes session-b trace, resumed from snapshot |
| `hermes-resume-session-b.meta.json` | sidecar WITH `resumeFrom` stamped |
| `handoff/turn-N/` | the packaged pause snapshot (trace-N.jsonl.zst, page-table-N.json, manifest.yaml, llms.txt, checksums.sha256) |
| `provenance.json` | drop metadata (harness, plugin version, flush semantics, redaction) |
| `checksums.sha256` | integrity for all files above |
| `README.md` | human-readable drop description |

## 3. Operator steps

```bash
# 1. Start Hermes tracing
hermes   # interactive session
/ctxvm-trace start /tmp/ctxvm-m6/a
# ... perform tool calls ...
/ctxvm-handoff /tmp/ctxvm-m6/a 3   # pause at turn 3 → packages handoff/turn-3/
/ctxvm-trace stop

# 2. Resume from the snapshot
CTXVM_RESUME_FROM=/tmp/ctxvm-m6/a/handoff/turn-3 \
  hermes   # new session-b
/ctxvm-trace start /tmp/ctxvm-m6/b
# ... session-b continues from session-a's state ...
/ctxvm-trace stop

# 3. Package and verify
tools/snapshot-capture.sh /tmp/ctxvm-m6/a hermes-pause-session-a turn-3
tools/verify-capture.sh /tmp/ctxvm-m6/a/hermes-pause-session-a.jsonl
tools/verify-capture.sh /tmp/ctxvm-m6/b/hermes-resume-session-b.jsonl

# 4. Verify resume prefix
rust/target/release/diff /tmp/ctxvm-m6/a/hermes-pause-session-a.jsonl \
                          /tmp/ctxvm-m6/b/hermes-resume-session-b.jsonl
# expect: relation "a_extends_b" or "identical" on shared prefix

# 5. Package into corpus/m6/ and regenerate hub
```

## 4. Validation gates

Before promoting m6 to the corpus, the operator must confirm:

| Check | Command | Expected |
|-------|---------|----------|
| Schema | `python spec/rfc-0/validate_schema.py corpus/m6/*.jsonl` | PASS |
| Replay | `rust/target/release/replay corpus/m6/hermes-pause-session-a.jsonl` | exit 0 |
| Replay | `rust/target/release/replay corpus/m6/hermes-resume-session-b.jsonl` | exit 0 |
| Prefix | `rust/target/release/diff <pause> <resume>` | `a_extends_b` / `identical` |
| Sidecar | `resumeFrom` present in session-b's `.meta.json` | object, not null |
| Checksums | `sha256sum -c corpus/m6/checksums.sha256` | OK |
| Hub | `tools/build-hub.sh` then `hub.sha256` self-baseline | byte-identity |
| CI | `bash tools/run-ci.sh` | ALL GATES GREEN |
