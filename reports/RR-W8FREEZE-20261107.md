# RR-W8FREEZE-20261107 — P0–P2: the invocation contract, four frozen templates, and the runner

Card: W8 run executor, stages P0 (isolation), P1 (tasks and checkers), P2 (runner and ledger).
No paid call was made. Nothing was pushed.

## 1. P0 — the design's invocation premise is false on this Hermes build

The plan says "a run is one `hermes -z` process: it inherits the contract, writes its own
trace, exits; the gateway is not involved." Measured, that is not what happens:

* `hermes gateway status` → `✓ Gateway is running via the default-profile multiplexer`,
  PID 4970, and the `gateway.lock` of the default, `w8-naive` and `w8-paged` homes all point
  at that one PID.
* The `-z` process itself carries the contract: `/proc/18875/environ` held
  `HERMES_HOME=…/w8-naive CTXVM_TRACE_NAME=probe-name CTXVM_TRACE_DIR=/tmp/w8p0/probe`.
  Nothing was written there. Inside the same run, `env | grep ^CTXVM` returned empty, and
  `~/.hermes/profiles/w8-naive/logs/agent.log` records the turn as
  `gateway.run: inbound message: platform=local`.
* The build says so itself: `hermes_cli/cli_single_query.py:486` — "the turn's plugin tools
  run in the gateway, and this process loads no plugins (PLG-7)".
* Consequence: one process holds the plugin for every session. Its witness log flushed eight
  tracers in one line, among them this conversation and every smoke run, and its in-memory
  slash-command state named captures `w8-run` — a leftover of the 2026-11-06 attempt.

What does hold: the profile config is per run. `hermes -z` under `w8-naive` reports
`context.engine = compressor`, under `w8-paged` `= ctxvm`, and the session key is
`agent:w8-naive:local:dm:…`. The one-factor setting survives; only the capture plumbing is
global.

`engine=ctxvm registered` is NOT arm evidence: `build_engine()` returns an engine whenever the
host ABC imports, and the *host* activates it by config. That line appears in both arms.

**Owner ruling (A′):** the gateway carries one shared pool; each run's capture is located by
the session id the run reports and copied into its own directory. Per-task alternation is
kept. One gateway restart applies the pool. The restart also restarts this CLI session, which
is why the pilot has not run yet.

## Deviations

1. **Capture is gateway-hosted** (P0 above), with owner ruling A′. The plan's "no restart is
   owed" does not hold; one restart is owed before the pilot.
2. **T2's page count** is 67 against a 40–60 band.
3. **DQ scanning of expected artefacts** is extension-gated: `tools/dq-secret-scan.py` accepts
   only `*.jsonl`, `*.meta.json`, `*.provenance`, so each expected artefact is copied
   byte-for-byte under a `.meta.json` name for the scan. The verdict is content-based; the
   re-extension is stated in `benchmarks/w8/dq-expected.sh` and in this report.
4. **T5 and T6 are not built.** The second repository's own suite is green
   (`python -m pytest -q tests mcp_server_test.py` → `7 passed in 2.18s`) and it has no
   spec-stated rename spanning ~12 modules. Building either needs seeded defects — a synthetic
   fixture, which the plan's §3 rejects. This is a premise failure, reported rather than
   papered over.

## Discoveries

* `~/.bashrc` exports `CTXVM_TRACE_TS=0` and `CTXVM_FEATURES=trace,handoff`. A CI run from an
  interactive shell inherits them and `@ctxvm/node`'s "ts rides LAST" test fails — the gate is
  green only after `unset`ing every `CTXVM_*` (the law in the brief). Anyone re-running the
  gate from a terminal must clear them first.
* The umpire tree carries a vendored `runners/src` subtree whose pytest collection fails on a
  missing `filelock`; a bare `pytest -q` at the repo root errors during collection. Its own
  suite is `tests/` plus `mcp_server_test.py`.
* The provider's live `/v1/models` gives the wire id `gpt-6-luna` (context window 1,050,000,
  $0.10 / $0.50 / $0.01 per 1M), not the catalogue's display id `openai/gpt-6-luna`. The grid
  pins `gpt-6-luna` and the price lookup uses the catalogue name `GPT-6 Luna` (row-013).

## T0 decisions taken at the freeze (2026-11-07, before run 1)

1. **Four templates, R raised to 6.** T5/T6 stay unbuilt (premise failure above); the owner
   chose interval width over task count, so the grid is T1–T4 × 6 rounds × 2 arms = 48 runs,
   ≈ $3.30 at the pinned row. Recorded in `benchmarks/w8/grid.json` before the first run.
2. **The capture-pool switch is the owner's act, run from a shell outside the gateway.** The
   executor cannot perform it: the switch restarts the gateway process that hosts its own CLI
   session, so the tool layer refuses the call ("cannot restart or stop the gateway from
   inside the gateway process") — a guard that also fired while editing this paragraph. The
   owner sets the pool in the user manager's environment, restarts the service, and resumes
   the session; after the grid the same switch is run with the variables unset so that daily
   captures stop landing in the pool directory.
