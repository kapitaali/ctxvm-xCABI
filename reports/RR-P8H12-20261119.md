## 2. Q1 — ranked candidates, with the falsifier

The reviewer's ranking is re-tested against the new numbers, not re-argued.

1. **(c) head byte-identical, mutate only near the tail — still the top candidate, UNTESTED.** H12 did not exercise
   (c): its cut is mid-prefix, and that is exactly why the cache fell. A cut in the tail keeps a contiguous prefix,
   which is the only structural way to bound residency without invalidating a prefix cache. It is a **candidate, not
   a result** — no run exists. Falsifier adopted verbatim from P8: *a run where the common prefix stays maximal
   between triggers (byte-compared) and the dollar ratio is still worse than control kills that candidate.*
2. **(a) reselect only when the resident set changes — NOT SUFFICIENT on a read-once shape.** H11 implements this as
   `stable`'s trigger logic. H12 shows why it failed here: every prompt adds a page, so `new-page`/`overflow` fires
   on every call and the hold never happens (zero same-size pairs). It needs a repeated working set, which this
   workload has none of. Not falsified as a mechanism; not demonstrated either.
3. **(b) select once and hold the set — SAME FAILURE, measured.** This was the H12 cell. Condition 3 of the design
   (hash unchanged on calls *between* triggers) cannot pass because there are no such calls. Holding a selection
   also holds a hole: with a mid-prefix cut, reuse truncates at the hole. No variant of "hold the choice" recovers
   the cache while the cut is mid-prefix.
4. **(d) abandon selection on a cache-billed provider — default until (c) is tested, with no dollar claim.** On
   this pair the paged arm's harness cache share fell 91.8 % → 56.6 % and uncached input rose 1.90×. That is a token
   shape, not a receipt; free tier. Nothing here measures dollars, so (d)'s economics stay UNMEASURED, not proved.
