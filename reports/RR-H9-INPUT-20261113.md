## 2. The `reason` is already computed where H9 wants it ✓ — and H9 is cheap ✓

`packages/hermes/live/context_engine.py:_plan` ✓ (`:735-769` ✓) computes, in order ✓:

```
floor_tokens = sum(_tokens_for(messages[i]) for i in keep_hard)      # :743  <- the floor, already computed
if floor_tokens >= self._v_budget:  return set(), set()             # :744-745  <- the floor_bust case
... walk the newest-first pages, drop the rest that do not fit ...   # :757-769  <- evicted / fits
```

⇒ ⇒ the **three reasons H9 names are exactly the three exits of `_plan`** ✓ ⇒ ⇒ the reason is **one line at
each exit** ✓ ⇒ and `floorTokens` is **already in hand** ✓ ⇒ ⇒ **H9 is a few lines in the engine plus a
block in the sidecar** ✓ ⇒ ⇒ consistent with the roadmap's own "small to build" ✓ ✓.

⇒ **But the observer's guard must change** ✓: the callback fires only for selections that dropped or
repositioned ✓ (`context_engine.py:553` ✓) ⇒ ⇒ a `reason` of **`fits`** would never be reported ✓ ⇒ ⇒ H9's
reason must be emitted for **every** selection ✓ ⇒ ⇒ the same "every call" requirement the P12 ruling made ✓
✓ ⇒ ⇒ **the guard is the one thing H9 must not forget** ✓ ✓.

⇒ And the **sidecar is the right home** ✓ (H9's own instinct ✓ ✓): the engine's `_decision.log` ✓ and
`_selections.log` ✓ are **shared, append-only text files** ✓ — the review lane has measured their pollution
(the plugin's own pytest suite writes into them ✓) and their **rotation** ✓ ⇒ ⇒ a machine-readable,
per-session, per-call record belongs in the sidecar ✓ ⇒ ⇒ H9's placement is right ✓ ✓.

## 3. The enum is **incomplete** ✓ — the engine has a fourth outcome ✓

`_plan` returns **two** sets ✓: `(dropped, repositioned)` ✓ ⇒ ⇒ a selection can **reposition pins without
dropping anything** ✓ ⇒ ⇒ {`fits`, `floor_bust`, `evicted`} cannot express it ✓ ⇒ ⇒ either a fourth case ✓
or a separate `repositioned` count ✓ ⇒ ⇒ the live instrument already records the third quantity ✓ (the
observer payload carries `repositioned` ✓) ⇒ ⇒ ⇒ the enum should be derived from what the engine actually
reports ✓ ⇒ ⇒ ⇒ **either** `reason ∈ {fits, floor_bust, evicted, repositioned}` ✓ **or**
`reason ∈ {fits, floor_bust, evicted}` **plus** `repositionedPages` ✓ ⇒ ⇒ ⇒ recorded ✓ (the P12 card made
the same point about the sidecar's per-call record being **partial** ✓ ✓).

## 4. The floor is **per call**, not a constant ✓ — and H10 needs the **turn** too ✓

Measured on the 0.13.21 capture ✓ (the run window of `_selections.log` ✓, 41 selections ✓, budget 60,000 ✓):
the smallest `before` in the window is **6,009** ✓ ⇒ ⇒ the floor is **≤ 6,009** tokens at turn 0 ✓ ⇒ ⇒ and
the floor **grows** with the last-six keep window ✓ ⇒ ⇒ ⇒ it is **not** a constant ✓ ⇒ ⇒ H9's `floorTokens`
must be **per call** ✓ ⇒ ⇒ ⇒ H10's *"the measured floor **and the turn spread** that produced it"* ✓ ⇒ ⇒ ⇒
⇒ ⇒ ⇒ ⇒ ⇒ ⇒ ⇒ the per-call plan must carry the **turn** ✓ ⇒ ⇒ the sidecar's per-call entry has the call
index `i` ✓ but **no turn** ✓ ⇒ ⇒ ⇒ ⇒ the turn is joinable from `perApiRequest` ✓ ⇒ ⇒ ⇒ ⇒ ⇒ ⇒ ⇒ ⇒ ⇒.

⇒ ⇒ **The floor is not derivable from today's sidecar** ✓ ⇒ ⇒ a *bounded estimate* is all the artefacts give
✓ ⇒ ⇒ H10's answer therefore **needs H9's number** ✓ ⇒ ⇒ ⇒ the roadmap's ordering (*"Once H9 lands…"* ✓) is
right ✓ ✓ ⇒ ⇒ ⇒ **and H9 and H10 are one change** ✓ (the same code path emits both ✓ ⇒ ⇒ the report line is
a read of the sidecar ✓ ✓) ⇒ ⇒ ⇒ landing them together is cheaper ✓ ✓.

## 5. `prefixHash` — the canonical form is the **owner's**, not the adapter's ✓

`prefixHash` hashes the request's prefix ⇒ ⇒ the hash's input must be **canonical** ✓ ⇒ ⇒ and that
canonical form was **already ruled on** ✓: packet **P11** ✓ ⇒ *"(c) owner, (a) pointer; **test FIRST**
(equal model/page table/report, **never bytes**), and the note states the fact it enforces; note =
compatibility statement only"* ✓ ⇒ ⇒ ⇒ H9 must **not** invent a canonicalisation inside the adapter ✓ ⇒ ⇒
it should follow the pointer ✓ ⇒ ⇒ ⇒ and the note lands as an **RFC-0.1 compatibility line** ✓ (D-numbered ✓
✓) ⇒ ⇒ ⇒ H9's hash is therefore **blocked on the owner's canonical form** ✓ ⇒ ⇒ ⇒ or H9 emits the hash over
a byte sequence the owner names ✓ ⇒ ⇒ ⇒ recorded ✓.

⇒ ⇒ **And the prefix hash is what closes the loop with the cache line** ✓: the W8D measurements ✓ (the paid
pair's **4.49× cache-write volume** ✓ and the paged arm's cached prefix **collapsing to the static
14,504 tokens** ✓) are the *provider's* view of a prefix change ✓ ⇒ ⇒ a per-call `prefixHash` ✓ would make
the engine's own view of the same event ✓ — the missing half of that pair ✓ ⇒ ⇒ ⇒ H9's `prefixHash` is worth
more than the roadmap's one line suggests ✓ ⇒ ⇒ ⇒ **the owner may want to prioritise it** ✓ ✓.
