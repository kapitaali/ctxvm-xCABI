## 1. Provider receipts (W8 D12, owner option A)

`packages/hermes/src/plugin.py`:

- `provider_usage_of(summary)` is a strict intake. It requires whole-number, non-negative
  `prompt_tokens`, `cache_read_tokens`, `cache_write_tokens` and `output_tokens`; anything else is an
  **absence** (returns `None`), never a zero.
- `inputTokens` on the wire is the **uncached** input: `prompt − cache_read − cache_write`, clamped at
  zero. Deriving it from the host's own keys keeps the provider's wire shape from leaking through the
  field's meaning.
- `note_usage` writes last-write-wins onto the newest pending meta; a receipt observed while no meta
  exists is held and attaches to the next created meta (the node `orphanUsage` law).
- Wire order is the Rust writer's: `latencyMs`, `providerUsage`, `ts`.
- `cacheEstimate.providerReported` stays **false**.

**Deviation from the frozen preregistration, recorded as an erratum.** `design/w8-capture-design.md` §6
and `RR-W8PREREG` §1 (D12 fork) both say the plugin "turns `providerReported` TRUE for the W8 captures".
The owner ruled option A on 2026-11-06: the estimate keeps page-table semantics and the receipt is a
separate fact. The frozen files are not edited; this report is the erratum, and the deviation is
analysis-neutral for the gate, which reads `cacheEstimate` by formula. What a reader loses: a trace from
this lane still says "estimated", even though a provider receipt rides beside it.

## 2. The paged arm's engine

`packages/hermes/live/context_engine.py` (686 lines) implements the preregistered `FaultPinPolicy`:
selection under `vBudget`, never compaction (`should_compress()` is always false,
`prune_tool_results_only()` is the preregistered no-op so the two seams cannot double-apply). The module
states seven laws — ordering with a frozen pin block, purity of selection given `(page-table, vBudget)`,
second-demand pinning, budget floor, and the rest — and `context_engine` exports its configuration
(`vBudget`, `vBudgetSource`, `vBudgetRefusedLower`) so a capture can be audited.

`vBudget` defaults to the preregistered 24,000. `CTXVM_VBUDGET` may confirm or raise it; a lower value is
**refused and flagged**, which is the one direction a preregistered budget cannot move after the fact.

Wiring is fail-open by design: `register()` builds the engine and registers it only when the host exposes
`register_context_engine`, and any failure is swallowed so the tracing hooks keep working. Outside the
Hermes runtime (`build_engine()` returns `None`), nothing registers and the suite still passes.

## 3. The redaction DQ gate

`tools/dq-secret-scan.py` (183 lines) is the pre-drop blocking scan from
`design/w8-capture-design.md` §10: credential-key patterns, `.env`-style assignments, e-mails, absolute
`/home/` paths, IPv4 literals and internal hostnames over every `.jsonl`, `.meta.json` and `.provenance`
in a declared drop set. Exit 0 = zero matches, 1 = cannot ship, 2 = scope error. It prints positions and
pattern names, **never matched bytes**, so the scan cannot become the leak.

## What is not proven

- **No live receipt yet.** The installed plugin copy is 0.9.0; 0.10.0 needs an install sync and a gateway
  restart before a real turn can show a `providerUsage` row. Everything above is test-level plus the
  wire contract.
- **The engine is inactive by default.** It registers only under a profile carrying
  `context.engine: "ctxvm"`; the naive arm runs the default profile. No capture has run against it.
- **No measurement.** Whether paging helps is the W8 run, which needs the owner's model/price row and the
  D5 cap. This card makes the run possible; it does not answer it.
- **The DQ scan is not in the CI gate.** It is a run-book gate on a drop set, and the corpus is frozen;
  adding it to CI would scan bytes that cannot change.
