# RR-DRIFT-20261109 — the gate stopped printing numbers it did not measure

Card: two drift classes closed in the gate, one guard added. No product code touched.

## 1. The count line was a literal

`tools/run-ci.sh` printed

```
ts suites green (22 + 62 + 46 tests); python suites green (182 + 66 + 8 tests)
```

from a hardcoded string. Two drifts had accumulated in it:

- **Stale:** it said 177 while pytest ran 182, after five budget tests were added the same day. The
  gate stayed green, so the number would have stayed wrong indefinitely.
- **Mislabeled:** the real counts are `packages/hermes` 182, `packages/py` **8**, `benchmarks/metrics`
  **66**. The literal printed `66 + 8` — the totals matched, so nobody noticed, but the line had the
  last two suites in the wrong order for as long as it existed.

Fixed by deriving every count from the step's own output. `run_counted` keeps the log and appends
`count<TAB>kind<TAB>name`; the summary reads that file:

```
[ctxvm-ci] ts suites green (22 + 62 + 46 tests); python suites green (182 + 8 + 66 tests)
```

The node parser is `grep -oE 'pass [0-9]+'` because node 26 prints `ℹ pass 22`, not the TAP
`# pass 22`. That detail cost one red-then-zero cycle; it is recorded here so the next edit does not
re-guess it.

## 2. Two version strings, no check

`PLUGIN_VERSION` in `packages/hermes/live/__init__.py` and `version:` in
`packages/hermes/live/plugin.yaml` are both hand-edited, and nothing compared them. One bump without
the other ships marketplace metadata that names a version the code is not.

Guard added to both the local gate and `ci.yml`, in the same position:

```
ver=$(sed -n 's/^version: *//p' packages/hermes/live/plugin.yaml)
grep -q "PLUGIN_VERSION = \"$ver\"" packages/hermes/live/__init__.py
```

Red-before verified (`ver=9.9.9` → exit 1); green on the current pair (0.10.11 both).

## 3. Verification

```
bash tools/run-ci.sh          GATE=0, ALL GATES GREEN, derived counts 22+62+46 / 182+8+66
python3 tools/ci-rehearsal.py rehearsal OK — 4 job(s), every run step green in a pristine clone
wrong-version guard           exit 1 (the guard can fail)
```

## 4. Still open, not fixed here

- `docs/quickstart.md` remains a top-level directory that `AGENTS.md` §3 does not list; that is an
  owner layout decision, not a drift to be patched silently.
- The runbook's expected-plugin-version line is prose. Rather than pin a number that goes stale, it
  now says "record both the disk version and the serving version" — a doc cannot be made to fail,
  so it should not carry a value that changes weekly.
