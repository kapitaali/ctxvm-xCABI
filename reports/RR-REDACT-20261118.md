# RR-REDACT-20261118 — implementation card for G4 (sidecar assertion record, declaration-only)

Status: **implementation card, not done.** Owner GO 2026-11-18 (`RR-G4GO-20261118`) authorizes this narrow first
implementation; G4's Done condition is a passing `RR-REDACT*` card **with a green kit + CI gate**, which this draft
does not yet have. No code has been written. Lane routing is stated below; the review lane records, it does not
implement under another lane's ownership.

## 1. Scope — exactly what GO authorized

- A **sidecar assertion record**, placed with a drop's existing `provenance.json` / `checksums.sha256` pair.
- A **stage LIST** per `design/redaction-block.md` §4.1: entries for `capture`, `flush`, `export`, each carrying
  `policyId`, `ruleSetVersion`, `stage`, `replacedFieldCount`. One artifact may be redacted more than once; the
  list is not a single flag.
- An **explicit consumer rule**: absence of the record means **UNKNOWN**, never "none". A consumer must say
  "redaction unknown" when the block is absent; the v0-era corpus predates any block.
- A **declaration-only enum** for how `logicalRef` is treated — `raw`, `keyed-hashed`, `dropped` — with `raw` as
  the shipped declared value. A declaration is a claim about treatment, not an emitter.

## 2. Explicitly refused — not in this card

- No **keyed-hash emitter**. `keyed-hashed` and `dropped` are enum vocabulary only; no code hashes a ref, and no
  fixture is regenerated. The earlier golden-vector precondition for an emitting card remains untouched.
- No **wire field**: no RFC-0.1 additive field, no five-touchpoint card, no v0.2 design note. `spec/rfc-0/` stays
  byte-sealed. The record is sidecar-only.
- No **verifier claim**: the block is an assertion by its writer. No tamper-evident chain, no seeded-canary test,
  no "verified"/"redacted" wording. The existing scanner remains a pre-drop **lint**: "the `w8-dq-v1` pattern list
  found zero matches", nothing stronger (`tools/dq-secret-scan.py` stamp; `RR-FIELDAUD-20261107`).
- No **release authorization**: D17 remains held until the owner judges there is enough data. No package bump,
  tag, registry action, catalog submission, or push.
- Not decided by the GO: `stubText`/`reason` bounded-vocabulary or pre-drop validation, and the separate
  consent/release plugin card (first-run notice minimum). Both stay owner-routed.

## 3. Where implementation would land — lane routing

`handoff/LANES.md`: `tools/**` is **hermes-lane-owned**, `research/**` is research-owned, `corpus/**` is
frozen for everyone (law 5: `checksums.sha256` pins trace bytes). The review lane owns `handoff/**`,
`reports/RR-DAY-*`, and the day indexes; it can write this card and the LOG row, but **not** the tool change.
Implementation therefore needs an owner-directed assignment to the hermes lane (or explicit owner clearance for a
cross-lane edit). Until that routing exists, this card stays a draft and G4 stays open.

A plausible hermes-lane implementation surface, to confirm with that lane before it starts:
1. Extend `tools/dq-secret-scan.py` (or a sibling tool it calls) to emit a **machine-readable stage-list record**
   from the drop's declared stages, using the four fields above. Keep the zero-match verdict and `w8-dq-v1`
   stamp unchanged; do not call the record a verifier.
2. Add a **sidecar writer** that writes `<drop>/redaction.json` (or the name the implementation card ratifies)
   beside `provenance.json` for **new drops only** — never retroactively into m1–m8, whose checksums are pinned.
   The tool must refuse to write into a frozen drop.
3. Add a **consumer rule** in the shared verifier path: absence of the sidecar → "unknown"; presence → print the
   declaration (stage entries + `logicalRef` enum value) without claiming verification. Extend
   `tools/verify-capture.sh` only if that is the agreed consumer surface.
4. Record negative/edge cases: a drop with two redaction stages; a drop with no block; a drop whose block declares
   `keyed-hashed` or `dropped` while traces still carry raw refs (declaration vs bytes — must be honest, not a
   claimed emitter).

- A DQ scan on a **fresh, non-frozen** fixture directory: exit 0 with the unchanged lint wording; sidecar written

- A refusal test: writing the sidecar into `corpus/m1` (frozen) fails without changing any committed byte.
- `bash tools/run-ci.sh` unpiped with ambient `CTXVM_*` cleared → rc=0 ALL GATES GREEN;
  `bash tools/check-handoff.sh` → ALL PASS; `bash tools/git-hygiene.sh` → OK.

  another lane's WIP (the tree currently carries modified `design/W8-EXECUTOR-PROMPT.md`,
  `reports/RR-W8B-20261110.md`, `tools/w8-run-env.sh`, the deletion of `research/white-paper-Part-II.md`, and
  untracked `design/*` and `research/*`).
- Privacy: no trace bytes, credentials, or unredacted session text in any report or committed file (law 9).

## 5. What this draft does and does not do

It records the G4 scope and the verification bar. It is **not** the implementation; it changes no tool, no wire
byte, no corpus drop, and no gate input. No model call, no spend, no push. G4 is marked done only when a
hermes-lane implementation card reports the green kit + CI gate above, or when the owner rules it further-deferred
in writing.
