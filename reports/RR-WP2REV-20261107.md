## What Part II is

"Part II asks what that record is worth for the three questions" (dangerous-capability evaluation,
seeing what a model is doing, making models do what we want). Its central claim, stated in the narrow
form: *a context trace lets a reader reconstruct and replay the exact request the harness sent* —
necessary for every downstream safety claim, sufficient for none. It carries an evidence-level scheme
(read-in-full / abstract / snippet / secondary — UNVERIFIED), a 19-row research agenda with statuses,
five preregistered-shape experimental designs, an honest §13.3 open-verification table (items it
explicitly refuses to assert until a locator exists), and states plainly "This paper runs no experiment."

## The one claim I verified against the source, and why it needs conditioning

§2.2: "The renderer is a pure function of the events. The same trace gives the same bytes." I grep-verified
`rust/crates/ctxvm-codec/src/model.rs`: no `Event` variant carries message-content bytes — pages travel
as `(logical_ref, content_hash)` identity (PageId, model.rs 14–21), and the v0 vocabulary's `page desc`
in `02-xcabi-events-v0.md` holds kind/tokens, not content. Synthetic corpus rows average ~133 bytes/event —
identity-level, not payload-level.

Therefore the byte-identical guarantee is proven for the **render geometry** (page table, resident/stub
composition, stub text, token math — also turn.render totals), not for the full message bytes, which are
reconstructable only where the sources the hashes point to live. This is a wording problem with a tail:
§6.3 defines monitor views as "a pure function of a trace — rendered pages only; resident pages plus
stubs," and agenda rows 2–5 (hint injection, view-parameterised monitors, ablation ground truth) run
monitors that need *content*. Suggested resolutions for the next revision of this draft — either name a
content-bearing capture channel (which then belongs in the §9 redaction story), or define views as
trace ⊗ sources joins whose version names its join inputs. Not a spec change proposal from this card:
`spec/**` is frozen law.

1. §9.4 "No verifier exists" — one exists, partially, as of this week: `tools/dq-secret-scan.py` stamps
   its own identity (SHA-256 of the scanner + scan-list version + UTC date) into `provenance.json`,
   runs pre-drop with exit 0/1/2, and never prints matched bytes (the never-print law was verified by
   double-run this week: the only between-run byte difference is the deliberate `scanDate` stamp). It is
   narrower than §9.4's verifier (no stage-list comparator, no third-party standard, personal-data classes
   limited to email/path/IPv4/hostnames) — but the flat negative will read as stale against the artifact.
   Next draft should say what exists and what part of the requirement it does not answer.
2. §9.3 "This paper does not contain that audit" — the field-conduct audit (which field holds user-derived
   content raw / hashed / counted) is derivable today from `model.rs` + the five-touchpoint allowlist law
   + the live corpus rows. That audit is a separate card from this lane (`RR-FIELDAUD-20261107`) rather
   than an edit here.
3. §5.2's proposed instruments are shipped: the live capture row on this box carries
   `prefix={source: measured, toolSchemas, requestChars, approxInputTokens}` per turn, beside
   `environmentId` (RR-HERMESENV derived `env-2b4652ae9d98` for this repo) — the static prefix and the
   environment key exist per turn on the current build.
4. §11's blocker rows 14/15 ("Blocked: pager inert at 24k") are now *present tense* with better evidence
   than the draft knew: the W8 pilot (`RR-W8PILOT-20261107`) ran T1 both arms at $0.0188 and gate b failed
   in *substance* — requestChars only −1.7% and ≈19.2k tokens under the 24k budget, because
   `search_files` with `output_mode:content` returned the whole public surface in one ~1,356-token page.
   The draft's own conditional — "The task set or the budget must change first ... logged as a deviation
   from preregistration before any paged run" — is satisfied as to logging (deviations are recorded), but
   today's finding is sharper than either half of that conditional: **pressure is a property of a correct
   reading path, not of the model's path**, so task-set size alone can't bind it; what binds is the per-
   task frozen tool set (§2.4 of the run plan), and the instrument that can *see* the request growth now
   exists (the `perApiRequest` series, `RR-W8INST-20261107`). Part II's §12.3 substitution clause ("a
   simple eviction policy that does act replaces it, and the substitution is recorded") remains
   owner-gated as a policy change and should not be improvised mid-run — the paper is welcome to cite the
   pilot as the dated measurement when it publishes.
5. §7.5's dual-use check (SHADE-Arena public split) is exactly the "capability-uplift" companion W8's
   arm pairs can feed once a decent paging policy exists; noted so the two lanes converge rather than
   build two grids.

## Verification note — a red gate, and what it proved (2026-11-07)

The first gate run of this card FAILED (`GATE_EXIT=1`, node tracer tests at
`packages/node/test/tracer.test.ts`: "ts must ride LAST on session.open", last key was `schemaVersion`,
and ts absent from `call.meta` with `providerUsage` present). Cause found before any code was touched:
this card's session is hosted by the same user-manager tree the W8 lane `set-environment`'d, and the
omission of the law's own pre-amble — `unset` every `CTXVM_*` before local runs — let the shell's
inherited contract leak into the gate's spawned processes. The offending value is
`CTXVM_TRACE_TS=0`, the **D9 per-trace opt-out** (`packages/node/src/tracer.ts:284`,
`packages/ai-sdk/src/flush.ts:125`, `packages/hermes/src/plugin.py:220`): ts is default-ON, and the
everyday environment on this machine carries it explicitly off for byte-stable captures. The clean-env
re-run (`grep -c ^CTXVM` = 0 first) is green: rust; ts `22 + 62 + 46` (node grew 21→22 with the run
lane's chain); python `173 + 66 + 8` (hermes 171→173); schema 682 checks; export round-trip; hub
identity; exit 0.

Two operational facts this episode hands the W8 lane, worth more than the green:

1. `systemctl --user set-environment` for the W8 contract sidewalls or *replaces* keys rather than
   appends its own: the manager now shows the W8 set (`CTXVM_MODEL=gpt-6-luna`,
   `CTXVM_TRACE_DIR=/tmp/w8/traces`, `CTXVM_TRACE_NAME=w8`, `CTXVM_FEATURES=trace`,
   writethrough 1/10) with the everyday set GONE (no `handoff` feature, no provider, no trace-ts
   override). The everyday values, for the post-grid restore, are recorded from the pre-W8 process
   snapshot this session still carries: `CTXVM_MODEL=deepseek/deepseek-v4.1-flash-1017`,
   `CTXVM_PROVIDER=nous`, `CTXVM_TRACE_DIR=$HOME/.local/state/ctxvm/traces`,
   `CTXVM_TRACE_NAME=ctxvm-dev`, `CTXVM_FEATURES=trace,handoff`, `CTXVM_TRACE_TS=0`,
   `CTXVM_AGENT_ID=hermes`, `CTXVM_BUDGET_TOKENS=200000` (hermes version tag aside). Restore must
   **re-set** these, not merely unset — the store was overwritten, and unset alone leaves the everyday
   capture unnamed and model-stamped wrong.
2. The ts opt-out is read at different times per adapter (`flush.ts` re-reads at flush; `plugin.py`
   reads once), so if the W8 contract later needs byte-stable fixtures, the choice must be made in the
   contract explicitly — silence means default-ON differs per adapter process.

Nothing in `packages/**` or `benchmarks/w8/**` was touched to red or prove this; the finding is evidence
from an environment the law already distrusts.
