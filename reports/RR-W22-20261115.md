## What was done

1. Scaffolded `packages/deepseek/` (bundle `cordis.patch.yml` inserting row `ctxvm-tracer`; `src/{index,config,tracer,event-map,page-table,types}.ts`; `test/`; locale; icon). Config schema via schemastery (`z`), per installed DSH docs — the W22 plan's "zod" is shorthand.
2. Fixed two real API drifts against `@ctxvm/node` v0.1.0, found by a failed live activation:
   - `finish()` returns `{ jsonl, events, stats }`, not `{ lines }` → `flushTracer` now writes `finished.jsonl` (writeFileSync, 0600, dir 0700).
   - `onApiRequest` takes `{ tool_count?, message_count?, request_char_count?, approx_input_tokens?, system_prompt? }`; provider/model belong in `createTrace(init)` → tracer is now created lazily on the first session event, using the leading `request/header` EpochHeader for `session.open`.
   - `resolveTraceDir` expands `${VAR:-default}` before `~` (default `${XDG_STATE_HOME:-~/.local/state}/ctxvm/traces`, law 9).
3. Installed into dsh profile `nvidia` via plugin-manager `install_bundle` (absolute path → `link:` dep, bundle selected). Activation initially failed on `@ctxvm/node` resolution (pnpm linked only the bundle; Node resolves from the plugin realpath) — fixed with `packages/deepseek/node_modules/@ctxvm/node → ../../../node` (repo-relative; `node_modules/` is gitignored, so the link is a local convenience, not a tracked byte) after building `packages/node/dist`.
4. Live capture: `dsh --profile nvidia headless "…"` printed `[ctxvm]` lines (session/created, session/event mapping, flush on exit) and wrote a trace. Note: the GUI web host booted before the install; a newly installed bundle needs a host restart — headless processes boot fresh and are the reliable test path.
