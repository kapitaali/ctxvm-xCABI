## 2. What was done

### 2.1 Feature registry — `packages/hermes/src/uc_registry.py` (NEW)
Shared UC module base + feature parsing:

- `FEATURE_*` constants: `trace`, `uc1-handoff`, `uc2-forensics`, `uc3-planner`
- `parse_features(raw) -> set[str]` — parses `CTXVM_FEATURES` (comma-separated,
  case-insensitive, deduped, unknown names ignored for forward compatibility);
  defaults to `{trace}` when unset/empty
- `is_enabled(features, feature) -> bool`
- `UCModule` base class — no-op hook handlers (`on_session_start`,
  `on_pre_tool_call`, `on_post_tool_call`, `on_pre_llm_call`,
  `on_session_end`, `flush`); `feature` attribute gates enablement (`None` =>
  always-on, used by the trace UC)

### 2.2 UC stub submodules — all NEW, all no-op stubs
- `packages/hermes/src/uc1_handoff.py` — `UC1Handoff` (feature `uc1-handoff`)
- `packages/hermes/src/uc2_forensics.py` — `UC2Forensics` (feature `uc2-forensics`)
- `packages/hermes/src/uc3_planner.py` — `UC3Planner` (feature `uc3-planner`)

Each extends `UCModule`, sets `name`/`feature`, overrides nothing (no-op
until UC1 pause/resume, UC2 forensics, UC3 planning logic lands).

### 2.3 Thin `live/` dispatcher — `packages/hermes/live/__init__.py` (MODIFIED)
`register(ctx)` now:
- Parses `CTXVM_FEATURES` into the process-global state (default `{trace}`)
- `_ensure_plugin()` only creates the tracer when `trace` is enabled AND a
  trace dir is set; other features drive their own UC modules
- Each hook handler gates tracer calls on the `trace` feature, then dispatches
  to enabled UC stubs (no-ops today)
- `_flush_traces()` calls tracer flush (if trace enabled) then UC stubs'
  `flush()` (no-ops today)
- `on_session_end()` calls UC stubs' `on_session_end()` after the tracer flush
- `_clear_env_for_tests()` also pops `CTXVM_FEATURES`

Capture path is byte-compatible: with default features (`{trace}`), behavior is
identical to before ORG-1 (verified by the existing 23-test suite passing
unchanged).

### 2.4 Per-UC test file — `packages/hermes/test/test_uc_registry.py` (NEW)
11 tests across 3 classes:

- `FeatureParsingTests` (4): default `{trace}` when unset, comma-separated,
  case-insensitive + deduped, unknown names ignored
- `UCModuleStubTests` (4): each stub's `name`/`feature`, all handlers no-op
  (return None), `enabled()` respects feature sets, trace UC (`feature=None`)
  always enabled
- `DispatcherTests` (3): default features → pages declared; `trace` disabled
  (`CTXVM_FEATURES=uc1-handoff`) → no jsonl written; `trace,uc1-handoff` →
  pages declared (UC1 stub is a no-op alongside the tracer)

### 2.5 build-hub.sh self-baselining — `tools/build-hub.sh` (MODIFIED)
Added step 5: after `odpc-build` regenerates `hub/catalog.yaml` +
`hub/index.html`, runs `(cd hub && sha256sum -c hub.sha256)` so drop cards no
longer need to run the checksum check by hand. Removed the now-redundant
separate check from `tools/run-ci.sh` and `.github/workflows/ci.yml`.

### 2.6 CI gate constants
- `tools/run-ci.sh`: removed the now-redundant `(cd hub && sha256sum -c hub.sha256)`
  line (build-hub.sh covers it)
- `.github/workflows/ci.yml`: removed the separate `cd hub && sha256sum -c hub.sha256`
  from the hub job (build-hub.sh covers it)
- No test-count constants needed updating (ci.yml runs suites directly;
  run-ci.sh line 51 already reports 23 + 27 from KIT-1)
