## 3. Residual unknowns, and how the run settles each

1. **Does the profile `toolsets: [file]` actually restrict a chat session?** The key is the config
   default that `_set_chat_arg_defaults` leaves to the agent, but I have not seen it enforced at
   runtime on this build. **First step of the run is a one-prompt probe (~$0.002)** that asks for a
   shell command; if the model can run one, the pin failed and no cell is bought.
2. **Does `--max-turns 8` bound the calls?** `hermes chat --help` documents it as the iteration
   ceiling; the probe's `usage` will show the call count.
3. **Does 55,000 actually evict?** Arithmetic says the floor is 49.4 k, so ~5.6 k of middle is
   selectable; the verifier decides, and a NO-OP verdict is a publishable finding rather than a
   failure.
4. **Naive arm's budget** is unset, so its `turn.render` headroom is computed against 200,000. That
   field is informational only; the analysis uses `perApiRequest` and the receipt.

## 5. Probe result — the surface pin holds

```
session     w8-probe-surface3-113851  (w8-paged)
reply       NO-SHELL
tool calls  0
api calls   1        cost $0.00082
```

So `toolsets: [file]` in the profile **is** enforced at runtime: the model had no shell and said so.
Two things the probe also taught, both now in the code:

- `--max-turns` cannot be passed at all on this flow: a named session with `--create-if-missing`
  rejects it as a creation override ("resume retains gateway session policy"), even on a fresh name.
  The driver no longer emits it; the ceiling is `agent.max_turns` in the profile, which was **150** in
  both arms (that is the number cell A hit as "max_iterations_reached(150/150)") and is now **12**.
- A one-prompt probe costs $0.00082, so the 13-call cell should be on the order of $0.011 if the cache
  behaves, not $0.11. The $0.00861/request blended rate is dominated by the heavy sessions.
