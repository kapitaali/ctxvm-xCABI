## 1. What was done

`CtxvmPlugin._transcript_texts` (`packages/hermes/src/plugin.py:426`) parsed
`message["content"]` as a list of `{type, text}` blocks. Live Hermes messages carry it
as a **plain string** (`agent/conversation_loop.py:350`, `oneshot.py:103`, Hermes
v0.22.5 @ `bf0203a794`), so the old parser iterated the string's characters, appended
nothing, and returned `""` on every real turn — `identifier_scan` could not fire on any
live Hermes capture (m4/m7 LIVE: 0 faults).

The fix (the proposal's §2 shape, verbatim): accept the string `zone`, keep the block
list and `parts` list branches, add the bare-string part branch, guard non-dict
messages, and keep the `text` fallback. ~12 lines.
