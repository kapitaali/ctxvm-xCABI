# RR-W8CATTR2-20261112 — the arm, the profile and the budget ARE recoverable from durable sources: the
## hermes DB's `sessions.profile_name` and the profile's own config — so the capture's mis-attribution
## does not void the existing evidence (though the capture still should be self-describing)

Card: a refinement of this lane's attribution finding (`reports/RR-W8CATTR-20261111.md` §2,
`reports/RR-W8CCELL01-20261111.md` §4), checked against the artefacts of cell-01 while the other lane
implements the session keying.

## 1. The finding

The capture's `plugin` block is **not** a reliable witness of which arm produced it: the arm, the profile
and the budget are process-global and read **at flush time** ✓, so a gateway restart's re-flush rewrote
all six of cell-01's captures with the then-current values, and the **paged** arm's own capture now
attests the **control** arm (`profile: default, arm: control, engineSetting: compressor,
engineSelections: 0, budgetTokens: 200000 / budgetSource: default`) although that session ran in the
paged profile ✓.

## 2. But the attribution is recoverable from two durable sources — checked today on cell-01's pair

| what | where it lives | cell-01's naive session | cell-01's paged session |
|---|---|---|---|
| the **profile** that served the session | the hermes DB's `sessions.profile_name` (per profile home) | `local-b04b81e98061…` → **`w8cn-naive`** ✓ | `local-31896a30da46…` → **`w8cn-paged`** ✓ |
| the **budget** and the **engine** the runner invoked | the profile's own `config.yaml` (`context.engine`, `plugins.entries.ctxvm-tracer.settings.budgetTokens`) | the naive profile carries none | `engine: "ctxvm"`, **`budgetTokens: 60000`** ✓ |
| the **usage** the provider reported | the same DB row (`input_tokens`, `cache_read_tokens`, …) | in 224,455 / cache_read 4,461,568 ✓ | in 1,071,090 / cache_read 2,870,144 ✓ |
| the **sidecar's own claim** | the capture's `plugin` block | — | ✗ says `default` / `control` / 200,000/`default` |

**So the arms of cell-01 are attributable today, retroactively** ✓ — the evidence is not lost: the DB's
`profile_name` is written by the host per session and is never a flush-time global, and the budget comes
from the profile's own config plus the runner's invocation record ✓.

## 3. What this changes, and what it does not

- **It lowers the risk this lane flagged**: a reader cannot mistake cell-01's pair for a mis-attributed
  run, because the attribution can be *re-derived* from the DB and the config rather than read off the
  capture ✓ — and the review side's own numbers (the arms' residency difference, the 4.77× uncached
  ratio) were taken from exactly those durable sources ✓.
- **It does not remove the need for the fix.** The capture should be **self-describing**: a reader who
  has only the trace directory and the sidecar would read the wrong arm ✓ — which is precisely the
  situation the next block's attribution clause works around (*"read from the run's own output … never
  re-read from a capture afterwards"*). The session keying (arm fields **and** budget, keyed by
  `session_id`) is still the right fix ✓; this finding only says the *evidence* for the runs already made
  is not void ✓.
- **And it names the durable witness for the future**: the pair's attribution can always be re-derived
  from `sessions.profile_name` + the profile's config, so a cell's attribution never depends on the
  capture alone ✓ — which is a useful thing to state in a block, because it means the attribution has a
  second, independent witness.
