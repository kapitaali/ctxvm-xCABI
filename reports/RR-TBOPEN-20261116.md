## Decisions in the plan, and why

- **One capability run, not a cell.** The OpenCode adapter cannot evict or report an engine, so this run cannot
  witness paging. It answers only "is the 150-row shape hand-answerable and complete?" A GO authorizes
  preregistering a *Hermes* paged cell; it does not prove anything about paging.
- **192×150, not 240×120.** Measured C is essentially unchanged from the 48×600 shape while per-prompt rows drop
  from 600 to 150. Crossing moves to turn 106, well inside the file count. F is not printed by the generator and
  is explicitly UNVERIFIED until phase 0 prints it.
- **Prompt kept verbatim.** P1–P192 use the exact sentence in `design/TB-PLAN.md` §3; P193 keeps both the artefact
  and the three exact-row lookups. Only the file count and prompt count change.
- **Ceiling 450, provisional.** Derived from the measured 12-prompt call ratio, not asserted as measured for 193
  prompts. The plan freezes it only after phase 1 measures the first three OpenCode prompts.
- **Re-preregistration is the gate.** New digest, new prompt count, new ceiling, new harness; none of those is a
  reason to skip a prereg before phase 3.

## Limitations / UNVERIFIED

- The 240×120 and 200×150 shapes were generated but their full curves were not printed; their digests are on
  record, their crossing turns are not.
- F for 192×150 is UNVERIFIED until phase 0.
- Zero-cost is a local config declaration; no provider receipt exists for the proposed subject.
- Whether `@ctxvm/opencode` emits a capture in this harness is unverified — the config has no `plugin` entry.
  The plan requires the run to say which it is rather than imply a trace.
- The rate limit from the Hermes chain is noted; the plan makes no call while it may still apply.
