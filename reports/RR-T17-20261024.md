## 3. Honest deviations / limitations

- **Live Hermes captures: env-gating needs gateway restart; slash commands don't.** The Hermes gateway is a long-running daemon process; plugins load in the gateway process at startup. `CTXVM_TRACE_DIR` exported in the CLI shell does **not** propagate to the gateway's environment. Two paths:

  **Path A — Env-gating (gateway restart required, separate shell):**
  ```bash
  # 1. Propagate env vars to the user systemd instance
  systemctl --user import-environment CTXVM_TRACE_DIR CTXVM_TRACE_NAME CTXVM_MODEL CTXVM_PROVIDER CTXVM_AGENT_ID CTXVM_BUDGET_TOKENS

  # 2. Restart the gateway from outside the gateway process
  hermes gateway restart

  # 3. Run a session — plugin now traces
  CTXVM_TRACE_DIR=/tmp/ctxvm-capture CTXVM_TRACE_NAME=my-session \
    hermes -z "Read /path/to/file.txt"
  ```
  `hermes gateway restart` (and `systemctl --user restart hermes-gateway.service`) are blocked from inside the gateway process: "command or referenced script cannot restart, stop, or uninstall the gateway from inside the gateway process." The restart must be initiated from a separate shell/process.

  **Path B — Slash command (no gateway restart, works from inside Hermes):**
  ```bash
  hermes -z "…"
  # Inside Hermes:
  /ctxvm-trace start /tmp/ctxvm-capture my-session
  hermes -z "Read notes/alpha.md."
  /ctxvm-trace stop
  ```
  The slash command sets the trace dir in-process via `ctx.register_command("ctxvm-trace", …)`, so no `systemctl --user import-environment` or gateway restart is needed. This is the recommended path for live captures.

  Synthetic traces in `corpus/m3/` exercise the same declare/fault/turn paths as live captures would. A successful live trace (expect 1 page per echo-beat read) is the natural corpus/m4 drop (provenance: LIVE), with m2↔m3↔m4 turn-attribution comparability per the earlier review finding.

- **Resume-from-files not implementable at v0.** No Hermes hook fires before session context assembly; `on_session_start` payload is `{session_id}` only. The `--resume-from snapshot` flow (UC1 §3 Step 3) requires core Hermes support (session-seeding API or pre-session hook) and is out of scope for this card.
- **Plugin installed at `~/.hermes/plugins/ctxvm-tracer/`** (minimal loader install, per card scope). Coordinate any deeper Hermes config integration with the Hermes config owner.
- **`live/ctxvm.py` is `.py` not `.ts`.** Hermes plugins are Python; the `.ts` extension in the card text follows the T12 naming convention but does not apply to Hermes's Python plugin system.
- **budgetTokens=120000** is declared headroom bookkeeping (T9 convention), not the provider's measured context window.
