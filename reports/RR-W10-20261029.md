## 4. Discoveries

1. **`@ctxvm/node` cannot be published as-is.** Its `exports` points at
   `./src/index.ts`, and Node.js "refuses to handle TypeScript files inside
   folders under a `node_modules` path"
   (`https://nodejs.org/api/typescript.html`). A build step emitting JS (plus
   `files`/LICENSE/repository metadata) is a prerequisite. The current `engines`
   floor `>=22.6.0` predates default type stripping (v22.18.0/v23.6.0).
2. **crates.io has a version-requirement blocker.** `ctxvm-core` (and likely
   `ctxvm-tokenizer`/`ctxvm-conformance`) fail `cargo publish --dry-run` because
   workspace path dependencies carry no `version`. `ctxvm-codec` alone passes,
   with warnings only.
3. **The PyPI wheel is not self-contained.** It shells out to the Rust binaries
   (`CTXVM_RUST_BIN_DIR`, repo-relative build dir, or PATH). Publishing it alone
   yields a broken install; platform wheels or a documented Rust prerequisite
   are required.
4. **`umpire` is unavailable as a bare name** on npm, crates.io, PyPI, and as a
   GitHub org. Any future publication needs a qualified name; the local repo
   name is unaffected.
5. **There is no `ctxvm` dispatcher binary** — five separate binaries
   (`replay`, `profile`, `diff`, `export`, `tokens`). Quickstart wording uses the
   real command.
6. **The OpenCode ecosystem entry is a docs-table PR**, while the Hermes catalog
   is a JSON index PR pinned to a commit SHA; both entries are drafted and
   explicitly not submitted. The Hermes index URL from the docs returned 404 at
   check time, so exact JSON keys are UNVERIFIED.
