# RR-T4 — xCABI RFC-0: spec + strict JSON Schema + conformance validator

**Card executed:** T4 (M) · **Date:** 2026-10-22

## What was done

- `spec/rfc-0/RFC-0-xCABI.md` — the RFC-style standard consolidating 02 + every
  semantic M0 locked:
  - event/payload field tables (exact tags, camelCase fields, snake_case value
    enums; resolution notes vs the 02 draft table: `call.meta` gains `turn`,
    pins stay turn-free, declare stays turn-free)
  - **effect-timing table** + change-ordering rule (from T1c: evict@t visible at t,
    fault@t → full at t+1, `(effective_turn, stream_seq)` max-wins) — normative
  - stub format verbatim; fault taxonomy; invariants (02's five + new #6: fact
    coherence must be mechanically checkable)
  - determinism boundary, canonical-form strictness rules, replay semantics
    (3 divergence kinds, exit codes 0/1/2, violation-vs-divergence split),
    fixture taxonomy (codec vectors vs replay fixtures), violations ledger
  - Open-questions section carrying ALL unresolved items (version field, declare
    turn, pin turn, evicted-token verification, semantic taxonomy naming) plus the
    02 originals — marked as RFC-1 duty; nothing silently invented into v0
- `spec/rfc-0/x-cabi.schema-v0.json` — JSON Schema draft 2020-12, `$defs` per event
  under strict `additionalProperties:false`, `"type"` consts, integer-only numeric
  fields with `minimum: 0`, optional fields typed-but-not-nullable (omit ≠ null),
  value enums exact (`file|tool_result|summary|image_ref`,
  `full|stub`, `tool_recall|identifier_scan|explicit_api|semantic`)
- `spec/rfc-0/validate_schema.py` — reusable conformance validator (CI-gettable:
  every vector-fixture line must validate + 5 engineered negative gates must trip)
- `00-README.md` index updated with `spec/rfc-0/`.

Positive coverage: `events-v0.jsonl` (10) + `session-clean.jsonl` (22) +
`session-divergent.jsonl` (18) = 50 lines. Negative gates: unknown tag, unknown
field, float tokens, `null` optional, missing required.

## Deviations from card

- Card allowed self-tests "if vectors don't exist yet" — they do, so all three
  conformance fixtures were used (strictest option).
- Validator lives as a script under `spec/rfc-0/` rather than a one-off command:
  reusable by CI (feeds the future T7-free validation job) and reusable whenever
  fixtures change.

## Discoveries

1. **Three-way cross-validation achieved on first run:** hand-authored vectors ↔
   hand-written JSON Schema ↔ Rust codec's canonical serde output agree line-for-line
   on all 50 lines. No drift between spec and code — the strongest result available
   in T4. (One diff class to watch for bindings: JSON Schema pins REQUIRED fields;
   the codec allowlist pins PRESENCE of required fields too — equivalent for v0.)
2. JSON Schema cannot natively express "optional integer, but ABSENT not null when
   unknown" without `if/then` in v2020-12 — chose typed-but-not-nullable, matching
   the codec's omit-never-null rule; noted in schema description.
3. The schema is the FIRST third-party-machine-checkable artifact of the project
   (any consumer can validate a candidate trace without Rust). This is the artifact
   T2's RFC-request/quality docs and T6's shim spec should reference.
