# RR-P11LEVEL2-20261111 — the P11 pair is committed and its third level is now ASSERTED: the derived
## page table is compared turn by turn and pinned, so the RFC-0.1 note's C2 clause is executed rather
## than inferred

Card: the owner ruled "do those" on 2026-11-11 — the two loose ends this lane had flagged on the P11
pair were (a) the pair + test were staged but never committed, so the RFC-0.1 note's C2 pointer named
an uncommitted file, and (b) the test's **third level** (the derived page table) was claimed in prose
but never compared. Both are now closed, in one commit.

## 1. What changed in the test (`rust/crates/ctxvm-conformance/tests/key_order.rs`)

**Level 2 is now an assertion.** For every turn a trace carries, both byte forms are projected and
compared, and both are compared against a pinned expectation:

```rust
let turns = turns_in(&a);
for turn in &turns {
    let pa = ctxvm_core::derive_projection(&a, *turn);
    let pb = ctxvm_core::derive_projection(&b, *turn);
    assert_eq!(pa, pb, "{label}: derived page table differs at turn {turn}");
    assert_eq!(serde_json::to_value(&pa)?, *pinned, "{label}: derived page table differs from the pinned projection at turn {turn}");
}
```

Three implementation points, each deliberate:

- **The turn set is read from the model's own serialisation** (`turns_in`: `serde_json::to_value(e)`
  then the `turn` field), so the helper stays correct if the codec's event set grows; `session.open`
  has no `turn` and contributes none.
- **The comparison is field-by-field, not byte-wise**: `TurnProjection` derives `PartialEq`
  (`rust/crates/ctxvm-core/src/render.rs:54-61`), so the assertion covers `slots`, `tally` and
  `violations` — the page table itself, not a hash of it.
- **The pin is what makes the level independent.** Without it, level 2 would follow from level 1 by
  the purity of `derive_projection` and would prove nothing on its own. The pinned projection comes
  from **the committed tool**: `ctxvm replay <vector> --turn N` (the CLI that already prints "the
  turn-N render projection"), captured into `vectors/order-expected-projection.json`.

**The two overstating comments are corrected.** The function comment said "Level 2: both derive the
same page table (the report carries it)" — the report does **not** carry it: `ReplayReport` has
`events`, `divergences`, `violations` and nothing else (`rust/crates/ctxvm-core/src/replay.rs:48-55`).
The assertion message said "replay report (page table, divergences, violations) differs"; it now says
"replay report (events, divergences, violations) differs". The header's claim — three levels of *parsed*
equality: model, derived page table, replay report — is now true rather than aspirational.

**The vectors README** (`rust/crates/ctxvm-conformance/vectors/README.md`) gained the new golden's row,
the sentence about what the test asserts, and the note that the report does not carry the page table.

## 2. The pinned projection, and what it contains (measured, not assumed)

`order-expected-projection.json` holds one projection per turn per pair, keyed by the struct-form file
of each pair (the sorted twin must derive the same table):

| pair | turn | slots | tally | violations |
|---|---|---|---|---|
| `order-struct-ts.jsonl` (v0.1) | 0 | 1 | resident 1 / 19 tokens, stubbed 0 | 0 |
| `order-struct-nots.jsonl` (v0) | 0 | 1 | resident 1 / 8200 tokens, stubbed 0 | 0 |
| `order-struct-nots.jsonl` (v0) | 1 | 1 | resident 0 / 0, **stubbed 1 / 8200** | 0 |
| `order-struct-nots.jsonl` (v0) | 2 | 1 | resident 0 / 0, **stubbed 1 / 8200** | 0 |

The v0 pair is the more interesting one: it is the trace where a page **goes stub** at turn 1 and
stays stubbed at turn 2, so its pinned page table shows the resident→stub transition — the page table
is not a formality here. (That vector also carries an engineered lie at turn 1 — a `residentTokens`
mismatch, recorded 47800 vs inferred 0 — which the CLI reports as a divergence; that is why
`ctxvm replay --turn 1` exits 1 there. The projection is still emitted and still pinned.)

## 3. Falsification (the check that makes the assertion worth having)

- **Level 2's pin, falsified:** changing one token in the pinned projection (`residentTokens` 19 → 20)
  fails with `v0.1 (ts on every line): derived page table differs from the pinned projection at turn 0`;
  restoring the golden returns green. Measured on the committed test, 2026-11-11.
- **The suite:** `cargo test -p ctxvm-conformance --test key_order` → **4 passed** (level 1 + level 2 +
  level 3 for both pairs, plus the ts-placement property and the empty-pair guard).

## 4. What this closes, and what it deliberately does not

- **Closed:** the RFC-0.1 note's C2 pointer now names a **committed** file, and the clause's reasoning
  ("equal parsed models entail equal derived page tables") is **executed** by the test rather than
  assumed. The erratum in `reports/RR-P11GAP-20261111.md` §3 — which corrected this lane's own card
  for claiming the report carries the page table — is retired by construction: the page table is
  compared, through the projection, and the report's message now names what it compares.
- **Deliberately untouched:** `spec/rfc-0.1/COMPATIBILITY.md`. The note's status line binds its content
  changes to a **new D-number**, and the owner's ruling was about the *test*, not about amending the
  note. The clause's existing text stays true (the test it points at now asserts more than the clause
  requires). If the owner wants the note to name the projection golden too, that is a fresh D-number
  and a one-line addition — the owner's call, not this lane's.
- **Also untouched:** the v0 schema and everything under `spec/rfc-0/` (sealed), the corpus, and every
  other lane's files.
