## 0. What was built

1. **Fixture T-A2** — 20 parts (part-01.txt … part-20.txt), 250 lines each, line lengths
   uniform in [5, 120] bytes, chars from `abcdefghijklmnopqrstuvwxyz ` (27-char alphabet),
   seed 42, single RNG stream. Materialised into `experiments/w8b/{ws-naive,ws-paged}/fixture/`.
   Parts 01–10 byte-identical to the original W8 T-A fixture (verified by cmp).

2. **Profiles** — `~/.hermes/profiles/w8b-naive` and `w8b-paged`, copied from the W8 pair,
   differing in exactly two keys: `context.engine` (compressor vs ctxvm) and
   `plugins.entries.ctxvm-tracer.settings.budgetTokens` (absent vs 70000). Both carry
   `toolsets: [file]`, `agent.max_turns: 12`, `model.default: nvidia/nemotron-3.5-super-vl-120b-a12b`,
   `model.provider: nvidia`.

3. **Driver** — `tools/w8-driver.py` extended: 20 PROMPTS (reads 1–18, parts 19–20 on prompt 19,
   artefact on prompt 20), `--profile-prefix w8b`, `--expect-budget 70000`, prompt digest
   (sha256 of prompts + artefact spec, 12 hex) stamped into the run dir, seal parts 01–03 after
   prompt 3.

4. **Env script** — `tools/w8-run-env.sh` extended to accept `w8b-naive` / `w8b-paged` arms
   with model defaults (nvidia/nemotron-3.5-super-vl-120b-a12b, provider nvidia, budget 70000).

5. **Checker** — reused `tools/w8-checker-ta.py` unchanged (parsed equality is the gate).

## 5. What the naive arm shows (and does not prove)

**Supportable:**
- At budget 70,000 over 22 turns on nemotron-3.5-super-vl-120b-a12b, the naive arm
  (compressor engine, no paging) produced 0 evictions and a parsed-equal artefact.
- The model can drive the 20-part T-A task surface (read_file, search_files, write_file).
- The floor is 87,578 resident tokens — well above the 70,000 budget. This means the
  paged arm *should* evict if it runs (resident 87,578 > budget 70,000 → ~17,578 tokens evictable).
- The model uses search_files extensively (61 calls) in addition to read_file (22 calls),
  suggesting it is not following the "read each part once" pattern efficiently.

**Not supportable:**
- Any saving or cost reduction (no paired paged run completed).
- Any claim about eviction behaviour (paged arm did not run).
- Any generalisation to the paid model (gpt-6-luna) or other shapes.
- Any cause for the cache-write volume (not measured in this run).

## 6. Open questions / next steps

1. **Rate limit:** The NVIDIA NIM free tier is throttling. Options:
   - Wait for hourly reset and retry.
   - Check NIM account quota / request limits.
   - Consider a different free model if the throttle persists.

2. **Paged arm:** Needs to run to complete Phase 2. Expected: resident 87,578 > budget 70,000
   → ~17,578 tokens evictable, ~20% of the peak request. The paged arm should produce
   evictedTokens > 0 (CELL) if the engine works as designed.

3. **Naive arm validity:** The naive arm ran under the w8b-naive profile but the coverage
   sidecar's engine field reads "ctxvm" (plugin registration, not host selection). The
   profile's context.engine is "compressor". The run is a valid control-arm measurement
   but the engine attribution in the sidecar is misleading. This is a known limitation
   documented in the plugin code (no public accessor for the profile's engine setting).

4. **Provider attestation:** The naive arm's meta records provider "unknown" because
   CTXVM_PROVIDER was not set in the gateway's environment during that run. The model
   is correctly attested as nvidia/nemotron-3.5-super-vl-120b-a12b.

5. **Model verbosity:** The model uses search_files (61 calls) and grep in addition to
   read_file (22 calls). This is more tool calls than expected for a 20-part census task.
   The model may be over-verifying. This increases both latency and token cost.
