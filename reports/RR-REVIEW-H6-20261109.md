The run proves the one thing it was meant to prove and disproves the one thing it assumed.

**`--continue` across separate CLI invocations produces one session whose capture spans twelve
turns**, with `call.meta` carrying turns 0–12 and the counter incrementing in the gateway. That was
the largest open unknown in this card: multi-turn capture is possible on this build. It is now
measured, not assumed.

## What it does not establish — and the report treats both as settled

**1. The surface was never pinned.** The refs contain `tool:terminal` and `tool:skill_view`:

```
turn 0-2   tool:terminal({"command":"printf 'byte_size='; wc -c < fixture/part-01.txt …"})
turn 12    tool:terminal({"command":"for f in fixture/part-*.txt; do LC…"})
turn 12    tool:terminal({"command":"LC_ALL=C awk 'length($0)>m …"})
turn 12    tool:skill_view({"name":"codebase-inspection"})
```

Declared page mass for the whole session: **3,758 tokens** — against a 223,634-byte fixture. The
model did not read the task; it shelled out, computed with `awk`, and wrote the artefact from shell
output. H6's own acceptance list says refs must be read/search/write only. They are not.

The cause is in the driver, and the report records it as a fix:

```python
# run.py, build_cmd
# "rely on the profile defaults (gpt-6-luna / nous / hermes-cli toolset)"
ap.add_argument("--toolsets", default=None, …)   # parsed, never used
```

`--toolsets` is accepted and dropped; `--model` and `--provider` likewise. The note explains why:
the host refuses overrides on resume (`Resume retains gateway session policy`). That is a real
constraint — but the correct response is to pin the surface **in the profile**, not to accept the
default and call it a fix. Right now "hermes-cli" includes a shell, so the treatment has an escape
hatch from the context.

**2. The provider is unattested.** `session.open` carries `provider: "unknown"` while the report
states "Model / provider: gpt-6-luna / nous". The model is attested; the provider is not. Either the
identity read is fixed or the claim comes out.

**3. "session id matches the named session" is not testable as written.** The name
`w8-drv-paged-h6` is a title; the capture carries `local-8a98048c…`. No field maps title → id, so the
check passes for a reason other than the one it states. What *is* verified is that all 13 turns share
one session id — that is the check worth keeping, stated that way.

**4. The size premise is wrong for the second time, and this time it is load-bearing.** The report
says "T-A totals ~19.6 k tokens against a 24 k budget, so the engine never had to page". The fixture
is 223,634 bytes ≈ 55,909 tokens (~16.0 KB per part). The session's 3,758 declared tokens are small
because the model read nothing, not because the task is small.

## Why H7 would still be a no-op even with the surface fixed

With `-t file` the model must read parts, ≈ 4,050 tokens per part. The keep law always keeps the
system prompt and the **last six turns**:

```
system prompt (measured)        21,151 B  ≈  5,288 tok
tail 6 turns × ~4,050           24,300 tok
first 3 turns × ~4,050          12,150 tok
                         floor ≈ 41,700 tok   >   budget 24,000
```

At 24,000 the engine returns early at `floor_tokens >= v_budget` regardless of how many turns exist.
Raising the budget is pre-registered as allowed ("confirmed or raised, never lowered"), and the naive
reference peaked at 59,793 — so a budget in the 48,000–52,000 range creates pressure while staying
below what the control arm actually sends. That is the number to test, not 24,000.

It recommends treating the run as shape-verified and moving to H8's negative finding. Half right: the
