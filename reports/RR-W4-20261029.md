## 2. Verification (commands + real output)

### 2.1 The docs are the authority for the turn model — and they contradict the adapter

Observer-hooks, Turn-Scoped LLM Hooks: `pre_llm_call` fires "Before the tool loop
begins for a **user turn**", and "Use request-scoped API hooks for LLM span
telemetry." The plugin uses that hook as its turn boundary, so a Hermes
`turn.render` is a **user-turn** row while `@ctxvm/opencode` and `@ctxvm/ai-sdk`
emit one per **model request**. Witness: m7-a has 5 `turn.render` for 29 hook
fires (`contexts 5 + before 12 + after 12`, sidecar `hookStats`); m8 has 10 turns
for one scripted task.

### 2.2 The `turn.render` gap is wider in Hermes than in the other two emitters

Documented in `OBSERVABILITY.md` §2 with locators; the load-bearing ones:

- `agent/conversation_loop.py:350` / `agent/oneshot.py:103` — messages are
  `{"role", "content": "<str>"}`.
- `agent/turn_context.py:816` — the hook receives `conversation_history=list(messages)`.
- `agent/context_engine.py:124` — `select_context()` "runs on every provider
  request… before prompt cache-control and every request sanitizer", and
  "unlike `pre_llm_call` it may replace the list". `prune_tool_results_only()`
  (same file) trims old tool payloads on a separate trigger. The tracer's view
  is pre-select, pre-prune — i.e. **not the request**.
- The system prompt, tool schemas and cache breakpoints are never passed to any
  hook (`on_session_start` fires "after the system prompt is built" and carries
  only `session_id`).
- `transform_tool_result` may replace a result *after* `post_tool_call`
  (`model_tools.py:849`), so a page body hashed there is the pre-transform body.

### 2.3 Cheap hooks — measured, not asserted

```

packages/hermes/src/plugin.py:327:  … s.startswith("http") …                # ditto
```
No network import; all I/O is the one flush at `on_session_end`/`on_unload`.
Cost of the heaviest callback (`pre_llm_call` → `scan`) with the real m7 page
refs and an 80 000-char history:

```
pages=34 identity_tokens=222 avg=6.5
scan cost (80k chars, 222 tokens): 5.86 ms      # best of 5
```
Against `plugins.hook_callback_timeout = 30`s (`hermes_cli/config_defaults.py:1733`
via `_resolve_hook_callback_timeout`), that is three orders of magnitude of
headroom. `post_tool_call` is sub-millisecond at these sizes.

### 2.4 DEFECT — `identifier_scan` is dead on live Hermes payloads

`_transcript_texts` iterates `content` as if it were a parts list. On the live
string shape, iterating a string yields characters, no dict matches, and the
function returns `""`:

## 3. Deviations from the card

- **No plugin code change.** The card's letter invites building the adapter; the
  adapter exists and passes its acceptance. The four defects found belong to a
  lane held by another workstream (standing `node/hermes do-not-touch` note), so
  they are a proposal with a proven patch instead of a unilateral edit — the same
  proposal-first shape every other lane-crossing card in this repo used.
- **`corpus/m7/provenance.json` was edited** (metadata only, trace bytes and
  package artifacts untouched, checksum row re-baselined). The prompt's W4
  explicitly requires a gap to be marked in the trace's provenance; leaving m7
  reading `faults: 0` would have been the dishonest option.
- **B3/B4 are not adapter work.** Provider-reported usage has nowhere to go in
  RFC-0 (`call.meta` is `additionalProperties: false`), so W2b-in-Hermes is a
  spec question → routed to the W7 RFC-0.1 card rather than patched around.

## 4. Discoveries (each with its downstream card)

1. **Hermes live traces under-report faults to zero on the inference surface.**
   Consequences: W1's hermes rows (`id-touched share 0`, `waste 1.0`) are not
   measurements — `waste = 1 − 0` is vacuous, not an upper bound; W5's
   cross-harness comparison is capture-limited on the hermes side until the fix
   lands; the m7 erratum is the reader-facing record.
2. **Turn units differ across emitters** (user turn vs model request). W5 MUST
   classify hermes↔opencode turn-tally mismatches as unit mismatches, never as
   behaviour, before quoting a divergence. This is the single most likely
   false finding in the coming portability test.
3. **The W2b gap is spec-shaped, not code-shaped** for Hermes: `usage` arrives on
   `post_api_request` today; `call.meta` cannot carry it. Third motivating
   friction for the RFC-0.1 proposal (W7), alongside umpire's two.
4. **The test suite pinned a shape the harness never sends.** Generalisable rule
   for the repo: a fixture generator that invents its payload shape can green a
   dead surface for four drops. B2 (a live-shape fixture) is the structural fix.
5. **`telemetry_schema_version = "hermes.observer.v1"`** exists on every payload
   and is recorded nowhere; the 09 sidecar canon would need one additive key on
   both sides. Low priority, routed to W7/09.
