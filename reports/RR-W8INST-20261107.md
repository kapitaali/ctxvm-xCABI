# RR-W8INST-20261107 — the instrument: a per-call request series, and why it is not on the wire

Card: W8 instrument fix (P0 of the owner's 2026-11-07 amendment, after the pilot). Spend $0.

## The defect, measured

`finish()` stamped **every** `turn.render` with the resident total **as of flush time**
(`resident = sum(all_declared.values())`). A session that renders at turn 0 and declares more
pages later therefore showed one constant: the series was flat by construction, not by
behaviour. The pilot made it visible from the other side: a five-API-call task rendered
**once**, so `turn.render.prefix.requestChars` was a single opening request (76,864 chars) and
nothing recorded the requests that followed.

## The conflict the amendment ran into

Putting the per-turn value on the wire (`turn.render.residentTokens = residentAtTurn`) makes
the engine disagree, and the engine is the authority:

```
$ ./rust/target/release/replay /tmp/w8p0/series.jsonl
{ "divergences": [ { "residentTokensMismatch": { "turn": 0, "inferred": 20, "recorded": 10 } } ] }
ctxvm replay: replay reported divergences
exit 1
```

`ctxvm-core`'s `tally_at` law counts a page declared at any stream point as resident **from
turn 0**, and the frozen corpus (m1–m8) was emitted under that law and is byte-pinned. A
per-turn wire value would diverge on every multi-turn trace. Reported rather than worked
around: changing `tally_at` is a core-law change that would invalidate the frozen drops.

## What was built instead (sidecar, additive, optional)

* `packages/hermes/src/plugin.py` — one sample per API request in `on_pre_api_request`:
  `{turn, call (1-based within the turn), requestChars, approxInputTokens, toolSchemas,
  messageCount}`, only for measured integers; `api_samples()` exposes a copy. This is the
  series NTR is computed from, and it exists even when a whole task is one user turn.
* `packages/hermes/live/__init__.py` — the coverage sidecar now carries two additive keys:
  `perCall` (one sample per `turn.render`, **byte-true** — it is read out of the trace rows
  the sidecar describes) and `perApiRequest` (the tracer's per-request samples).
* `tools/coverage_check.py` — verifies `perCall` against the trace exactly (turn,
  residentTokens, requestChars, approxInputTokens) and `perApiRequest` for shape and ordering
  (integer turn, 1-based call index ascending per turn, non-negative counters). Both keys are
  optional, so every existing corpus sidecar still passes unchanged.

The installed plugin copy was synced (`~/.hermes/plugins/ctxvm-tracer/__init__.py`); the
gateway imports a plugin once per process, so the new keys appear only after the next restart.

## What this does not fix

The wire still has one render per user turn. The per-call series lives in the sidecar, so any
NTR figure must be computed from the sidecar (`perApiRequest`) and say so; a reader that reads
only `turn.render` rows will still see a single opening request per run. The amendment's
wire half needs an owner ruling on `tally_at` — it cannot be done without breaking the frozen
corpus.
