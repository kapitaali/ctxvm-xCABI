## 2. The ERRATUM on this lane's P10 card (appended block; the committed text stands)

The P10 card's Evidence 4 framed (c)'s blast radius as "a field on `page.declare` makes EVERY declare
line invalid for strict v0 consumers". **That framing overstates the marginal cost.** Corrected: a
strict v0 consumer already rejects a v0.1 trace at its `session.open` line — measured today and
earlier: the sealed v0 validator rejects the umpire ab-demo ledger with 4 failures (lines 1, 3, 4, 6:
the `schemaVersion` line and the three `intentional_rerun` fault rows) — so (c) does not newly break
v0-only readers of v0.1 data. The **marginal** costs of (c) are: (i) every v0.1-aware consumer must
be updated (the strict allowlist rejects an unknown field), (ii) two sources of identity per line, and
(iii) a consistency rule between them — the reviewer's framing, which this card adopts. And the
"sealed v0 data keeps both shapes forever" argument (their #4) is the decisive one against (c),
because the asymmetry is in the SEALED v0 schema itself, not an RFC-0.1 artefact. The ruling is
unchanged; the reasoning behind it is corrected and sharpened.

## 3. The ruling as recorded

**Ruling: (b) + (a) — one RFC-0.1 compatibility-note line plus prose docs; NO field.** The note
states the rule the schemas already implement, in the words the reviewer supplied:

> Read a page's identity from `page.id.logicalRef` and `page.id.contentHash` when the event type is
> `page.declare`, and from `page.logicalRef` and `page.contentHash` for every other page-carrying
> verb; dispatch on event type, never on which fields happen to be present.

with the last clause spelled out in the note (a reader that accepts either shape by sniffing fields
will silently pass a malformed line), and with the note naming the general rule rather than any
profile-specific shortcut (see §1 #9). Landing route (owner-gated, per §1 #10): a **new file under
`spec/rfc-0.1/`** — the RFC's own declared scope — carrying the note, approved with a **D-number** in
the ctxvm decision ledger; `spec/rfc-0/` stays byte-sealed and the existing RFC-0.1 text is not
edited. A conformance **vector** makes the rule testable (a fixture, §1 #11): one line per shape —
a `page.declare` with nested `page.id`, and one flat page-carrying verb — plus a **negative** vector:
a `page.declare` carrying a flat `page.logicalRef`, which a sniffing reader would accept and the
validator must reject. That negative vector is what turns "dispatch on type, never on field presence"
from a sentence into a test.

**Falsifiers adopted verbatim** (any one changes the ruling): a valid v0 or v0.1 line where the
type-dispatch rule gives the wrong identity; a verb that legitimately carries both shapes; a new verb
proposed with a third shape (that is a v0.2 design question, and (c) would then deserve a hearing); a
reported consumer, outside these repos, that cannot dispatch on event type.

**Not ruled, not done:** the note file, the vector, and the D-number are the owner's. This lane
records the ruling, the note text, the landing route, the vector plan and the falsifiers — and writes
no spec, schema or vector byte.
