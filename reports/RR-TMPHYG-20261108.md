# RR-TMPHYG-20261108 — the `/tmp/ctxvm-*` directories are test scratch, and they were leaking

Card: test hygiene. No product code, no wire, no gate semantics changed.

## What the directories were

```
ls -d /tmp/ctxvm-* | wc -l     364
du -sh                         7.9 MB
mtimes                         2026-11-08 10:15, 10:34, 11:01, 11:32
names                          ctxvm-b3-argvlaw-*, ctxvm-b3-badturn-*, ctxvm-b3-bytecmp-*,
                               ctxvm-b3-digest-*, ctxvm-ws-b-*, ctxvm-wt-*
```

Four gate runs, about ninety directories each. They are `tempfile.mkdtemp()` leftovers from
`packages/hermes/test/test_plugin.py` — handoff/resume, workspace and worktree fixtures that
the tests create and never remove. Nothing in them is evidence: they are regenerable scratch,
rebuilt from the suite's own fixed inputs on the next run.

## Recommendation: delete, do not archive

Archiving them would convert a leak into a chore. They carry no measured data, they are
reproducible by running the suite, and an archive of them would be indistinguishable from an
archive of nothing. Deleted on 2026-11-08 (`rm -rf /tmp/ctxvm-*`, 0 left).

The distinction worth keeping: **evidence goes to the state dir, scratch stays in `/tmp` and
may vanish.** The W8 runs learned this the hard way on 2026-11-07 — `/tmp/w8/runs` took 24
traces with it. The redline benchmark's logs live in `~/Documents/benchmark-experiment/` and
in its repo copy; those are evidence and are not in `/tmp`. `/tmp/ctxvm-*` was never that.

## The leak, fixed

`packages/hermes/test/conftest.py` wraps `tempfile.mkdtemp` once for the session and removes
every directory it made at exit. Applied at the module rather than per test, so a test
written next month is cleaned up without its author knowing the file exists.

Verified:

```
python -m pytest packages/hermes -q     174 passed, 15 subtests
ls -d /tmp/ctxvm-* | wc -l              0        (before the fix: 91 per run)
```

## What this does not change

- No test semantics: the patch only records a path after the real call returns it.
- No gate wiring: the suite is already in gate 2, and the cleanup runs inside the process.
- Nothing about the W8 evidence loss: that was a *capture* directory, which is why the runner
  now defaults to `~/.local/state/ctxvm/w8-runs`.
