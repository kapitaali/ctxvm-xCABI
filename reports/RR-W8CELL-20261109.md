## Lane review: the hard stop fired on a broken witness, and the pair is confounded twice

**1. `engineSelections: 0` on the paged arm is a false negative, not an inert engine.**

The host deep-copies the engine per agent — `clone_for_agent()` defaults to deepcopy
(`agent/agent_init.py:1828-1841`, with the comment "the plugin system holds ONE shared instance; each
agent gets its own") — and our engine implements `__deepcopy__` by copying `__dict__`. So the clone
runs, increments *its own* `_selections`, and the instance the plugin holds stays at 0. The gateway log
shows no "engine could not be safely copied" and no "not found — falling back", which is what a
failed activation would print.

Fixed in plugin 0.10.10: the counter is a mutable meter (`{"select": n}`) that `__deepcopy__` shares
instead of copying, so the plugin reads the same number the running engine increments. Pinned by a
test that deep-copies an engine, increments the clone, and asserts the original sees it.

This is the third witness to fail on this host, and the failure mode is always the same: measuring an
object that is not the one doing the work.

**2. The two arms took different routes, so the pair is not an arm comparison.**

```
naive   5 calls,  73,392 input    one execute_code call (2 searches + code + write), 4 declares, peak 9k
paged   7 calls, 448,446 input    reads pulled into context
```

The naive arm never held the material: it computed the answer with a script. The paged arm read. That
is a comparison of two different strategies, not of two context policies, and `NTR = -5.11` is the
ratio between a code shortcut and a read-heavy run — meaningless as a paging number.

The tool surface is the same wall as cell A's 686 searches, one level up: before, a content search
made reading unnecessary; now a code interpreter makes the whole fixture unnecessary. Both are
answers the harness allows, and neither is the behaviour the experiment wants to measure.

**3. What has to be true before the next pair**

- `-t` must be passed explicitly and its effect recorded: the trace's declared refs are the evidence
  of which tools were actually used (`execute_code`, `read_file`, `search_files`).
- The cell must be *read-only by construction*: no code execution, no shell. That is the read-only
  MCP surface the consultant ranked first for exactly this reason, and the pair has now demonstrated
  the need for it more convincingly than the search evidence did.
- Until then, every pair is a pilot record, and the spend is a tuition fee.

**4. What the pair did prove.** Both artefacts are byte-identical and correct, from two different
routes, with a checker that takes its arguments and rejects the old max-line artefact. The task is
solvable, the checker works, and the capture/replay/coverage chain is intact on both arms. The
instrument question is now purely the engine witness (fixed) and the tool surface (not fixed).
