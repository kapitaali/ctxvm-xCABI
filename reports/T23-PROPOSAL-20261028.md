# T23 PROPOSAL — `ctxvm export` dir-hygiene guard (foreign-slice protection at export time)

**Date:** 2026-10-28 · **Lane:** kapitaali (rust engine — legal; opencode/hermes/node untouched)
**Size:** S · **Deps:** T21 (export), UC1-VERIFY-CHECKS (the resume-side cross-check this card complements)
**Commit law:** one commit (code + tests + gate + books), per the T22 ruling pattern.

## §1 Objective

Close the m7-recorded engine wart: **a second `export` into the same `--output`
dir at a DIFFERENT turn silently overwrites the shared per-dir trio
(`manifest.yaml`, `llms.txt`, `checksums.sha256`) and orphans the older slice**
— the older `trace-N.jsonl.zst` survives but is no longer covered by any
checksums file, and the trio now describes only the newest slice. Recorded in
the m7 books ("per-turn export into one dir overwrites manifest/llms/checksums
— engine wart, frontier item"): the resumed agent's own in-dir analysis
clobbered the live `corpus/m7 handoff/turn-3/` package, detected only after the
fact from the sidecar digest.

## §2 The wart's mechanics (surveyed 2026-10-28, `rust/crates/ctxvm-conformance/src/cli.rs`)

- `export` writes turn-named artifacts (`trace-N.jsonl[.zst]`,
  `page-table-N.json`) plus — on the `--odps` path — the shared trio whose
  names carry NO turn: `manifest.yaml`, `llms.txt`, `checksums.sha256`.
- `checksums.sha256` lists only the CURRENT run's artifacts: after a second
  export at turn M, the older turn-N zst is checksum-uncovered (the digest
  hashes only the current run's names).
- `manifest.sliceTurn` names only the newest slice.
- Consequence chain already wired on the RESUME side: `resumeVerify` globs
  `trace-*.jsonl.zst` sorted and takes the FIRST — in a mixed dir that is the
  OLD slice, and the UC1-VERIFY-CHECKS `sliceTurn` cross-check fail-closes
  (`manifest sliceTurn M != trace turn N`). So mixed dirs fail loudly at
  resume — but nothing warns at EXPORT time, which is how m7 shipped a
  silently-clobbered package in the first place.
- **Library lane impact (T22):** every `pauseAll` exports into the SAME
  `<dir>/handoff/` snapshot dir — a second pause at a different turn collides
  exactly as above, TODAY, silently. The guard turns the silent wart into a
  loud, actionable failure at the moment it happens.

## §3 Proposed law

**Foreign-slice guard in `export_core` (before any write):** after parsing the
trace and deriving the EFFECTIVE turn (arg or last-turn fact), scan the target
dir if it exists; collect any turn-named artifact of a DIFFERENT turn
(`trace-*.jsonl`, `trace-*.jsonl.zst`, `page-table-*.json` — turns compared
NUMERICALLY, not by string) and any `manifest.yaml` whose `sliceTurn` differs.
- **No foreign artifacts → clean pass (unchanged behavior).**
- **Foreign artifacts present:**
  - without `--force`: **BLOCK — exit 2**, loud stderr reason naming the
    foreign artifacts and the remedy (`… use --force to override`);
  - with `--force`: proceed; the report gains
    `dirHygiene: {"status": "forced", "foreign": [names]}` and a warning line
    per foreign artifact rides the existing warnings law (stderr + report).
- **Same-turn re-export (the legitimate m6/m7 restore pattern): clean pass** —
  the guard never fires when every present artifact belongs to the effective
  turn.
- Scope: the raw (non-`--odps`) lane is turn-named-clean today, but the guard
  scans BOTH lanes' artifacts (a foreign raw `trace-N.jsonl` in a dir that is
  about to receive the `--odps` trio is exactly the pollution the guard
  exists to catch).
- The block is a **usage-class exit 2** (no new exit class — every caller
  contract stays intact); the reason string is pinned byte-for-byte in tests,
  mirror-law style.

## §4 What changes

- `rust/crates/ctxvm-conformance/src/cli.rs` — the guard inside `export_core`
  (the single exit/serialization site the py lane shares through the binary,
  so ctxvm-py inherits the law with no py-side change; py tests all use fresh
  tmp dirs and stay green untouched), + `dirHygiene` report field.
- `rust/crates/ctxvm-conformance/src/bin/export.rs` — `--force` argv parse +
  usage/help text (one line).
- No corpus drop, no manifest/hub change (engine-only; gate-3 round-trip uses
  fresh dirs and stays byte-identical).

## §5 Test plan (new `#[cfg(test)] mod` in cli.rs — the first fs-level CLI tests)

1. Foreign zst at a different turn, no `--force` → exit 2, reason pinned,
   NOTHING written (the trio of run 1 is intact — assert byte-equality).
2. Same, with `--force` → exit 0, `dirHygiene` = forced + foreign list, warning
   lines present, older zst STILL present and still checksum-uncovered (the
   disclosed consequence, documented in the RR).
3. Same-turn re-export → clean pass, `dirHygiene` absent or clean; byte-stable
   double-run (existing determinism law).
4. Foreign raw `trace-N.jsonl` (no zst) → blocked.
5. Foreign `manifest.yaml` sliceTurn (artifacts same turn) → blocked.
6. `trace-2` vs `trace-02` → numeric compare, treated as SAME turn (clean).
7. Fresh dir → pass (existing behavior, covered by gate-3 round-trip too).

Plus one **T22 ride-along in `packages/ai-sdk`** (optional, §7 Q4): a wiring
test proving `pauseAll` at a second turn hits the guard (exit_code=2, witness
line surfaces it) — the library analogue of the wart, red-ensuring the capture
never breaks on it.
