Card: one diagnostic cell, one finding that closes the current experiment design. Cell is NO-OP;
cells counted remain 0.


Acceptance checks 1–2 passed, check 3 failed. Recorded NO-OP, not a paging result.

## 2. Why nothing was dropped — and it is not the budget

Every `page.declare` in the capture carries `turn: 0`. All fifty tool results, 63,713 tokens, sit in
one turn, because a `-z` one-shot session is one turn no matter how many tool calls the model batches
inside it. The engine's keep law is **turn**-based: `protect_first_n=3` head turns and
`protect_last_n=6` tail turns are always kept, and the system prompt with them.

With one turn in the session, "first three turns" and "last six turns" are both the whole thing. The
floor equals the request, `_plan` hits `floor_tokens >= self._v_budget` and returns early by design
(L5: "pages never rescue a busting floor"). No budget value changes this: raise it to 200,000 or
lower it to 8,000, the protected set is still the entire session.

This is not new in principle — `RR-ENGINEGAP-20261106` and the engine's own docstring record the
24,000 no-op — but the cause was attributed to the floor's size. The floor's size is a symptom. The
cause is **granularity**: the policy protects turns, the harness produces one turn.

## 3. What this means for W8 as designed

The current protocol cannot measure paging, and no further cell in this shape can:

- task A is solved inside one turn by an 8-call batched read;
- the keep law protects that one turn in full;
- therefore selection has nothing to select, at any `vBudget`.

Three ways out, in increasing cost:

1. **Multi-turn harness** — a session that spans 12+ turns (a scripted conversation, or an interactive
   session driven by successive prompts). Then first-3 + last-6 leaves a middle to select from. No
   engine change; the task must still need the older material, which means the model must be asked,
   after the reads, to answer from them.
2. **Re-preregister the keep law in messages, not turns** — protect `system + first m messages +
   last k messages`, with m, k fixed before the run. This changes the policy under test, so it needs
   a new preregistration and the old cells cannot be pooled with the new ones.
3. **A task whose pressure comes from one huge result** rather than many reads — but that is the
   regime where the engine's page granularity does act, and it tests a different claim (bounding one
   large page, not managing a working set).

Option 1 is the cheapest honest path and it does not touch the sealed policy. Option 2 is a research
decision, not an implementation one.

## 4. What today's four cells did buy

- The surface is pinned: `-t file`, no code, no shell, 32 reads in 8 calls.
- The budget is a profile setting with recorded provenance, so the treatment can be verified at
  turn 0 instead of inferred afterwards.
- The cache mechanism is measured and priced: selection that rewrites the prefix forfeits it.
- And the reason the experiment cannot run is now stated in mechanism terms rather than as a
  mysterious no-op.

That is four findings for $1.43. The next dollar should not be spent until the session shape changes.

## 5. Recommendation

Stop buying cells under the one-turn protocol. If the card continues, the next artefact is a
**multi-turn driver** — same task, same surface, same budget, but the session must span enough turns
for the keep law to leave a middle. Until that exists, every cell is a guaranteed NO-OP and a
measurement of the harness, not of paging.
