# T24 PROPOSAL — handoff-inject for `@ctxvm/ai-sdk` (library lane, control-path v-next)

**Date:** 2026-10-28 · **Lane:** kapitaali (ai-sdk + tests; opencode/hermes/node untouched)
**Size:** M · **Deps:** T22 (typed pause/resume + boot law), T23 (dir hygiene), UC1-VERIFY-CHECKS
**Commit law:** one commit (code + tests + gate + books), per the T22/T23 pattern.

## §1 Objective

Execute the design's gated **`handoff-inject`** beat (`design/uc1-plugin.md` §1.3(3),
§3 "Injection (opt-in, later)") in the lane where it is legally executable:
the library adapter. The beat: when a session resumes from a verified package,
**materialize the package's projection into the new session's assembled
context** — resident pages rendered full, stubbed pages carrying their
re-materialization instructions — instead of leaving the resumed session
observation-only. Today every resume in every lane is "observation, not
injection" (corpus/m6 + m7 READMEs): the operator reads the package and
rebuilds context by hand. The m7 session-b record IS the manual recipe
("rebuilt strictly from the 5 package artifacts, llms.txt-led"); T24
automates exactly that assembly and hands it to the app.

## §2 Survey facts this proposal is built on (probed 2026-10-28)

- **The package is content-blind for FULL pages.** `page.render` events carry
  `{page: {logicalRef, contentHash}, mode}` — no text (the tracer is a
  metering/decision witness by design; RFC-0). Resident-page CONTENT lives in
  the app's knowledge store. Therefore honest injection **requires an
  app-supplied resolver** — the library must never invent content (T22 law:
  the module only orchestrates).
- **The package IS self-sufficient for STUBS.** `page.evict` carries
  `stubText` — the exact text the model was told (spec 02-xcabi §table:
  "paging decision + what the model was told"). m1 thrash witness:
  `"[Paged out: read src/auth/session.ts (8.2k tok, 187 lines). Re-call
  read_file(...) to re-materialize.]"`.
- **The projection is typed and complete**: `page-table-N.json` =
  `{turn, slots: [{reference, kind, tokens, mode: "full"|"stub", pinned}],
  tally, violations}`.
- **The library's injection point exists and is provably mutable**:
  `transformParams({ params })` sees `params.prompt` (the messages array) —
  the exact mutation point the design names. The mirror law (params returned
  unchanged) is what injection must be gated against.
- **Design law**: the tracer remains read-only in every v0 surface; injection
  is "a separate, separately-gated control feature that mutates messages";
  plugin lanes gate via `CTXVM_FEATURES=…,handoff-inject` — the library lane's
  gate is the explicit API (T22 ruling); per-harness feasibility falls back to
  verify-only where impossible.

## §3 Proposed law — injection-as-DATA (v0), mutation deferred

**Boot (unchanged T22 law):** `resumeVerify(dir)` runs FIRST; unverified →
constructor throws. Injection arms ONLY from a verified boot.

**Assembly (new `resumeBrief` capability):** when armed, the capture assembles
the **resume brief** at boot from the package — a plain-text, llms.txt-led
block mirroring the m7 session-b manual recipe:

- header: snapshot digest, snapTurn, provenance line (from the T22 evidence);
- per slot, in page-table order: `mode: "full"` → materialized via the
  app-supplied resolver `(slot) => string | null` (content-blind law honored:
  the library renders the CONTENT THE APP RETURNS; resolver omitted/null →
  the slot degrades loudly to its stub text or an explicit
  `[unresolved: <logicalRef> — content not provided]` marker, never silently,
  never thrown); `mode: "stub"` → the slice's `stubText` bytes verbatim
  (package-complete, no resolver needed);
- footer: projection tally + slot counts.

**Delivery — the §7 Q1 ruling:** with injection-as-DATA, the capture exposes
`capture.resumeBrief(): string` and the APP prepends it to its own message
history. The middleware stays a byte-mirror in EVERY case — `transformParams`
keeps returning params unchanged, so the tracer-side mirror law and the
mutability-temptation guard are preserved intact (red-pinned). The design's
mutation-based injection (library mutates `params.prompt` under the feature
gate) is recorded as the v-next control shape, not built in v0. This resolves
the design's per-harness feasibility question for the library lane: the app
OWNS message assembly (its own message history), so no library mutation is
needed — injection here is the library doing the m7 operator's work and
handing over the result.

**No canon changes:** sidecar keys untouched (the brief is derived data, not
recorded state); no engine change (assembly reads the package the export
binary already produced); no corpus drop; witness lines at arm
(`resumeBrief assembled: N slots (M full, K stub), digest=…`).

## §4 What changes

- `packages/ai-sdk/src/uc1-handoff.ts` — NEW `assembleResumeBrief(dir,
  resolver?)`: reads the verified package's `page-table-N.json` + decompressed
  slice (zstd, the resume path's own placement law), extracts stub texts,
  renders the brief. Pure function of the package + resolver.
- `packages/ai-sdk/src/index.ts` — `createCtxvmCapture` gains `inject?: {
  materialize?: (slot) => string | null }`; verified boot + inject → build
  and hold the brief; `capture.resumeBrief(): string | null` (null when not
  armed/no resumeFrom). Boot-throw law untouched.
- `packages/ai-sdk/test/uc1-mirror.test.ts` — the test plan below.
- NO changes: rust engine, corpus, manifest/hub, opencode, hermes, node,
  sidecar canon.

## §7 Open questions (recommendations — I proceed on acceptance)

1. **Injection shape:** injection-as-DATA (`capture.resumeBrief()`, middleware
   stays a byte-mirror, mutation recorded as v-next) — RECOMMENDED — vs
   mutation-based middleware injection (the design letter; library mutates
   `params.prompt` per request under the explicit gate).
2. **Arming:** `inject: { materialize? }` option on `createCtxvmCapture`
   (explicit API, off by default — RECOMMENDED) vs always-on accessor.
3. **Resolver contract:** `(slot: { logicalRef, contentHash, kind, tokens,
   mode, pinned }) => string | null` — app-owned content; null → loud
   unresolved marker (RECOMMENDED) vs requiring the resolver (throw when
   content unresolvable).
4. **Brief format:** single plain-text block, llms.txt-led section layout
   mirroring the m7 manual recipe (RECOMMENDED).
5. **One commit** for code + tests + books (RECOMMENDED).
