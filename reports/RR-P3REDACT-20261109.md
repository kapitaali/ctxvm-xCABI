## The redaction card (verdict 2 — proposal-only, sidecar-first)

**Working title:** `redaction-block` (name to be ratified with the card). **Status:** PROPOSAL-ONLY.
**No wire change** in this option: nothing is added to the RFC-0/0.1 event field set, so the
five-touchpoints additive law is not exercised. **Placement request:** `design/redaction-block.md`
awaits owner clearance.

**Sidecar-first (the chosen first option).** The scanner already stamps its identity (scanner
SHA-256, scan-list version `w8-dq-v1`, UTC date) into every drop's `provenance.json`
(`tools/dq-secret-scan.py:18–21`; corpus drops each carry a `provenance.json` + `checksums.sha256`,
README table). A redaction record can live beside that stamp with no wire change: the artifact that
"describes its own redaction after leaving its corpus drop" is then the drop itself. **A session
field is only needed if a trace must describe its own redaction independently of its drop** — after
the trace leaves `corpus/<drop>/` without its sidecars. The card weighs both and stays sidecar-first;
wire-additive becomes an option only when a real consumer need is shown (the D13/DIFFNORM posture:
capture-side canonicalisation destroys harness faithfulness; the same conservatism applies here).

**Required properties (per the verdict, all proposal-only):**

1. **A stage LIST, not one stage.** Entries for capture, flush, export — each with `policyId`,
   `ruleSetVersion`, `stage`, and `replacedFieldCount` (aligned with Part II §9.1–§9.2's list shape,
   `:350–354`: one artifact can be redacted twice, and `Part II :340`'s release-minimum already
   expects "the redaction stages applied"). Stage semantics follow the paper's: capture replaces page
   content before declaration; flush rewrites content fields; export produces a third-party slice.
2. **Absence means "unknown," never "none."** An artifact with no redaction record says nothing
   about redaction — the v0.0-era corpus predates any block, so absence is provably not evidence of
   none.
3. **A reference policy.** One entry per rule set declaring how `logicalRef` was treated — enum
   `raw | keyed-hashed | dropped` — grounded in `RR-FIELDAUD-20261107` ("raw — the leak channel",
   `:44`; "raw, and the dominant surface", 112 raw `tool:` refs, `:65–71`; the m1 healthy fixture
   carries `file:src/auth.ts` raw). Today's value is `raw`, declared for what it is.
4. **The block is an assertion.** Without tamper evidence — not built (Part II §9.4 still reads "No
   verifier exists", `:364`) — the record is a claim by the writer, never a proof. The existing
   scanner is a pre-drop LINT, not a verifier (its own card says so: `RR-FIELDAUD-20261107:106–108`
   "pre-drop lint, not the draft's §9.4 verifier (no stage-list comparator, no third-party
   standard)") — that distinction stays explicit in the card so no "verified" escapes an
   unverifiable design.

**The reviewer's UNKNOWN, resolved as far as the books allow (no test sufficient to propose keyed
emission):** *is keyed-hashing refs consistent with page_id minting?* `page_id` is
`(logical_ref, content_hash)` as a `PartialEq/Eq/Hash` identity (`model.rs:14–22`). A deterministic
session/drop-scoped keyed hash preserves equality WITHIN one artifact — replay, rendering, and stub
semantics never parse the ref string, they only compare it — so minting stays internally consistent.
The costs are structural: (a) cross-drop joins break (the exact trade `environmentId` shows:
hashed + salted-by-worktree is why the env key cannot join across environments,
`RR-FIELDAUD:88–91`); (b) it collides with the consumer-side diff rule N1
(`design/diff-normalisation.md`): keyed refs are not comparable between artifacts, so raw-ref diffs
become intra-artifact only; (c) all frozen fixtures pin raw ref bytes, so any keyed EMITTER needs a
declared fixture-regen path. **Disposition:** the card proposes only the declaration enum; `raw` is
the shipped value; enabling `keyed-hashed` emission stays a future owner-gated card that must pass a
golden-vectors test BEFORE the proposal (the reviewer's precondition — met by not proposing a rule
yet, and the vector-set precedent is the pinning already on the books). `dropped` is listed as an
enum value for completeness.

**Falsifier (verdict 2):** a seeded-canary test — plant synthetic secrets and personal data in
fixtures; if the scanner's recall is low, "scan clean" cannot support "redacted" and the card must
say so (until the canary exists, "scan clean" claims only "the `w8-dq-v1` pattern list found zero
matches" — lint strength, exactly per FIELDAUD's distinction).

**Constraints carried from the packet:** spec/rfc-0 sealed; any wire field = additive RFC-0.1 card
(five touchpoints + negative) or a v0.2 design note, owner-gated; privacy law `08.1 §4` (redaction
DQ + secrets scan before anything leaves the machine) stays blocking; default-capture behavior

(`RR-FIELDAUD:84–87` notes its dictionary-attack caveat honestly; redacting it is out of scope for
this card — it is the page-identity half that replay consumes).

**Open (explicit UNKNOWN):** the canary test does not exist; the tamper-evident chain is not built
(Part II :500 lists it first among three pieces of work); no session field is proposed, so no
