## 2. Three defects, found by running rather than reading

**2.1 The probe's precondition read the wrong counter.** It required `engineSelections > 0`, which a
**one-turn probe can never have** — the keep law protects the whole request, so `_plan` returns early and
the plan says `fits`. The first probe therefore printed `NOT READY — engine never selected` on a healthy
session whose own sidecar said `fits` with `engineEntered 354`. Fixed: the paged precondition now reads the
plan (`fits`/`floor_bust` = asked and declined, with the numbers printed) and falls back to
`PARTIAL — entered but no plan` (a pre-0.13.24 build) or `NOT READY — never entered`.

**2.2 `--arms` did nothing.** `--arm` defaulted to **`paged`**, and the "a scoring run needs one arm"
override fired on every run — so `--arms naive` silently ran the paged arm. Reproduced twice: a run asked for
`naive`, the bundle and `session.json` both said `paged`. Fixed: `--arm` defaults to `null`, the probe branch
supplies its own default, and an explicit `--arm` still wins over `--arms`.

**2.3 `--limit` was appended and then discarded.** The T-B branch assigned `ctl = [...]` instead of
appending, so the limit vanished exactly for the task that needed it; a "limit 3" run executed all 49
prompts. Fixed (`ctl +=`), and the driver's dry run now honours `--limit` too (it printed 49 commands for a
3-prompt run, which read as if the limit had not taken).

## 3. Phase 1b — DATA-INVALID, twice, for two different reasons

**Attempt 1 (naive, 1 prompt, 120 s cap):** the model read `fixture/data-01.csv`, then **wrote a Python
script and called `tool:terminal` to run it**. The trace declares `tool:read_file`, `tool:write_file`,
`tool:terminal`. The profile carries `toolsets: [file]`, `hermes config get toolsets -p w8cn-naive` prints
`[file]`, and the root config carries `toolsets: [hermes-cli]` — yet a shell reached the model. The cell is
DATA-INVALID by the plan's own rule (a shell tool is a hard stop), and the model then burned its iteration
budget (12 tool calls, `Iteration budget reached (6/6)`) on one file.

**Attempt 2 (after pinning `-t file` on the creation call):** refused outright —
`Resume retains gateway session policy; creation overrides are unsupported on resume. -t/--toolsets differs
from this session's launch`. The `tb-pin1-naive` session was **created** by that very command and then
re-entered as a resume, so `--create-if-missing` + `-t` cannot pin a fresh session's toolset. 4.6 s, no
model call.

**So the surface cannot be pinned through this path today, and until it is, no T-B cell is evidence.** The
`-t` change is kept deliberately: it fails loudly instead of allowing a shell-reachable cell that would be
DATA-INVALID anyway. The next card is to find the key the `hermes chat` path actually reads —
`platform_toolsets.cli` is unset, the profile's `toolsets` is `[file]`, the root's is `[hermes-cli]`, and a
session still reached `terminal` — and to prove the pin from a capture (`page.declare.toolEffect` /
`logicalRef`) before any further cell.

## 4. What the free tier has cost, and what it has bought

Calls made: 2 (probe) + 1 (naive attempt 1) + 0 (attempt 2, refused) + 3 timeouts (paged, from the `--arms`
defect) ≈ 6 prompts, **$0.00**. What it bought: a live `enginePlan`, three fixed defects, and a hard answer
on the surface — all before a paid call.

The model's own arithmetic is still untested: both attempts failed on the *surface* or on the budget, not on
wrong counts. That question is exactly what phase 1b was built to answer, and it is still open.

## Addendum — the five background exits, the killed bundle, and what the salvage actually shows

Five runs were launched in the background; all five are accounted for here, because a killed run that
leaves no row is invisible evidence (the repo's own lesson from an earlier cell):

| bundle | exit | arm | outcome |
|---|---|---|---|
| `tb-1b` | 1 | paged | NO RECORD — prompt 1 timed out at 120 s (this is the run the `--arms` defect mis-targeted) |
| `tb-smoke` | 1 | paged | NO RECORD — prompt 1 timed out at 90 s |
| `tb-1b-naive` | **143** | naive | **killed by me** with a limit that had been dropped: 12 of 49 prompts ran, **36 prompt files, no `summary.json`** |
| `tb-1b-naive2` | 1 | naive | DATA-INVALID — shell reached, iteration budget 6/6 |
| `tb-pin1` | 1 | naive | DATA-INVALID — the `-t` creation override was refused in 4.6 s |

**The scorer was wrong before the model was.** The 12 replies in the killed bundle scored **0/48** and looked
like a total failure. Two parser defects, both measured on those real transcripts:

1. the host CLI wraps the answer in framing (echoed `Query:`, a resume hint, `Session:`/`Title:`/`Duration:`
   block), which a line parser counted as noise;
2. the same transcript hard-wraps, fusing two tuples into one line (`zeta 81 -390 32 9986theta 80 5054 131
   9956`) — a **correct** answer a strict token parser rejects.

`parse_reply` now strips the framing and matches the tuple grammar anywhere in the text (a CSV row cannot
match: it carries commas and one value, not four integers after a bare category word). Rescored:

| measure | value |
|---|---|
| files attempted | 12 of 48 |
| tuples parsed | **69** |
| of those correct | **69 — 100 % precision** |
| categories expected | 96 |
| coverage | **71.9 %** |

Per file, 5–7 of 8 categories were right; the misses are **omissions, never wrong numbers**. So on this
evidence the free model's arithmetic is sound and its replies are **truncated**: it stops answering part-way
through the category list.

**What that means for the next card.** The shape's obstacle is output completeness, not capability, so the
candidate fixes are: a smaller per-prompt output (fewer categories per prompt, or one file per prompt with a
compact single-line format), a per-file JSON write instead of prose, or a longer output budget. Any of those
changes the fixture/prompt digests and must be re-preregistered — and none of them is a cell until the
toolset pin is proven.

This reading is **not** a cell result: the run it came from is DATA-INVALID (a shell was reachable). It is a
capability reading on real transcripts, and it is recorded as one.
