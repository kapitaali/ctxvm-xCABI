## 3. The defect: the mode did not engage, and everything I could rule out

The paged session's plan block: `selectionMode: fresh`, `trigger: null`, with `budgetTokens: 24000` and
`budgetSource: settings` — i.e. the policy reached the engine (budget) but the mode did not.

Ruled out, each by a check rather than by argument:

| candidate | check | result |
|---|---|---|
| installed copy behind the repo | `cmp` | **identical**; `PLUGIN_VERSION 0.13.26` in both |
| profile-local plugin dirs running an old build | `is_symlink()` | they are **symlinks** to the shared install |
| env leaking a mode into the gateway | `/proc/<gateway>/environ` | **no `CTXVM_*` at all** |
| the clone losing the attribute | `__deepcopy__` | copies the whole `__dict__`; the meter and observer slots are the only shared ones |
| the policy not reading the key | direct call `policy(w8cn-paged)` | `engine: ctxvm, budget: 24000/settings, selectionMode: stable/settings` |
| the adoption logic not working | in-process host emulation (same plugin dir, `HERMES_HOME`, ABC stub) | adopts, and the plan reports `selectionMode: stable`, `trigger: held` |

The code path works outside the gateway and does not work inside it. Rather than infer further, the plan block
now carries **`policyMode`**, **`policyModeSource`** and **`modeExplicit`** (0.13.26, synced). The next capture
says which of the two it is: the policy dict lacked the key, or the adoption never ran. One paged prompt (~26 s,
free) answers it.

## 4. A runner bug found on the way (and fixed)

The first control attempt exited 1 in 3.5 s with `driver: need >= 10 prompts, have 1`. Cause: `run_arm` compared
`task is not TASKS["ta2"]`, and `task` is a **copy** of the table entry — so every ta2 run took the tb branch,
wrote a one-prompt file (the reconciliation prompt), and the driver refused it. Fixed to compare
`task.get("name") != "ta2"`. A failed run that cost 3.5 s and no model call; recorded because the same
copy-vs-identity mistake is invisible to the eye.
