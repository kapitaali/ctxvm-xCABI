# RR-T3 — Metric simulator reference implementation (Python)

**Card executed:** T3 (M) · **Date:** 2026-10-22

## What was done

- `benchmarks/metrics/metrics.py` — pure functions over parsed xCABI JSONL event
  streams, implementing `07`'s four formulas **verbatim**:
  - `net_tokens` → "net = rendered tokens + Σ estimated cache-miss cost
    re-normalization" (rendered = Σ `turn.render.residentTokens`; misses =
    Σ `call.meta.cacheEstimate.estMissTokens`)
  - `net_token_reduction(paged, naive)` = `1 - net(paged)/net(naive)`; single-trace
    mode recomputes the denominator from `counterfactual_naive()`
  - `fault_recall` = recovered_faults / **evictions** (07's exact denominator —
    not faults); "recovered" = the faulted page has a `page.render` **fact**
    (mode=full) at any turn > the fault turn
  - `touch_ratio` = touched_tokens / rendered_tokens (+ `waste` companion);
    v0 touch evidence = `page.fault` (the only recorded model-behavior surface)
  - `thrash_index` = mean faults-per-turn over the window's turns
    (zero-fault turns included); `--windows a-b,c-d` gives the P-pathology
    sustained-pressure windows; default = whole trace
  - undecided cases return **None** (JSON null) — never a fudged 0 or 1
    (no evictions, no turns, zero rendered, zero naive cost)
  - `counterfactual_naive()` — simulated no-paging baseline (same declares,
    same recorded miss estimates, every page full every observed turn),
    explicitly labeled an approximation in the docstring
  - CLI: `venvs/odps/bin/python -m benchmarks.metrics.metrics TRACE
    [--baseline FILE] [--windows SPEC]` → full JSON stats
- `benchmarks/metrics/fixtures/` — two synthetic sessions (card taxonomy),
  **both replay-consistent and fully schema-valid** (see Verification):
  - `session-healthy.jsonl` (12 events): 3 pages (700+8200+60 = 8960/turn),
    3 full turns, one resident-page touch (summary, `identifier_scan` fault),
    one `call.meta` (200 est. misses)
  - `session-thrashing.jsonl` (41 events): A=1000 / B=400 under 6000 budget;
    all 20 `page.render` facts + 10 `turn.render` receipts recorded so the
    fact-coherence and recovery accounting are mechanically checkable;
    4 evictions (B@1 B@4 A@5 B@8), 3 faults (B@2 B@6 A@9), A never recovered
- `benchmarks/metrics/test_metrics.py` (~140 lines) — 18 tests: hand-summed
  expectations for both fixtures + edge suite (empty trace, zero-rendered,
  unknown-page touch dedupe, unanchored fault turns, strict-JSONL fixture text)
- `tools/setup-env.sh` — pytest added to venv A (additive; card DoD runs
  `python -m pytest`); re-ran script: both venvs still grep-green + verify-green
- `spec/rfc-0/validate_schema.py` — now accepts extra CLI paths so ANY future
  xCABI JSONL (e.g. these benchmark fixtures) rides the same conformance gate

Hand-arithmetic check (thrashing): resident series [1400,1000,1000,1400,1000,
0,0,400,0,0] = 6200; misses 300 → net 6500. Naive = 10×1400 + 300 = 14300 →
reduction = 1 − 5/11 = **6/11 ≈ 0.545455**. Recall = 2 recovered (B@2→full@3,
B@6→full@7) / 4 evictions = **0.5** (A@9 never re-rendered; B@4 evicted
faultlessly — an eviction with no fault, which is exactly why 07's denominator
is evictions, not faults). Touch = (1000+400)/6200 = **7/31**. Thrash = 3/10.

## Discoveries

1. **Hand-sum lesson (process, not math):** the plan-phase expectations were
   authored BEFORE checksumming the fixture, and were wrong (7200 vs true 6200
   rendered). Tests then failed against the fixture — correctly. Fix: expectations
   recomputed from the committed fixture. The fixture was never bent to match
   the tests. Rule going into M1: **author fixture arithmetic first, then write
   the test's expected numbers from a written ledger.**
2. **07's `net` has a terminology tension:** invariant text says costs must
   "subtract estimated cache misses", the formula block says `net = rendered +
   Σ misses re-normalization`. Implemented the formula as written (additive) and
   the estimator+misses are reported separately (`estimatedMisses` field) so a
   consumer can re-derive either reading. Stamped as a documented interpretation.
3. **v0 touch proxy:** xCABI v0 has no read/touch event; `page.fault` is the
   only recorded model-behavior surface (tool_recall / identifier_scan /
   explicit_api / semantic). `touch_ratio` therefore uses Σ declared tokens of
   DISTINCT faulted pages. `page.touch`-style receipts are parked for RFC-1
   (gap recorded, not invented).
4. **Recovery must read FACTS, not the derived schedule:** fault@t schedules a
   full@t+1, so a derivation-based recall would be 1.0 by construction
   (meaningless). Using recorded `page.render` full facts makes recall a real
   measurement (our 0.5 fixture exercises it) and dovetails with T1d's
   divergence detection (a fault followed by NO full fact = a trace that either
   diverges per-derivation or honestly never re-materialized).
5. **Thrash windows:** P-pathology defines pressure windows, so `thrash_index`
   denominator = turns INSIDE the window (zero-fault turns included) — mean
   faults-per-turn is a rate over exposure, not over faulted turns.
6. **Counterfactual honesty:** a single-trace baseline can't be recorded data;
   it is clearly labeled `counterfactual-no-paging` vs `recorded:<path>` in the
   CLI output. 07's harnesses (naive vs tracer) will supply recorded baselines
   in M1 for real numbers.
