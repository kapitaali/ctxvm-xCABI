## 3. NEW FINDING — the MCP's default calibration is the SUPERSEDED v2 map

`calibration_info` (no argument) returned `/home/theb/Documents/umpire/calibration/umpire-cal-v2.json`
— **data_version `cal-v1:aceb881587b3b3a6`**, test ECE 0.026684, Brier 0.172292, accuracy 0.708333.
The calibration OF RECORD is **v3** (`cal-v1:057a5a35a9d4ec71`; named as the record in umpire
`00-SPEC.md`; `calibration/cal-precision-v3.json` ECE 0.030163; produced by the quiescent recapture
`RR-M3V3-20261024`; used by the umpire repo's own `spec/calibration_ci.py:38`,
`spec/test_packaging.py:33`, `spec/transfer_eval.py:35` and the ODPS/ODCS plan).

This is NOT a stale label on an identical map — the two fitted artifacts differ in substance
(key-by-key diff): `isotonic.points` differ, `raw_sha256` differs (`5649d7bd…` → `8ecbd6ee…`),
`provenance.git_head` differs (`64f9132c…` → `afa9c66b…`), `selection` (temperature 5.8317956 →
5.8224421) differs, and the test metrics differ (calibrated ECE 0.026684 → 0.030163; Brier 0.172292 →
0.172597; raw-entropy ECE 0.210984 → 0.210593; raw-top ECE 0.248294 → 0.247289; accuracy 0.708333
unchanged, n=120). The magnitudes are inside the noise the books already flagged (RR-M3V3:94 — "the
calibrated ECE, the calibrated Brier and the accuracy are each within noise"), but the MAP is a
different map and the DATA VERSION STAMP is a different stamp.

Where the default comes from — and it is not the code: `mcp_server.py:54` has **no** artifact default
(`DEFAULT_CALIBRATION = os.environ.get("UMPIRE_CALIBRATION") or None`); the value is injected by the
launcher environment. The three running `mcp_server.py` processes (started 12:20) carry
`UMPIRE_CALIBRATION=…/umpire-cal-v2.json`, and the launcher is the hermes gateway config:
`~/.hermes/config.yaml:2114` (and the same line in the arm profile `~/.hermes/profiles/w8bo-paged/
config.yaml:2115`). **Consequence:** any MCP consumer that takes the default calibration is served
the superseded map, so a row it produces does not carry the record's `data_version` and its
calibrated confidence is not the record's mapping — the MCP, as configured, cannot reproduce the
calibration of record. **Fix:** one config line (point at `umpire-cal-v3.json`) plus a gateway
restart. **Not done here:** `~/.hermes/**` is the hermes lane's territory and the umpire repo is
read-only from this lane; the change is owner-routed (recorded as board item U6).
