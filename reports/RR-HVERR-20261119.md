# RR-HVERR-20261119 — erratum to RR-HVREV: the "null" diagnosis was a probe error; fix confirmed live

## 1. The correction

`RR-HVREV` §1 claimed the 0.13.28 metadata fallback "returned **None** in the actual runtime." That is
**wrong.** A real capture flushed by the 0.13.28 gateway —
`~/.local/state/ctxvm/traces/local-f913ef14….meta.json`, `pluginVersion 0.13.28`,
`harnessVersion "0.21.5"`, captured 22:50 — shows the gateway **did** resolve the metadata, to a
**stale pip dist (0.21.5)** that sits on the gateway's `sys.path`. The true running install is the git
source **0.23.2**. So the 0.13.28 defect was **wrong version**, not null.

**Why the miss:** the bare-interpreter probe (`<gateway-python> -c "importlib.metadata.version(…)"`)
raised `PackageNotFoundError` because it did not replicate the gateway's full runtime path. The disk
capture is authoritative; the probe was not. Same lesson as before, one level deeper: measure the
object that does the work, in the runtime that runs it — a stripped-down probe is not that runtime.

**The fix direction was still correct:** the canonical resolver `hermes_cli.version_info` reports the
*running* git version (0.23.2), not the stale dist (0.21.5). 0.13.29 stands.

## 3. Test-leak found and fixed (test-only)

Verification surfaced `hv-*` synthetic captures in the real trace dir. Root cause: `register()`
captures the state dict in a closure and registers `atexit(_flush_traces)`; the exit-flush uses that
**stale closure dict** (still holding the test's tracers) while `_active_trace_dir()` re-resolves to
the **default real dir** after `_clear_env_for_tests` deletes the live state. Reproduced
deterministically (a write-spy caught the exit-flush writing `hv-can/meta/env` to the real dir).

Fix: `_SmokeBase._drop_tracers` cleanup clears the plugin's tracers before teardown, so the exit-flush
has nothing to write. Verified: full `test_capture_smoke.py` (13 tests) and the whole hermes suite run
with **zero** `hv-*` writes to the real dir. The already-leaked `hv-*` artifacts were removed (exact
dir, `hv-*` prefix only; no real `local-*` capture touched).
