# RR-T1c — Page table + deterministic renderer

**Card executed:** T1c (L) · **Date:** 2026-10-22

## What was done

- `ctxvm-core` implemented:
  - `page_table.rs` — `Playback` streaming page table keyed by `(logical_ref, content_hash)`;
    per-page `PageTrack` render-mode state machine; telemetry-first `Violation` ledger
    (8 kinds: duplicate declare / unknown-page decision / evict-while-pinned / evict-while-stubbed /
    fault-of-resident / duplicate fault / unpin-of-unpinned / content-attach guard);
    max-pins counting; content attach (first-wins, immutable per page key)
  - `render.rs` — `Slot` / `TurnTally` / `TurnProjection` + `derive_projection(trace, turn)`
    pure function; stub slots carry the **verbatim** `page.evict.stub_text` + declared
    full-size tokens; consistent canonical serde (`camelCase`) output incl. manual
    `Violation` serialization
- `ctxvm-core/README.md` (≈55 lines) — semantics: page key, effect timing table,
  change ordering rule, violation list, determinism boundary, v0 limits.

## Locked semantics documented (feeding RFC-0; deviations/extensions vs 02 draft)

1. **Effect timing table — the core spec decision of this card:**
   `page.evict@t` → stub visible AT turn t · `page.fault@t` → full from turn t+1
   (fault is discovered observing turn t's output; re-materialization at next boundary).
   This is consistent with the T1b golden corpus (evict@1 + stub render@1).
2. **Change ordering rule:** mode at turn t = latest `(effective_turn, stream_seq)` with
   turn ≤ t; stream seq breaks same-turn ties. Required, stated, and tested —
   malformed traces must still replay deterministically.
3. **Transcript shape stability** (02 invariant 3) rendered concretely: v0 slots list
   EVERY declared page each turn — evicted pages keep their slot, holding the stub
   (paging swaps content↔stub; shape never changes).
4. **pin/unpin have no effective turn in v0** — slot `pinned` flag = latest stream
   state. Flagged for RFC-0 (draft should add turn).
5. v0 renderer scope: page-layer projection only (not provider raw messages) —
   recorded in crate README.

## Deviations from card

- Violation ledger extended beyond the draft's implicit set (duplicate fault,
  content-attach guard): the draft names no invalid-event semantics; v0 pins them
  down because a determinism standard cannot leave them undefined.

## Discoveries (feeding T1d/RFC-0)

1. `Vec::split_off` trap: using it to partition "new violations" silently REMOVED
   the entries from the table — feed_all then lost the whole ledger. Caught by the
   scenario tests (S2 passing with an empty-assert masked it initially). Fixed with
   slice-copy (`[before..].to_vec()`). Lesson: state-retention semantics must be
   tested with a NON-empty expected ledger (S3 does this permanently).
2. Ordering-rule choice is real spec content: the naive "last stream event wins"
   rule allows an oddly-ordered re-evict to override a scheduled t+1 re-materialize.
   Locked rule instead: effective-turn dominates. Must be stated in RFC-0.
3. Repetition semantics: a repeat evict of a stubbed page rewrites the stub text
   (latest stream evict wins as "what the model was told") and logs once per
   offending event — the ledger counts events, not states.
