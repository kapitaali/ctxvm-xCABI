**The four plan corrections, applied.** Strict names with no alias map (so `"read"` in the old
fixtures classifies `MUTATING` — the fail-safe outcome, now asserted as such); the host's verified
bucket as the only default, with the degeneracy measured rather than assumed; the env var as an
extension, never the mechanism (both lanes classify with zero `CTXVM_*` set); and one signature per
event type with an explicit optional-key set, because a mixed run legitimately has two `page.declare`
shapes.

The value test is the one that matters: it drives the real adapter hooks for `read_file`,
`search_files`, `terminal` and `read`, then asserts on the wire that the first two are `READ_ONLY`
and the last two `MUTATING`. A keys-only parity test would pass while every page read `MUTATING`;
that is the failure mode this test exists to prevent.

## 3. Measured split (the degeneracy, as a number)

Regenerated fixtures, by construction:

```
hermes live-echo    READ_ONLY 2 / MUTATING 1   (the beats emulate read calls)
ai-sdk echo-thrash  READ_ONLY 0 / MUTATING 1
conformance vector  READ_ONLY 1 / MUTATING 0
```

These numbers describe fixtures, not sessions. A real Hermes session calls `terminal`, `write_file`,
`patch`, `browser_*` and the delegation tools far more often than the two read tools, so the expected
live split is heavily `MUTATING`. **Not yet measured on a live capture** — the gateway must restart
to load 0.5.0. Until it does, the honest statement is: the field is wired, its values are asserted in
tests, and its real-world distribution is unknown.

## 4. Not claimed

- No write-ahead log, no dry-run execution, no replay safety for mutating calls. The class says what
  a tool *can* do, not what this call *did*.
- The Hermes table covers two tools. It is a verified floor, not a taxonomy.
- Classification is by exact registered name. Aliases (`read` for `read_file`) deliberately do not
  resolve; they classify `MUTATING`.

## 5. Deviations from the plan of record

- The plan's §S12 asked for a per-kind signature rule. Implemented instead as an explicit
  **optional-key set** (`OPTIONAL_EVENT_KEYS`) with a value check, because the fixture run passes
  through the tracer directly (no adapter, so no class) while a live run always tags. Both shapes are
  legal; a per-kind rule would have forced the fixture to fake an adapter.
- `CTXVM_READONLY_TOOLS` was added to opencode and ai-sdk only. The Hermes lane classifies from the
  host bucket alone; an env extension there would be a second source of truth for a table that
  already has one.

## Correction (2026-11-03)

This report says the plugin was bumped to 0.5.0. It was not: `PLUGIN_VERSION` read `0.4.1` at the
time, and the edit that was supposed to change it searched for `0.4.0`, so it matched nothing and
reported success without checking. `plugin.yaml` and the constant agreed throughout — both were
`0.4.1` — so nothing was inconsistent, only unchanged.

The real bump is **0.7.0**, made with the `/ctxvm-help` card, and a test now asserts that
`plugin.yaml` and `PLUGIN_VERSION` agree. A version number that silently does not move is the same
failure class as a gate that silently does not run.
