# RR-STREAM-20261103 — the view W14 promised: sessions grouped by environment

**Card:** the second half of W14 (`08.1-UPDATE-PROMPT.md` §W14: "Provide a stream view that orders
sessions by time within an environment"). **Status:** landed; `ALL GATES GREEN`. No schema change.

## 1. What was missing

W14 shipped `session.open.environmentId` and stopped there. A grouping key nobody reads is a field,
not a measurement: the reason to carry it is the question it unlocks — what a repository's sessions
repeat, and whether the same content is re-declared session after session.

## 2. What landed

`ctxvm stream <dir|file>... [--json]`, sixth binary beside `replay`, `profile`, `diff`, `export`,
`tokens`. Per session: start time, turns, declared pages, pages a render actually showed, declarations
no render showed, faults, resident tokens. Per environment: a summary line with sessions, turns,
declarations, **declarations repeated across sessions**, and faults.

Determinism: grouping is a `BTreeMap`, the row order is `(environment, started, file)` with known
environments first and `(unknown)` last, and the JSON emits keys alphabetically. Two runs over the
same files agree byte for byte; nothing here reads a clock or a hash seed.

Deliberate limit: `unrendered` counts declarations no `page.render` showed. That is an **upper
bound** on unused content, named as such, not "waste" — the honest-waste work in `benchmarks/metrics`
already owns that word.

## 3. First real output, and what it already shows

Over the live trace directory (six sessions, all `(unknown)` because the hermes lane cannot derive an
environment id — W14 documented exactly this):

  -                      117    156    156        0     156        65277  ctxvm-dev.jsonl
  2026-11-03T08:08:57Z     4     91     91        0      93        46536  local-eea604e2….jsonl

Three declarations repeat across sessions. That is the first cross-session number this repo has
produced, and it is small precisely because the grouping key is absent on that lane — which is the
argument for fixing the Hermes side, not for trusting the number.

## 6. Not claimed

- No waste metric: `unrendered` is an upper bound, and the paper's cost questions need the `prefix`
  record (W13) to be combined with this view — not done here.
- No controller, no policy, no savings.
- The live numbers above are one machine, six sessions, hermes only, with no environment id. They are
  a smoke test of the view, not a measurement of anything.

## 7. Open

- Hermes still cannot derive an environment id (the gateway does not disclose the workspace). Until an
  operator registers `CTXVM_ENVIRONMENT_ID`, every hermes session lands in `(unknown)` — visible in the
  output above rather than hidden.
- A per-environment repetition count is deliberately page-level (logicalRef + hash). Tool-call-level
  repetition — the paper's 12–28% of bytes — needs `callId` (W16 option B) and is not attempted.
