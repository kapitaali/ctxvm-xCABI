# 第三部分——上下文轨迹能为自我改进循环提供什么

**作者：** Kapitaali · **版本：** 1.1，2026 年 11 月 18 日 · **状态：** 供审阅的草稿
**第一部分：** *用于 LLM 智能体上下文的虚拟内存：xCABI 标准与 ctxvm 引擎。*
**第二部分：** *上下文轨迹能说明什么、不能说明什么——关于 AI 安全。*

---

## 摘要

本文问一个问题：上下文轨迹能为构建自我改进的 AI 模型贡献什么？答案很窄。ctxvm 不训练权重。
它没有奖励模型，也无法访问模型内部。它提供的是输入侧：对编排器请求的可移植记录、页表投影的
确定性重放，以及带有因果主张所需溯源信息的页面级反事实干预。循环仍需要生成器、评估器、
选择器和更新步骤。ctxvm 强化其中两个部分——**评估器**（版本化视图）和**训练数据选择器**
（来自页面消融的因果标签）。它不强化生成器或权重更新。本文描述六条路线，每条都有机制、
被改变的对象、证伪条件和实验。没有任何路线被运行过。依赖片段的论断标记为未核实，不承担论证。

## 1. 范围与术语

### 1.1 定义术语

| 术语 | 本文中的含义 |
|---|---|
| 自我改进 | 一种循环，它改变系统，使后续版本在保留任务上得分更高。改变可以发生在权重、模型外部的策略或数据中。 |
| 循环 | 生成、评估、选择、更新、重复。 |
| 被改变的对象 | 某条路线更新的东西：策略、排序器、训练数据、评估器或权重。 |
| 页面 | 带有 `(logical_ref, content_hash)` 标识、类别和 token 计数的上下文单元。 |
| 干预重放 | 在已记录轨迹中改变一件事，然后再次调用模型。引擎是确定性的，模型不是。 |
| 监控视图 | 轨迹与其来源及遗漏记录的连接，带有版本，给出监控器所见的数据（第二部分 §1.1）。 |
| 遗漏缺口 | 移除策略丢弃的页面不在密封 v0 线路上；轨迹将其声明为完整，而请求中并无该页面（第二部分 §2.4）。 |
| 刷新尾部捕获 | 一类轨迹，其 `page.declare` 和 `page.render` 行全部位于 `turn.render` 块之前，因此按位置的轮次切分会包含来自后续轮次的声明。此时派生表不按轮次限定（第二部分 §2.4）。 |
| 预算项 | 上下文目标中的成本部分。没有它，"全部保留"就能平凡地最小化故障。 |
| 噪声底线 | 两次未改变运行之间的答案变化率。 |

| 等级 | 含义 |
|---|---|

## 2. 问题与简短回答

**问题。** 上下文轨迹能为自我改进模型贡献什么？

**简短回答。** 把 ctxvm 用作现有循环周边的测量与数据生成层：

1. 生成**因果标签**。从开放权重模型开始：留一法作用于输出概率，仅需计算（第二部分 §12.1）。
   托管模型用于行为，需设置噪声底线。
2. 把**故障事件用作选择特征**，而不是独立的策略目标。故障告诉我们消融时应测试哪些页面；
   它无法离线评估一个新策略。
3. 给评估器加版本。视图是轨迹与来源及遗漏记录的连接。两个模型版本可针对同一视图版本打分。

ctxvm 不执行更新。团队仍需训练排序器、策略或数据选择器。第一部分 §16 和第二部分 §10 限定了
轨迹能支持的内容。

## 4. ctxvm 提供什么

第一部分 §2–3 定义线路格式；§3.8 引擎；§10 干预重放；§12 监控视图。

| 能力 | 机制 | 对循环的价值 |
|---|---|---|
| 页面标识与哈希 | `page.declare` 携带 `(logical_ref, content_hash)`、类别、token 计数 | 跨运行、跨模型版本的稳定键 |
| 确定性推导 | 渲染器从事件推导页表；相同字节在单一机器和构建上给出相同投影 | 可复现基线（限定范围） |
| 故障事件 | `page.fault` 带来源；含义取决于捕获表面 | 选择特征，不是过程真值（§4.1） |
| token 核算 | `turn.render` 携带 resident、evicted 和余量 | 上下文压力 |
| 干预重放 | 移除、存根化或替换页面，调用模型 | 页面粒度的反事实标签 |
| 噪声底线协议 | 基线对基线；每臂多个样本 | 把效应与采样噪声分开 |
| 六部分溯源 | 摘要、干预、采样、模型快照与日期、编排器版本、分词器 | 可复现、可引用的运行 |
| 版本化视图 | 轨迹与来源及遗漏记录的连接 | 跨版本的可比评估器 |
| 导出与 diff | ODPS 工件；`ctxvm diff` 比较轨迹 | 版本化数据 |

### 4.1 格式不记录什么

- 轨迹保存标识与哈希，不保存页面内容。
- 渲染一个页面不构成答案的原因。只有干预支持因果主张。
- 托管模型在固定设置下也不是确定性的。单次抽样不是效应。
- 密封 v0 没有表示无存根页面移除的动词（第二部分 §2.4）。
- 对移除策略，`turn.render.evictedTokens` 在 v0 中记录但不检查（第一部分 §7）。
- 付费分页单元成本是对照的 2.11 倍。不声称节省成本（法则 7）。

## 5. 循环需要什么

循环有四个部分。更新是作者的公式，不是引用来源：

$$
M_{t+1} = U\bigl(M_t,\; E_t(G(M_t, D_t)),\; D_t\bigr)
$$

这个公式给出**三类失效点的分类法**：生成器可能没有产生有用变化；评估器可能把噪声排成信号；
更新可能改变错误的对象。

### 5.1 路线与对象映射

| 路线 | 被改变的对象 | 贡献类型 |
|---|---|---|
| A——故障驱动的消融选择 | 训练数据选择器 | 选择要消融的页面 |
| B——反事实页面消融 | 页面排序器／数据过滤器 | 真值因果标签 |
| C——轨迹依据的批评 | 会话内上下文使用行为 | 针对结构而非内容的批评 |
| D——主动选择 | 训练数据选择器 | 选择困难轨迹供标注 |
| E——版本化视图 | 评估器 | 跨版本可比分数 |
| F——编排器摘要 | 上下文策略（编排器侧） | 压缩请求 |

## 6. 路线

每条路线陈述机制、被改变的对象、输入、输出、成本和证伪条件。

### 路线 A——故障事件作为消融选择特征

**陈述。** 用故障事件和触碰计数选择路线 B 中要消融的页面。

**机制。** 故障只在已记录的策略下被观察到。新策略的故障需要反事实运行。因此故障标签无法离线
评估策略。转而用它分层消融样本：`tool_recall` 故障或指向非常驻页面的 `identifier_scan` 提及
所命名的页面是候选。目标必须包含预算项
$\max_{\pi}\; I(\text{answer}; \text{pages}\mid\pi) - \lambda\,\text{tokens}(\pi)$；
没有 $\lambda$ 时，"全部保留"就能平凡地最小化故障。由于已渲染页面上的 identifier-scan 故障
接近定义性（第一部分 §17），需要对照。

**被改变的对象。** 路线 B 的训练数据选择器。**输入。** 轨迹、触碰计数、故障。
**输出。** 分层消融列表。**成本。** 计算；路线 B 的调用另计。
**证伪条件。** 故障分层消融在预测答案变化上不优于匹配的随机消融。
**证据。** 第二部分 §12.1（触碰率）；第一部分 §4、§17（故障、定义性）。*推断*。

### 路线 B——反事实页面消融

**陈述。** 把每个页面变成因果重要性标签。这是仓库现在能运行的第一步，因为开放权重臂只需计算。

**机制。** 开放权重为主：按第二部分 §12.1 定义的输出概率留一法。托管为辅：移除页面 $p$，
再次调用模型，使用多个样本和基线对基线噪声底线。三个样本时二元答案变化标签只有四个取值，
噪声底线同样粗糙；对变化率使用二项区间，而不是硬阈值。**只学一个对象**：页面排序器／
训练数据过滤器。消融重要性不是步骤正确性，因此不能得出过程奖励模型。

$$
\Delta(p) = \frac{1}{n}\sum_{i=1}^{n} \mathbb{1}[a_i(\tau) \neq a_i(\tau\setminus p)],
\qquad \hat c(p) = \mathrm{BinInt}(\Delta(p), n, \alpha)
$$

**被改变的对象。** 页面排序器／数据过滤器。**输入。** 冻结轨迹、开放权重模型、托管模型（辅臂）。
**输出。** 页面粒度的因果标签。**成本。** 开放权重：仅计算。托管：约 **1,300 次调用，约 11.37 美元**，
按仓库混合费率 0.00861 美元／请求（`reports/W8-SPEND.md:82`）：
$(20 \times 10 \times 3 \times 2) + (20 \times 3 \times 2) = 1{,}320$ 次调用。
**未核实的估算**；引用前核对收据。
**证伪条件。** 用消融标签训练的排序器在保留任务成功上不优于随机消融。
**证据。** 第二部分 §12.1 定义了该设计；交叉引用，不要复制。ContextCite（Cohen-Wang 等，
arXiv:2409.00729，摘要）是句子级的相关工作。

### 路线 C——用于上下文使用的轨迹依据批评

**陈述。** 用投影作为批评输入，改变**上下文使用行为**，而不是答案正确性。

**机制。** 把模型的页表、故障、token 总量和请求的估计大小交给模型。请它修订工具计划。
轨迹不含内容，因此批评可以改变重读、故障和完成所需步数；它无法提供缺失内容。测量这些行为。
带轨迹的错误答案语料、constitution 和 SFT 成本**不在仓库中**；因此权重更新处于被阻断状态
（第二部分状态），该路线停留在会话内。

**被改变的对象。** 上下文使用行为。**输入。** 轨迹、会话内批评。**输出。** 批评数据集与行为测量。
**成本。** 生成需要游戏调用；SFT 未定价。
**证伪条件。** 投影支持的批评在每轮故障数或完成步数上不优于普通批评。
**状态。** 权重步骤被阻断；会话内步骤可原型化。

### 路线 D——从上下文指标主动选择

**陈述。** 用 ctxvm 指标和路线 B 的标签选择困难轨迹供标注。

**机制。** 计算 thrash index、refetch rate、net token reduction 和 touch ratio。选择高压力或
高故障密度的轨迹。需要真值时使用路线 B 的标签。把选出的步骤交给评判器，重新训练选择器。
这不依赖未核实来源：Goldilocks Selection（Mindermann 等，2021-07-06，摘要）报告"恰到好处"
的点优于困难、简单和不确定的点。

**被改变的对象。** 训练数据选择器。**输入。** 轨迹、指标、评判器。**输出。** 选出的集合。
**成本。** 评判时间。**证伪条件。** 用 ctxvm 指标训练的选择器在相同标注预算下不优于随机选择。
**证据。** Mindermann 等（摘要）；第一部分 §6 指标。*推断*。

### 路线 E——版本化监控视图作为评估器

**陈述。** 让评估器成为带版本的对象。

**机制。** 把 $V_k$ 定义为轨迹与来源及遗漏记录的连接（第二部分 §1.1）。在一个语料上用一个
视图版本给各模型版本打分。视图和评分规则不进入智能体上下文。三个版本无法支持显著性主张；
使用至少十个版本，或把三版本结果报告为描述性配对比较，而不是推断。

**被改变的对象。** 评估器。**输入。** 语料、来源、视图函数。**输出。** 可比分数。**成本。** 计算。
**证伪条件。** 视图分数在版本集合上不预测保留任务指标。
**证据。** 第一部分 §12；ImpossibleBench 和 SLEIGHT-Bench（摘要）说明评分器会被利用。

### 路线 F——编排器侧递归摘要

**陈述。** 在页面边界压缩长请求——在编排器中，而不是从轨迹中。

**机制。** 摘要前缀需要页面内容，而轨迹不保存内容。这是编排器策略。W8 对照臂中的标准压缩器
可能已经在做摘要；这是**未知**，在定义任何臂之前必须核查。E5 使用现有的 W8 配置，而不是新功能。

**被改变的对象。** 上下文策略（编排器侧）。**输入。** 长轨迹、W8 配置。**输出。** 压缩策略比较。
**成本。** 计算加现有模型调用。**证伪条件。** 摘要策略在相同上下文预算下不优于简单截断。
**证据。** Wu 等（2021-09-22，摘要）提供类比，不是方法。

### 6.1 路线汇总

| 路线 | 被改变的对象 | 新增模型开销 | 可证伪 |
|---|---|---|---|
| A——故障选择 | 训练数据选择器 | 无（供 B 使用） | 是 |
| B——页面消融 | 排序器／数据过滤器 | 开放权重：无；托管：约 1,300 次调用 | 是 |
| C——轨迹批评 | 上下文使用行为 | 游戏调用；SFT 未定价 | 是，仅会话内 |
| D——主动选择 | 训练数据选择器 | 评判时间 | 是 |
| E——版本化视图 | 评估器 | 无 | 是，需 ≥10 个版本 |
| F——编排器摘要 | 上下文策略 | 现有 W8 配置 | 是 |

## 7. 护栏

1. **效应之前先有噪声底线**（第一部分 §10）。
2. **每臂多个样本**；使用区间，而不是硬阈值（第一部分 §10）。
3. **六部分溯源**（第一部分 §10）。
4. **分开确定性重放与模型驱动运行**——不共享目录、校验文件或主张。
5. **内容盲**：不要训练模型从轨迹恢复页面内容。
6. **不从渲染得出因果**；只有干预支持因果主张。
7. **隐藏评分器**（ImpossibleBench、SLEIGHT-Bench）。
8. **包含预算项**；"全部保留"不是结果。
9. **用第二部分的词汇标记未核实来源**；它们不承担论证。
10. **记录否定结果**及其证伪条件。
11. **不声称节省成本**（法则 7）；付费单元是对照的 2.11 倍。

## 8. 失效模式与风险

| 失效 | 信号 | 应对 |
|---|---|---|
| 自我修订中的奖励劫持 | 评判器分数上升，保留任务持平 | 隐藏评判器；不可能对照（Pan 等，2024-07-05，摘要） |
| 上下文奖励劫持 | 反馈循环在单会话内改变行为 | 分开反馈轮次与评估轮次（Pan 等，2024-02-09，摘要） |
| 故障标签是定义性的 | 故障率跟随提及率，而不是需求 | 使用 `tool_recall`；加入匹配消融（路线 B） |
| 遗漏缺口 | 表中显示请求未携带的完整页面 | 第二部分 §2.4；提供方收据；不要推断内容 |
| 评估器被规避 | 监控器遗漏隐蔽行为 | SLEIGHT-Bench 式测试（摘要） |
| 优化视图而非任务 | 视图分数上升，保留指标持平 | 证伪条件触发，停止该路线 |
| 作者错配 | 训练集中有错配人物的论文 | 筛选 `author_match = confirmed` |

**能力提升风险（第二部分）。** 上下文管理是一种能力。改进页面选择的循环也可能改进破坏：
学会保留哪些页面的智能体也学会了监控器看到什么。在运行任何路线之前，加入第二部分的能力
提升检查——该改变是否同时改善有害任务与良性任务？——并对每一次权重或策略更新保留**人工闸门**。
能力提升检查为负时停止该路线。

## 9. 实验设计

每个设计都写出单位、样本量、裕度和命令。所有设计在首次调用前预注册；结果后的修改是偏差，
必须记录。

### 9.0 E0——开放权重页面消融（路线 B 主臂）

- **问题。** 页面级因果重要性是否优于匹配的随机消融？
- **数据。** 20 个提示；一个冻结模型快照；每条轨迹 10 个页面。
- **臂。** 基线；基线重复；逐页留一；匹配随机页面。
- **主要指标。** 触碰计数与对数概率变化的秩相关，跨提示给出置信区间。**单位：** 相关系数。
- **样本量／裕度。** 20 个提示的区间较宽；报告它，而不是声称显著性。需要更窄区间时用 40 个。
- **命令。** 第二部分 §12.1 协议；交叉引用，不要分叉。
- **停止规则。** 区间包含零 → 否定结果。

### 9.1 E1——故障可用性与标签质量（路线 A，零开销）

- **问题。** 每个来源有多少故障？它们是否命名页面？
- **数据。** 仅冻结语料（15 个含故障的路径；41 个 `identifier_scan`，21 个 `tool_recall`）；
  以完整路径为单位，绝不按文件名扁平化。
- **指标。** 按来源计数；被故障页面仍常驻的比例。**单位：** 事件。
- **命令。** 对 `corpus/m*/**/*.jsonl` 做 JSON 解析；用 `sha256sum` 生成清单。
- **停止规则。** `tool_recall` n < 10 → 标签质量不足，路线 A 被阻断。

### 9.2 E2——带区间的托管消融（路线 B 辅臂）

- **问题。** 开放权重效应能否迁移到答案变化？
- **数据／臂。** 20 个提示，10 个页面，每臂 6 个样本，基线两次。
- **主要指标。** 答案变化率的二项区间。**单位：** 比例。
- **成本。** 约 1,320 次调用；约 11.37 美元（0.00861 美元／请求，`reports/W8-SPEND.md:82`）；未核实估算；核对收据。
- **命令。** 第二部分 §12.1 托管协议，使用上述参数；预注册模型快照与种子。
- **停止规则。** 区间与随机消融重叠 → 否定结果。

### 9.3 E3——会话内批评（路线 C）

- **问题。** 投影支持的批评能否减少每轮故障数？
- **设计。** 30 个任务，三个臂，每个 3 次试验。**单位：** 每轮故障数。
- **命令。** 对批评前后的保留轨迹做 JSON 解析，按 `turn.render` 统计 `page.fault`，使用 §9.1 的解析器；预注册任务 id 与种子。
- **裕度。** 报告带区间的配对差异；30 个任务是试点，不是效力声明。
- **阻断项。** 权重步骤需要错误答案语料和 SFT 价格；两者未知／被阻断。

### 9.4 E4——版本化视图（路线 E）

- **问题。** 视图分数能否跨版本预测任务成功？
- **设计。** ≥10 个模型版本；一个语料；一个视图版本；配对比较加描述性趋势。**单位：** 分数差异。
  n=3 时无法作显著性声明。
- **命令。** 用视图 `V_k` 在同一语料上为所有版本打分；按版本 id 做配对比较；预注册视图哈希。
- **护栏。** 视图和评分规则不进入智能体上下文。

### 9.5 E5——编排器摘要（路线 F）

- **问题。** 在相同预算下，页面边界检查点是否优于截断？
- **设计。** 使用现有 W8 配置；先核查对照压缩器已经做什么（未知）。使用语料中最长的轨迹。
  **单位：** 相同 token 预算下的保留任务成功率。
- **命令。** 用 `benchmarks/metrics` 策略模拟器处理语料中最长轨迹；在相同 token 预算下比较摘要与截断。

## 10. ctxvm 不能做什么

1. 训练权重或选择训练目标。
2. 看到激活、探针或隐藏推理。
3. 从轨迹重建请求字节。
4. 判断正确性；必须有人类或模型评判器。
5. 从渲染证明因果；只有干预可以。
6. 在密封 v0 中记录无存根的页面移除。
7. 提供页面内容供摘要或基于内容的批评使用。
8. 让循环免于奖励劫持或能力提升。
9. 在实测单元上声称节省成本。

## 12. 复现证据

```bash
# 在 ctxvm 仓库根目录
python3 research/datamining/datamining.py
# 单术语计数（词边界，标题+参考）——正则见脚本
python3 - <<'PY'
import os, sqlite3, re
c = sqlite3.connect(os.path.expanduser("~/research/anthropic-papers-reference.sqlite"))
c.row_factory = sqlite3.Row
rows = [dict(r) for r in c.execute("SELECT title, reference FROM papers")]
n = sum(1 for r in rows if re.search(r"\bAnthropic\b", (r["title"] or "") + " " + (r["reference"] or ""), re.I))
print("词边界 Anthropic:", n)   # 与 SQL LIKE 的 59 一起打印
PY
sqlite3 "$HOME/research/anthropic-papers-reference.sqlite" \
  "SELECT COUNT(*) FROM papers WHERE reference LIKE '%Anthropic%';"   # 59；词边界计数同为 59
```

SQLite 表有五列；reference 列保存一页抽取式参考。参考中的方程是启发式 PDF 转换。
这里使用 `$HOME` 展开，因为数据库在仓库外；`lookup.txt` 共 433 行（两行表头 + 431 条数据）。
上述两种 Anthropic 计数在 2026-11-18 实测均为 59。关键词列表和 JSON 转储在仓库内 `research/datamining/`。

## 13. 结论

自我改进循环有四个部分。ctxvm 不闭合它。它让输入侧可观测、可版本化、可受控干预。
这足以改进评估器和训练数据选择器；不足以改进权重。

第一步是开放权重页面消融（E0）：它以计算成本给出因果标签，现在就能运行。这些标签检验
故障选择和主动选择路线，然后是视图路线。每条路线都有证伪条件、单位、样本量和人工闸门。
如果证伪条件触发，该路线就是否定结果，必须记录。
