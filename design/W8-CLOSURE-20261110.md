## The claim the books support

1. **Page selection as implemented cannot act on a single-turn session.** A `-z` session is one turn;
   every `page.declare` carries `turn: 0`, and the keep law protects the first 3 and last 6 turns, so
   the protected set is the whole request. `_plan` returns early at any `vBudget`. Measured at 24,000
   (`RR-NOOP`): 9 selections, 0 evictions, peak 63,246.
2. **On a 12-turn session the protected floor plus scaffold exceeded every budget tried.** Floor
   53,790 (system 5,483 + first three turns 13,240 + last six 35,067) against 24,000, 28,000 and
   55,000. At 55,000 (`RR-W8CELL2`): 30 selections, 0 evictions, request peak 79,960.
3. **Where a middle exists, the shape caps the effect.** With 12 turns the unprotected middle appears
   only at turn 9; the cumulative evictable ceiling is **25,404 of 479,076 request tokens = 5.3%**
   (`RR-W8SIM` §2). Eviction needs a budget below floor + middle ≈ 66,600.
4. **No cost saving was measured, and the one measured pair cost more.** Naive 336,358 input /
   $0.0175; paged 1,057,053 input / $0.1264 — 3.14× tokens and 7.2× dollars for identical parsed
   artefacts (`RR-W8PAIR`).
5. **The extra cache writes are not explained by the engine's message list.** The request series is
   strictly append-only with a byte-constant system prompt, and a unit test shows byte-identical
   no-op output (`RR-W8CACHE`, `RR-W8NOOPBYTES`). Cause **UNKNOWN**.
