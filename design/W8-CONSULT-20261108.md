1. THE SYSTEM, IN THREE PARAGRAPHS
======================================================================
ctxvm is a context manager for agent sessions. It records what the harness sent as an xCABI
trace (a JSONL of typed events) and can select, per request, which recorded pages stay in the
context under a token budget. The experiment ("W8") asks one question: does that selection
reduce the tokens an agent spends on a task without making it less accurate? Two arms, one
factor — the host's `context.engine` setting: `compressor` (stock, naive) vs `ctxvm` (selects
to a budget, never compacts).

The subject is a Hermes agent driven by `hermes -z "<prompt>"`. That client does not execute the
turn: it hands the prompt to the gateway, which runs it (`hermes_cli/main.py:2844` — "every
hermes / -q / -z / TUI turn executes in the gateway"). Plugins, hooks and the context engine
therefore live in the gateway process, not in the client shell.

The gateway is ONE host process serving every profile (`hermes gateway migrate`: "converge every
per-profile gateway onto the ONE host gateway"). Inside it, each profile gets its own plugin
manager (`hermes_cli/plugins.py:1643`, `PluginManager(scope_key=hermes_home_key(current_home))`,
with `scope_key`/`home_path` at `:1080-1086`), so plugin module state is per profile. What is
still process-wide: the plugin *code* (imported once) and `os.environ` (read at import).
