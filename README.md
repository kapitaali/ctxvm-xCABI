# ctxvm

**The context base layer: a virtual-memory manager for LLM agent context.** One interoperable
trace standard (**xCABI** — pages, faults, replay), a deterministic engine (Rust core + TS
bindings), and an open measurement stack (corpus → metric simulator → policy leaderboard)
packaged as ODPS/ODPC-native open data products. `ctxvm` / `xCABI` are working names.

> **v0 wedge (locked):** *telemetry-first* — a read-only flight recorder for any agent loop
> (the OpenTelemetry playbook flips to pages/faults). Paging control ships later behind an
> opt-in policy. Semantic/LLM-based faults stay out of the deterministic core.

## Verify it yourself

The repo claims nothing you can't re-run:

```sh
tools/run-ci.sh            # byte-equivalent local mirror of the Actions workflow
```

Actual output of the 2026-10-23 witness run:

```text
[ctxvm-ci] rust suite green
[ctxvm-ci] ts suites green (12 + 6 tests)
[ctxvm-ci] gate 3/4: schema validator + corpus checksums
positive: 260 event lines validated across 13 fixtures
negative: 5 engineered bad cases correctly rejected
SCHEMA CONFORMANCE: PASS (265 checks)
[ctxvm-ci] hub byte-identity green
[ctxvm-ci] ALL GATES GREEN
```

Same four gates run in Actions per push: `rust` (cargo test), `ts` (both packages),
`schema` (RFC-0 validator + corpus `sha256sum -c`), `hub` (ODPS validate + regen must
reproduce the committed baseline byte-for-byte). Model-free, spend-free, deterministic.
